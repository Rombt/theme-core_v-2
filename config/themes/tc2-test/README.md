# Theme Core v2 Configuration Package — Classic Basic

This is a working Classic WordPress theme configuration package for Theme Core v2. It is not a standalone WordPress theme: Theme Core v2 materializes the WordPress theme files from the declarations and Resources in this package.

The package is intentionally based on the visible starter experience of Temforge's `classic-basic` template. The standalone `classic-basic` template is not modified.

## What is included

- `nodes.php`: atomic Site Logo and Primary Navigation nodes.
- `compositions.php`: the `index`, `header`, and `footer` compositions. The index template uses Theme Core's Classic `get_header()` / `get_footer()` rendering semantics.
- `functions.php` and `resources/functions/`: the complete Classic Basic helper set (including the SVG sprite helper) plus WordPress theme setup.
- `assets.php`: ready CSS, JavaScript, fonts, raster images, and SVG sprite declarations, including Function Requirements for enqueueing CSS/JS.
- `resources/components/index/`: the page Resource and its own SCSS/JavaScript source files. The frontend source belongs to this Resource; it is not placed in a global `classic/` or `block/` source directory.
- `resources/components/header/`, `footer/`, `site_logo_01/`, and `primary_navigation_01/`: Classic representations used by the composition tree.
- `design-system.php`: intentionally empty. Design System is not part of this implementation step.
- `integrations.php`: empty; no external integration is assumed.

## Build workflow

The build has two distinct stages because Theme Core v2 consumes ready Assets and does not compile SCSS or bundle JavaScript.

1. Create this package outside an existing Temforge project, then move it into the Theme Core v2 package directory.
2. From the package directory, install the package-local frontend dependency and build the Resource Assets:

   ```powershell
   npm install
   temforge build
   ```

   Temforge compiles the index Resource's SCSS to `resources/assets/style/index/classic/main-style.css` and bundles its JavaScript to `resources/assets/script/index/classic/main-scripts.js`.
3. Configure the Theme Core v2 project to use this package and its `resources/` directory.
4. Run the Theme Core v2 build from the Theme Core project root:

   ```powershell
   php bin/console.php
   ```

The Theme Core v2 output includes the standard Classic theme artifacts (`style.css`, `index.php`, `header.php`, `footer.php`, `functions.php`) and the declared Assets. Run the Temforge build before the Theme Core build; the CSS/JS output files are generated, not checked into the starter package.

## Resource and Asset paths

Component representations use `resources/components/<resource-id>/classic.php`. The index Resource owns its frontend source under `resources/components/index/src/`.

Ready Assets use Theme Core's architecture-aware path model:

```text
resources/assets/<asset-resource-path>/classic/<file>
```

`assets.php` declares each Asset's exact source and destination. CSS and JavaScript are generated by Temforge into the paths referenced by those declarations. Fonts, images, and the SVG sprite are included as ready package Assets.

## Create the package

```powershell
temforge create --name "My Theme" --template tc2-conf-package --destination C:\work\my-theme-package --author "Theme Author"
```

`create` copies the package template; it does not run npm installation or either build stage. Do not place the new package inside an already configured Temforge project before running `create`.
