theme-core v-2
Architectural Foundation
Core Development Compass

==================================================
1. SYSTEM IDENTITY
==================================================

theme-core v-2 — это configuration-driven platform layer для построения сайтов поверх WordPress.
theme-core v-2 стремиться к component-driven architecture

Система проектирует, собирает и координирует сайт
как композицию архитектурных слоёв,
а не как набор theme templates.

Главный объект системы:
не theme,
не demo import,
не template set,
а platform-composed website.

--------------------------------------------------

Ключевой принцип:

Сайт = результат конфигурации и оркестрации.

Не:
- импорт snapshot-контента
- копирование templates
- XML demo dumps

А:
- composition
- configuration
- rendering orchestration
- reusable visual architecture

==================================================
2. WORDPRESS ROLE
==================================================

WordPress является базовой execution platform.

WordPress отвечает за:
- CMS capabilities
- data storage
- user management
- content APIs
- plugin ecosystem
- native rendering lifecycle
- runtime environment

theme-core v-2 НЕ:
- заменяет WordPress
- создаёт новую CMS
- ломает WordPress lifecycle
- конкурирует с WordPress ecosystem

theme-core v-2 работает:
поверх WordPress,
используя native APIs и native flows.

--------------------------------------------------

Архитектурная формула:

WordPress = Foundation Layer
theme-core v-2 = Orchestration & Composition Layer

==================================================
4. CORE ARCHITECTURAL PRINCIPLE
==================================================

Система строится вокруг идеи:

"Architecture over Templates"

--------------------------------------------------

Template-centric подход:
- pages
- duplicated layouts
- static theme files
- demo snapshots

Configuration-centric подход:
- reusable sections
- render contracts
- composition rules
- design tokens
- renderer pipelines
- configurable architecture

--------------------------------------------------

Каждый сайт — это assembled architecture, а не набор файлов.

==================================================
5. SITE MODEL
==================================================

Сайт рассматривается как:

configuration-defined composition.

--------------------------------------------------

Сайт описывается через:

- configuration
- presets
- design tokens
- layout mappings
- composition rules
- rendering rules
- asset workflows
- renderer bindings

--------------------------------------------------

Итог:

Сайт не хранится.
Сайт собирается поочерёдно проходя вот такие этапы:
    описывается
    собирается
    резолвится
    рендерится
    исполняется

==================================================
6. DEMO PHILOSOPHY
==================================================

Demo — это architectural preset.

Demo НЕ является:
- копией готового сайта
- snapshot pages
- giant XML export
- duplicated templates

Demo является:
- пакет конфигурации
- схема композиции
- визуальное определение
- предварительные настройки подготовки

--------------------------------------------------

Demo описывает:

"как система должна собрать сайт"

а не:

"какой HTML нужно импортировать"

==================================================
7. RENDERING MODEL
==================================================

theme-core v-2 использует rendering abstraction layer.

--------------------------------------------------

Visual architecture должна быть независима
от конкретного renderer.

Одна архитектура может работать через:
- native PHP rendering
- Gutenberg
- Elementor
- WooCommerce integrations
- future rendering systems

--------------------------------------------------

Следствие:

Rendering engine — это детали реализации, а не основная архитектура.

==================================================
8. DESIGN SYSTEM FOUNDATION
==================================================

Design System — центральное ядро платформы.

Design System управляет:
- typography
- spacing
- colors

- visual rhythm

Design System является: не набором CSS, а глобальным visual contract layer.

==================================================
9. COMPOSITION MODEL
==================================================

Композиция является главным механизмом системы.

--------------------------------------------------

Система строится из:

- reusable sections
- layout primitives
- composition contracts
- renderer adapters
- visual tokens
- orchestrated pipelines

--------------------------------------------------

Композиция должна быть:
- reusable
- scalable
- renderer-independent
- configuration-driven

==================================================
10. PROVISIONING MODEL
==================================================

Создание сайта — это конвейер подготовки ресурсов.

--------------------------------------------------

Provisioning включает:
- Подготовка среды
- Предварительно настроенное приложение
- Координация рендерера
- Предоставление ресурсов
- Сборка композиции
- Автоматическая настройка

--------------------------------------------------

Сайт не "импортируется".

Сайт:
- provisioned
- assembled
- orchestrated

==================================================
11. MULTISITE ARCHITECTURE
==================================================

Система проектируется как: multisite-capable platform.

--------------------------------------------------

Архитектура должна поддерживать:
- single-site mode
- multisite mode

--------------------------------------------------

В multisite architecture:
- визуальная система может быть общей
- система проектирования может быть централизованной
- рабочие процессы обеспечения могут быть общими
- архитектура композиции может переиспользоваться

--------------------------------------------------

Следствие:

theme-core v-2 проектируется как platform ecosystem, а не isolated theme.

==================================================
12. CORE ENGINEERING DIRECTION
==================================================

Главная инженерная идея:

Максимально отделить:
- визуальная архитектура
- логика композиции
- реализация рендеринга
- рабочие процессы предоставления ресурсов
- система проектирования
- среда выполнения WordPress

--------------------------------------------------

Система должна стремиться к:
- абстракция
- оркестровка
- композиция
- масштабируемость
- независимость от рендерера
- многократно используемая архитектура
- сборка, управляемая конфигурацией

==================================================
13. FINAL SYSTEM DEFINITION
==================================================

theme-core v-2 — это platform-oriented orchestration system
для WordPress, которая собирает сайты из конфигурации, композиции, дизайн-системы и orchestration pipelines.
