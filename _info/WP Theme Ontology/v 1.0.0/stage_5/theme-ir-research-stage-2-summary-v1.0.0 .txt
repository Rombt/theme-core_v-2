================================================================================
1. ЦЕЛЬ ЭТАПА
================================================================================

    После завершения первого этапа исследования была сформулирована главная задача.

    Необходимо определить:
        существует ли объективная причина, по которой генераторы артефактов
            не могут работать непосредственно с ThemeComponentCollection.

    Исследование проводится дедуктивным методом.

    Не допускается проектирование Theme IR.

    Необходимо доказать её необходимость или доказать её избыточность.

================================================================================
2. ИСХОДНЫЕ ПОЛОЖЕНИЯ
================================================================================

    К началу этапа были приняты следующие положения.

    1. ThemeComponentCollection представляет собой инфраструктурную модель стадии загрузки.
        Она объединяет результаты всех предметных доменов.

    2. ThemeComponentCollection уже содержит знания, сообщённые автором темы.

    3. Theme IR не должна рассматриваться как существующая архитектурная сущность.
        Её необходимость должна быть доказана.

    4. Исследование не использует устаревшую концепцию Resolution.

================================================================================
3. МЕТОДОЛОГИЧЕСКАЯ ОСНОВА
================================================================================

    Из предыдущих исследований была сохранена единственная рабочая идея.

    Вместо вопроса: Как должна выглядеть Theme IR?

    исследование строится вокруг вопроса: Что необходимо знать генератору,
        чтобы полностью сгенерировать артефакт?

    Именно этот вопрос признан единственной корректной отправной точкой.

================================================================================
4. КОНТРАКТ ГЕНЕРАТОРА
================================================================================

    Была предпринята попытка определить минимальный контракт любого генератора.

    Генератору необходимо знать:

    1. Что необходимо создать.
        То есть:  целевой тип артефакта.

    2. Из чего создавать.
        То есть: предметную модель темы.

    3. По каким правилам создавать.
        То есть: правила материализации конкретной целевой архитектуры.

    Было установлено: только второй пункт относится к предметной модели темы.

    Первый и третий принадлежат самому генератору.

================================================================================
5. ПРОВЕРКА НА ДВУХ АРХИТЕКТУРАХ WORDPRESS
================================================================================

    Для исключения ложных выводов было принято дополнительное правило исследования.

    Любой вывод считается подтверждённым только в том случае, если он остаётся справедливым
        минимум для двух принципиально различных архитектур WordPress.

    На текущем этапе выбраны:
        Block Themes
            templates/*.html

        Classic Themes
            templates/*.php

    Исследование остальных архитектур переносится на последующие этапы.

================================================================================
6. СРАВНЕНИЕ КОНТРАКТОВ ГЕНЕРАТОРОВ
================================================================================

    Было проведено мысленное сравнение двух генераторов.
        Генератор Block Theme и Генератор Classic Theme.

    Вывод:
        Оба генератора используют одну и ту же предметную информацию.

    Им необходимо знать:
        Composition
        Nodes
        Templates
        DesignSystem
        остальные доменные компоненты

    Различается исключительно способ материализации.

    Следовательно: изменяется алгоритм генерации, но не знания о теме.

================================================================================
7. ПРОВЕРКА ГИПОТЕЗЫ О THEME IR
================================================================================

        Был поставлен вопрос.
            Что произойдёт, если Theme IR полностью убрать из архитектуры?

        Рассматривалась модель:

            ThemeComponentCollection
                    ↓
                Generators
                    ↓
                Artifacts

        Были проверены три возможные причины существования Theme IR.

        Причина 1: Генератор перестанет понимать тему.
            Результат: Не подтверждено.

        Причина 2: Генератор перестанет понимать целевую архитектуру.
            Результат: Не подтверждено.  Знание архитектуры принадлежит самому генератору.

        Причина 3: Будет потеряна часть предметной информации.
            Результат: Не подтверждено.

        На текущем этапе исследования не обнаружено информации,
            которая существовала бы только внутри Theme IR.

================================================================================
8. ГЛАВНЫЙ КРИТЕРИЙ НЕОБХОДИМОСТИ THEME IR
================================================================================

    Был сформулирован наиболее строгий критерий всего исследования.

    Сам факт преобразования данных не является доказательством существования Theme IR.

    Theme IR может считаться архитектурно необходимой только в том случае,
        если между ThemeComponentCollection и генераторами появляется новая предметная информация.

    Иными словами. Необходимо доказать существование знаний, которые:
        отсутствуют в ThemeComponentCollection, но объективно необходимы
        для генерации артефактов.

    Пока подобных знаний обнаружить не удалось.

================================================================================
9. ПРОМЕЖУТОЧНЫЙ ВЫВОД ЭТАПА
================================================================================

    На момент завершения второго этапа не найдено ни одной объективной причины,
        по которой генераторы артефактов не могли бы работать непосредственно
        с ThemeComponentCollection.

    Для двух исследованных архитектур WordPress наблюдается следующая закономерность.
        Меняется исключительно способ материализации темы.
        Предметная информация остаётся неизменной.

    Следовательно, необходимость отдельной Theme IR на данном этапе исследования не подтверждена.

    При этом она ещё не считается опровергнутой.

    Для окончательного вывода необходимо продолжить исследование и попытаться обнаружить
        хотя бы одну операцию, которая требует построения новой предметной модели
        между ThemeComponentCollection и генераторами артефактов.
