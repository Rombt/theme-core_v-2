theme-core v-2
THEME IR RESEARCH
STAGE 9
SPECIALIZED CONSUMPTION MODELS
PART 1
NAVIGATION MENUS
(v1.0.0)

Status: Completed

==================================================
1. PURPOSE
==================================================

    Начать практическое проектирование
    специализированных моделей потребления Theme IR
    для конкретных генераторов.

    В рамках данного этапа исследовалась публичная
    модель Theme IR, предназначенная для генератора
    Navigation Menus.

==================================================
2. RESEARCH METHOD
==================================================

    Исследование проводилось исключительно с точки
    зрения генератора.

    Внутреннее устройство Theme IR полностью
    исключалось из рассмотрения.

    Основной вопрос исследования:

        "Какую предметную модель должен получить
        генератор Navigation Menus, чтобы полностью
        выполнить свою задачу без принятия каких-либо
        предметных решений?"

==================================================
3. RESPONSIBILITY OF THE GENERATOR
==================================================

    Было подтверждено, что генератор Navigation
    Menus не участвует в построении предметной
    модели.

    Его единственная ответственность заключается в
    материализации уже подготовленного набора меню
    средствами целевой платформы.

    Генератор не должен:

        - анализировать конфигурацию;
        - искать объекты;
        - разрешать ссылки;
        - выполнять вычисления;
        - принимать предметные решения.

==================================================
4. ROOT DOMAIN MODEL
==================================================

    Было установлено, что генератор работает не с
    отдельными объектами меню, а с завершённой
    предметной моделью зарегистрированных меню.

    Корневой объект модели имеет вид:

        NavigationMenus
            └── NavigationMenu*

    NavigationMenus является полноценной предметной
    сущностью, а не служебной коллекцией.

==================================================
5. NAVIGATION MENU MODEL
==================================================

    Каждый NavigationMenu представляет собой
    завершённую предметную сущность.

    Генератору необходимы исключительно свойства,
    имеющие предметный смысл.

    Например:

        - id
        - name
        - description

    При этом объект не должен отражать структуру
    исходной конфигурации и не должен содержать
    платформенно-зависимые данные.

==================================================
6. COMPLETE DOMAIN MODEL
==================================================

    В результате исследования была сформирована
    следующая концептуальная модель потребления.

        NavigationMenus
            └── NavigationMenu
                    ├── id()
                    ├── name()
                    └── description()

    Данная модель полностью описывает предметный
    результат, необходимый генератору.

==================================================
7. READ-ONLY CONTRACT
==================================================

    Было установлено, что специализированная модель
    потребления представляет собой исключительно
    модель чтения.

    Публичный контракт не должен содержать методы,
    изменяющие состояние модели.

    Допустимыми являются только операции чтения
    предметных свойств.

==================================================
8. SELF-SUFFICIENCY OF THE MODEL
==================================================

    Модель должна быть полностью самодостаточной.

    Генератор не должен нуждаться в информации о:

        - происхождении объектов;
        - структуре конфигурации;
        - этапах подготовки модели;
        - внутренних вычислениях Theme IR;
        - процессе разрешения зависимостей.

    Единственным источником информации для
    генератора должна являться сама предметная
    модель.

==================================================
9. PLATFORM INDEPENDENCE
==================================================

    Было подтверждено, что публичная модель Theme IR
    может быть полностью описана без использования
    понятий целевой платформы.

    Контракт оперирует исключительно предметными
    сущностями:

        NavigationMenus
        NavigationMenu

    а не механизмами материализации WordPress.

==================================================
10. CONFIRMATION OF UNIVERSAL PRINCIPLES
==================================================

    Исследование Navigation Menus полностью
    подтвердило универсальные принципы,
    сформулированные на предыдущем этапе.

    В частности было подтверждено, что:

        - Theme IR предоставляет генератору готовую
          предметную модель;

        - специализированная модель состоит из
          предметных объектов;

        - свойства объектов имеют исключительно
          предметный смысл;

        - генератор выполняет только материализацию;

        - публичный контракт представляет собой
          полностью подготовленную read-only модель.

==================================================
11. CONCLUSION
==================================================

    Исследование показало, что специализированная
    модель потребления Navigation Menus является
    чистой предметной моделью, полностью отделённой
    как от конфигурационной модели, так и от API
    целевой платформы.

    Генератор получает законченный предметный
    результат и не выполняет никаких дополнительных
    преобразований.

    Таким образом, домен Navigation Menus стал
    вторым независимым подтверждением универсальных
    принципов проектирования публичного контракта
    Theme IR, ранее выявленных при исследовании
    Theme Supports.

    Следующим этапом исследования должно стать
    проектирование специализированной модели
    потребления для домена Templates, который
    позволит проверить применимость данных
    принципов к значительно более сложной
    предметной модели.
