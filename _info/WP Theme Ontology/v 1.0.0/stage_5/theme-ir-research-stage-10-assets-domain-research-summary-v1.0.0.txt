theme-core v-2
WP THEME ONTOLOGY RESEARCH
STAGE 10

ASSETS DOMAIN RESEARCH
(v1.0.0)

Status: Completed


==================================================
1. PURPOSE
==================================================

  Определить предметную природу домена Assets
  независимо от технической реализации WordPress,
  Theme Core, Theme IR и механизмов генерации.

  Исследование направлено на определение:

  - причины существования Assets Domain;
  - самостоятельной ответственности;
  - границ ответственности;
  - минимальной онтологии;
  - модели потребления домена генераторами;
  - требований к будущему публичному контракту Theme IR.


==================================================
2. RESEARCH PRINCIPLES
==================================================

Исследование выполнялось независимо от:

- структуры файлов WordPress Theme;
- wp_enqueue механизма;
- CSS/JS реализации;
- файловой системы;
- способов сборки ресурсов;
- Theme Core архитектуры;
- формата хранения конфигурации.

Asset рассматривается как предметная сущность темы,
а не как технологический файл.


==================================================
3. OBJECTIVE REASON FOR EXISTENCE
==================================================

WordPress Theme состоит не только из представлений
и структурных элементов.

Для реализации пользовательского опыта тема может
зависеть от ресурсов, которые:

- не являются структурными элементами темы;
- не являются пользовательским содержанием;
- необходимы для полноценного функционирования
  представлений темы.


Примеры:

- типографические ресурсы;
- визуальные ресурсы;
- ресурсы поведения;
- другие ресурсы, необходимые теме.


Следовательно:

Assets Domain существует потому, что тема должна
описывать ресурсные зависимости, необходимые для
реализации пользовательского опыта.


==================================================
4. DOMAIN RESPONSIBILITY
==================================================

Assets Domain отвечает за:

описание ресурсных сущностей темы,
их назначения и использования
другими сущностями темы.


Assets Domain отвечает на вопрос:

"Какие ресурсы существуют в теме
и какую роль они выполняют?"


==================================================
5. RESPONSIBILITY BOUNDARIES
==================================================


------------------------------
5.1 Templates Boundary
------------------------------

Templates описывает:

- какие представления существуют;
- какие пользовательские сценарии
  они обслуживают.


Templates не описывает:

- необходимые ресурсы;
- способы подключения ресурсов.


Связь:

Template may require Asset.


------------------------------
5.2 Composition Boundary
------------------------------

Composition описывает:

- структуру представления;
- расположение элементов;
- иерархию.


Composition не описывает:

- стили;
- скрипты;
- внешние ресурсы.


Связь:

Composition Element may require Asset.


------------------------------
5.3 Nodes Boundary
------------------------------

Node описывает:

- существование структурного элемента;
- его предметное назначение.


Node не владеет ресурсами.


Связь:

Node requires Asset.


------------------------------
5.4 Design System Boundary
------------------------------

Design System описывает:

- визуальные правила;
- дизайн-решения.


Assets описывает:

- ресурсные реализации этих решений.


Пример:

Design System:

Primary Typeface


Assets:

Font Resource


Связь:

Design System requires Asset.


------------------------------
5.5 Materialization Boundary
------------------------------

Asset не является:

- файлом;
- директорией;
- URL;
- CSS-файлом;
- JavaScript-файлом.


Это способы материализации ресурса.


==================================================
6. MINIMAL ONTOLOGY
==================================================

Исследование показало, что минимальная онтология
Assets Domain состоит из двух сущностей.


------------------------------
6.1 Asset
------------------------------

Asset — самостоятельная ресурсная сущность темы,
необходимая для реализации определённой части
пользовательского опыта.


Asset не является:

- файлом;
- технологическим объектом;
- способом загрузки.


------------------------------
6.2 Asset Purpose
------------------------------

Asset Purpose — назначение ресурса
в пользовательском опыте темы.


Примеры назначения:

- Typography Resource;
- Interaction Resource;
- Visual Resource.


Purpose является семантическим,
а не техническим понятием.


==================================================
7. DOMAIN RELATIONSHIPS
==================================================

Основное отношение:


Theme Entity

        requires

          Asset


Источниками зависимости могут быть:

- Template;
- Composition Element;
- Node;
- Design System.


Asset не владеет этими сущностями.


==================================================
8. GENERATOR CONSUMPTION MODEL
==================================================

Генераторы должны получать:

- идентичность ресурса;
- назначение ресурса;
- связи использования.


Генераторы не должны получать:

- путь к файлу;
- имя файла;
- структуру каталогов;
- механизм подключения;
- enqueue правила;
- bundling информацию.


Генератор должен знать:

"какой ресурс существует и зачем он нужен"


но не:

"как именно он будет создан или подключён".


==================================================
9. THEME IR REQUIREMENTS
==================================================

На основании исследования Assets Domain
выводятся следующие требования.


Theme IR должен поддерживать:


1. Asset Identity

Возможность однозначно ссылаться
на ресурс.


2. Asset Purpose

Возможность определить назначение ресурса.


3. Asset Usage Relationship

Возможность выразить:

Entity requires Asset.


==================================================
10. EXCLUDED FROM THEME IR
==================================================

Не должны входить:


Technical Resource Information:

- file;
- path;
- URL;
- extension;
- CSS;
- JavaScript;
- enqueue handle;
- loading strategy.


Причина:

это уровень Materialization,
а не предметное описание темы.


==================================================
11. FINAL DOMAIN DEFINITION
==================================================

Assets Domain —

предметная область WordPress Theme,
ответственная за описание ресурсных сущностей темы,
необходимых для реализации пользовательского опыта,
их назначения и зависимостей от других сущностей темы.
