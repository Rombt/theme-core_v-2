theme-core v-2
THEME IR RESEARCH
STAGE 6
RESEARCH METHODOLOGY
(v1.0.0)

Status: Completed

==================================================
1. PURPOSE
==================================================

    Определить объективную методологию дальнейшего исследования Theme IR.

    Методология должна исключить проектирование архитектуры "из головы" и обеспечить получение
        модели Theme IR исключительно как следствия реальных требований платформы.

==================================================
2. INITIAL POSITION
==================================================

    На предыдущем этапе исследования были
    установлены следующие положения.

        - Theme IR существует для обеспечения
          стабильного контракта между
          ThemeComponents и генераторами
          артефактов.

        - Публичный контракт Theme IR должен
          определяться задачами генераторов,
          а не внутренней структурой
          ThemeComponents.

        - Архитектура Theme IR должна быть
          следствием объективных требований,
          а не предварительных архитектурных
          предположений.

    Однако отсутствовала практическая методика,
    позволяющая получить эти требования.

==================================================
3. METHODOLOGICAL PROBLEM
==================================================

    Первоначально предполагалось определить полный набор сценариев генераторов.

    Однако дальнейший анализ показал, что подобная формулировка слишком широка.

    Генераторы выполняют задачи различных архитектурных слоёв, многие из которых
        не имеют отношения к Theme IR.

    Следовательно, исследование необходимо ограничить исключительно теми сценариями,
        которые требуют взаимодействия между генераторами артефактов и Theme IR.

==================================================
4. KEY DISCOVERY
==================================================

    Был найден более практический подход.

    Вместо исследования Theme IR необходимо исследовать реальные потребности генераторов.

    Для каждого генератора должен задаваться только один вопрос.

        "Какие данные должен получить данный генератор, чтобы полностью выполнить свою задачу?"

    Именно ответы на этот вопрос должны становиться сценариями Theme IR.

==================================================
5. PRACTICAL STARTING POINT
==================================================

    Было принято решение полностью отказаться от построения абстрактных моделей.

    Исследование должно начинаться исключительно с конечного результата работы платформы.

        Theme Core автоматически строит готовую тему одной из поддерживаемых архитектур.

    Следовательно, именно реальные архитектуры тем являются
        исходной точкой исследования.

==================================================
6. TARGET ARCHITECTURES
==================================================

    В качестве объектов исследования принимаются реальные архитектуры WordPress тем.

    На текущем этапе определён следующий рабочий перечень:
        - Classic Architecture
        - Hybrid Architecture
        - Block (FSE) Architecture
        - Builder Architecture

    Данный перечень может уточняться в ходе дальнейшего исследования, однако именно он
        принимается в качестве практической основы.

==================================================
7. RESEARCH PROCESS
==================================================

    Для каждой архитектуры выполняется одинаковая последовательность действий.

    1. Определяется полный набор артефактов, необходимых для реализации данной архитектуры.
    2. Для каждого артефакта определяется соответствующий генератор.
    3. Для каждого генератора исследуется исключительно один вопрос.
           Какие данные он должен получить от Theme IR?
    4. Каждый запрос генератора фиксируется как отдельный сценарий.
    5. После исследования всех архитектур одинаковые сценарии объединяются.

    Результатом становится полный перечень уникальных сценариев взаимодействия между
        генераторами артефактов и Theme IR.

==================================================
8. RESPONSIBILITY BOUNDARIES
==================================================

    В ходе исследования были окончательно разделены обязанности архитектурных слоёв.

    Theme IR
        Подготавливает архитектурно-независимую предметную модель.

    Artifacts
        Используют Theme IR для построения архитектурно-зависимых артефактов.

    Materialization
        Преобразует готовые артефакты в физическую структуру проекта.

==================================================
9. EXCLUDED RESPONSIBILITIES
==================================================

    Было принято решение сознательно исключить из исследования задачи, 
        принадлежащие слою Materialization.

    В частности, исследование Theme IR больше не рассматривает вопросы:
        - выбора файлов;
        - выбора каталогов;
        - выбора путей;
        - выбора расширений;
        - записи файлов;
        - создания каталогов;
        - любой физической материализации.

    Эти задачи не должны влиять на проектирование Theme IR.

==================================================
10. DESIGN CONSEQUENCES
==================================================

    После завершения исследования сценариев проектирование выполняется в строгой последовательности.

        1. Формируется полный перечень уникальных сценариев.
        2. На их основе проектируется минимальный публичный контракт Theme IR.

        3. Только после этого определяется внутренняя архитектура Theme IR, необходимая для реализации
           данного контракта.

==================================================
11. MAIN METHODOLOGICAL PRINCIPLE
==================================================

    Главным результатом исследования стало формирование нового методологического принципа.

        Каждый элемент Theme IR должен иметь объективное прикладное обоснование.

    Иначе говоря,
        любой элемент Theme IR существует только потому, что необходим хотя бы одному реальному генератору артефактов.

    Если невозможно указать генератор и соответствующий сценарий, требующий существования некоторого элемента,
        то такой элемент не должен входить в Theme IR.

==================================================
12. RESULT OF THE STAGE
==================================================

    Данный этап завершил формирование методологии исследования Theme IR.

    Дальнейшее исследование полностью переводится из области архитектурных
        предположений в область прикладного инженерного анализа.

    Объектом исследования становятся реальные потребности генераторов артефактов.

    Theme IR больше не проектируется непосредственно.

    Его публичный контракт и внутренняя архитектура должны быть полностью
        выведены из объективного анализа сценариев взаимодействия генераторов
        с предметной моделью.

==================================================
13. IMPORTANT IDEAS
==================================================

    Исходной точкой исследования является
        конечный результат работы платформы,
        а не устройство Theme IR.

    Исследуются реальные архитектуры, а не абстрактные модели.

    Исследуется не Theme IR, а потребности генераторов артефактов.

    Для каждого генератора задаётся  единственный вопрос:

            "Какие данные он должен получить от Theme IR, чтобы полностью выполнить свою задачу?"

    Каждый запрос генератора становится отдельным сценарием Theme IR.

    Все вопросы физической материализации полностью исключаются из исследования
        и относятся к отдельному слою Materialization.

    Публичный контракт Theme IR является следствием найденных сценариев.

    Внутренняя архитектура Theme IR является следствием его публичного контракта.

    Каждый элемент Theme IR обязан иметь конкретное прикладное обоснование
        в виде хотя бы одного реального сценария генератора.
