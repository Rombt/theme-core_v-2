theme-core v-2
THEME IR RESEARCH
STAGE 9 (PART 3)

TEMPLATES CONSUMPTION MODEL
(v1.0.0)

Status: Completed

==================================================
1. PURPOSE
==================================================

Определить специализированную модель потребления
домена Templates генераторами артефактов.

Исследование выполнялось исключительно с точки
зрения потребителя Theme IR.

Внутреннее устройство Theme IR, ThemeComponents,
Configuration Domains и способы реализации
полностью исключались из рассмотрения.

==================================================
2. RESEARCH BASIS
==================================================

Исследование основано на ранее утверждённых
результатах.

В частности:

- Stage 5
  Scenarios-First Approach;

- Stage 6
  Research Methodology;

- Stage 7
  Generator Contract Analysis;

- Stage 8
  Universal Principles of Theme IR;

- Stage 9 (Part 2)
  Templates Domain Research.

Повторная проверка данных принципов
не выполнялась.

Они принимались в качестве исходных
аксиом исследования.

==================================================
3. RESEARCH QUESTION
==================================================

Для исследования использовался единственный
методологический вопрос.

    Какие данные должен получить
    Template Artifact Generator
    от Theme IR, чтобы полностью выполнить
    свою задачу без принятия каких-либо
    предметных решений?

==================================================
4. GENERATOR RESPONSIBILITY
==================================================

Было установлено, что Template Artifact Generator
не участвует в построении предметной модели.

Он не должен:

- анализировать конфигурацию;
- выбирать представления;
- определять пользовательские сценарии;
- выполнять назначения;
- искать объекты;
- разрешать ссылки;
- выполнять предметные вычисления;
- принимать предметные решения.

Единственная ответственность генератора
заключается в материализации уже подготовленной
предметной модели средствами целевой
архитектуры.

==================================================
5. ANALYSIS OF DOMAIN ENTITIES
==================================================

Предыдущий этап исследования установил
минимальную онтологию домена:

    User Scenario
    Template
    Template Assignment

Был исследован вопрос,
какие из этих сущностей должны входить
в специализированную модель потребления.

------------------------------
5.1 User Scenario
------------------------------

User Scenario необходим генератору.

Именно пользовательский сценарий определяет
назначение представления.

Без него Template теряет предметный смысл.

------------------------------
5.2 Template
------------------------------

Template необходим генератору.

Он представляет собой предметное описание
представления, которое должно быть
материализовано средствами целевой архитектуры.

------------------------------
5.3 Template Assignment
------------------------------

Template Assignment является самостоятельной
предметной сущностью онтологии.

Однако генератор не должен выполнять
процесс назначения.

К моменту получения модели Theme IR
соответствие между User Scenario
и Template уже должно быть полностью
разрешено.

Следовательно,
Template Assignment не входит
в публичную модель потребления.

Он остаётся внутренней ответственностью
Theme IR.

==================================================
6. CONSUMPTION MODEL
==================================================

В результате исследования была получена
следующая специализированная модель
потребления.

        Templates
            |
            +-- Template
                    |
                    +-- Identity
                    +-- Purpose
                    +-- User Scenario

Templates представляет собой завершённую
предметную модель представлений темы.

Каждый Template является самостоятельной
read-only предметной сущностью.

==================================================
7. MODEL SELF-SUFFICIENCY
==================================================

Было установлено,
что специализированная модель должна быть
полностью самодостаточной.

После получения Template генератор
не должен обращаться:

- к Theme Configuration;
- к ThemeComponents;
- к другим Theme Concepts;
- к Resolver;
- к Configuration Domains.

Вся необходимая предметная информация
должна содержаться в самой модели.

==================================================
8. EXCLUDED FROM THE PUBLIC CONTRACT
==================================================

Не должны входить
в специализированную модель потребления:

- PHP-файлы;
- HTML-шаблоны;
- Template Hierarchy;
- пути;
- имена файлов;
- способы материализации;
- информация о платформе;
- Node;
- CompositionComponent;
- внутренние структуры ThemeComponents;
- сведения о происхождении модели.

Причина:

данные элементы относятся
либо к внутреннему устройству Theme Core,
либо к слою Materialization,
и не являются частью предметной модели
Templates.

==================================================
9. CONFIRMATION OF UNIVERSAL PRINCIPLES
==================================================

Полученная модель полностью соответствует
универсальным принципам Theme IR.

В частности подтверждено:

- Theme IR предоставляет генератору
  специализированную предметную модель;

- генератор получает полностью подготовленный
  результат;

- вся предметная неопределённость
  устраняется внутри Theme IR;

- генератор не выполняет поиск,
  вычисления и разрешение зависимостей;

- ответственность генератора начинается
  только с материализации полученной модели.

==================================================
10. FINAL CONCLUSION
==================================================

Исследование показало,
что специализированная модель потребления
домена Templates существенно отличается
от его предметной онтологии.

Онтология включает:

    User Scenario
    Template
    Template Assignment

Публичная модель потребления включает:

    Templates
        └── Template
                ├── Identity
                ├── Purpose
                └── User Scenario

Таким образом Theme IR предоставляет
не модель хранения предметной области,
а полностью подготовленную
read-only модель потребления,
не требующую дополнительных
предметных преобразований.

==================================================
11. RESEARCH RESULT
==================================================

Исследование специализированной модели
потребления домена Templates завершено.

Полученная модель может использоваться
в качестве объективной основы
для проектирования публичного контракта
Theme Concept Templates
в новой архитектуре Theme IR.
