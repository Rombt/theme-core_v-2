КОНЦЕПЦИЯ №1 — METADATA

1. ОБЪЕКТ ИССЛЕДОВАНИЯ
================================================================================

    Концепция:

        Metadata

    В рамках Theme Specification Metadata рассматривается как декларативное
    описание темы как самостоятельного программного продукта.


2. ЦЕЛЬ ИССЛЕДОВАНИЯ
================================================================================

    Определить:

        - должна ли Metadata существовать в Theme Specification;
        - достаточно ли существующей архитектуры Theme Specification для её
          описания;
        - требуется ли изменение архитектуры;
        - может ли Resolution детерминированно построить фундаментальную
          внутреннюю модель;
        - какие генераторы являются потребителями полученной информации.


3. ОСНОВНЫЕ РЕЗУЛЬТАТЫ
================================================================================


    3.1 Metadata является фундаментальной частью Theme Specification.
    --------------------------------------------------------------------------------

        Metadata не может быть вычислена автоматически.
        Она представляет собой знания, принадлежащие автору темы.
        Следовательно, Metadata обязана существовать как самостоятельное декларативное описание.


    3.2 Metadata не зависит от платформы публикации.
    --------------------------------------------------------------------------------

        Metadata описывает саму тему, а не способы её распространения.

        Такие артефакты как:
            - style.css
            - readme.txt
            - marketplace manifest
            - package metadata

        являются лишь различными представлениями одного и того же описания.


    3.3 Существующая архитектура Theme Specification подтверждается.
    --------------------------------------------------------------------------------

        Исследование показало, что отдельный канал уже существует это package.php
        Архитектурных причин для появления нового канала не обнаружено.
        Следовательно, архитектура Theme Specification изменяться не должна.


    3.4 Недостаточной является только структура канала.
    --------------------------------------------------------------------------------

        Текущее состояние package.php:

            return [

                'name' => 'Blog Theme',

                'version' => '1.0.0',

            ];

        пригодно исключительно для MVP.
        Для описания реальной коммерческой темы его возможностей недостаточно.
        При этом проблема заключается не в архитектуре, а исключительно
        в недостаточной полноте модели данных.


4. RESOLUTION
================================================================================

    Resolution обязан:
        - проверить корректность Metadata;
        - нормализовать значения;
        - построить внутреннее представление Metadata;
        - подготовить информацию для последующей генерации артефактов.

    Resolution не должен:
        - изменять смысл Metadata;
        - дополнять Metadata предположениями;
        - получать отсутствующую информацию эвристически.


5. FUNDAMENTAL IR
================================================================================

    Результатом Resolution должен являться самостоятельный Metadata IR.
    Metadata IR представляет собой нормализованное внутреннее описание темы как программного продукта.
    Все последующие генераторы работают исключительно с Metadata IR.


6. ARTIFACT GENERATORS
================================================================================

    Metadata IR является источником информации для генераторов публикационных
    артефактов.

    Минимально:
        - style.css Generator;
        - readme Generator;
        - Marketplace Generator;
        - Package Metadata Generator;
        - будущих генераторов публикации.


7. ПРОВЕРКА ОСНОВНОЙ ГИПОТЕЗЫ
================================================================================

    В ходе исследования подтверждена цепочка:

        Theme Specification
                ↓
            Resolution
                ↓
            Metadata IR
                ↓
        Artifact Generators
                ↓
        Published Artifacts

    Построение IR выполняется детерминированно.
    Дополнительные предположения со стороны Resolution не требуются.


8. ИТОГОВЫЙ ВЕРДИКТ
================================================================================

    Metadata подтверждается как самостоятельная концепция Theme Specification.
    Архитектура Theme Specification признана достаточной.
    Изменение состава каналов не требуется.
    Требуется исключительно расширение структуры package.php до полноценной
    декларативной модели Metadata.

    Концепция получает статус: CONFIRMED
