THEME-CORE V-2
ФИНАЛЬНОЕ ИССЛЕДОВАНИЕ THEME SPECIFICATION
(v0.2.0)

================================================================================
1. ПРЕДПОСЫЛКИ ИССЛЕДОВАНИЯ
================================================================================

    На предыдущих этапах исследования были получены следующие результаты.

        1. Было исследовано множество современных WordPress-тем.
        2. Построена онтология предметной области.
        3. Выполнена группировка обнаруженных концепций.
        4. Найдены фундаментальные инварианты.
        5. Выполнен переход от онтологии к Intermediate Representation (IR).
        6. Выделен предварительный набор фундаментальных IR-узлов.
            - Composition
            - Query
            - Asset
            - DesignSystem
            - Integration

        7. Было установлено, что ряд первоначально предполагаемых доменов не являются фундаментальными.
            В частности:
                - Workflow
                - Configuration
                - Component
                - Dataset
                - Field
                - Region
                - State
                - Action
            были признаны производными либо инфраструктурными механизмами.

    Главный вывод предыдущих этапов исследования:
        ThemeDefinition не является коллекцией специализированных Definition-классов.

        ThemeDefinition представляет собой комбинацию небольшого количества
            универсальных фундаментальных IR-узлов.

================================================================================
2. ТЕКУЩЕЕ СОСТОЯНИЕ ПРОЕКТА
================================================================================

    На текущем этапе ThemeCore уже обладает собственной Theme Specification.

    Она представлена набором декларативных каналов.
        - package.php
        - compositions.php
        - templates.php
        - queries.php
        - design-system.php
        - assets.php
        - integrations.php

    Кроме этого существуют прикладные каналы, не являющиеся фундаментальными доменами.
        - entities.php
        - workflows.php

    Следовательно, целью исследования не является проектирование новой архитектуры Theme Specification.

    Необходимо проверить полноту, достаточность и архитектурную состоятельность уже существующей модели.

================================================================================
3. ОБЛАСТЬ ОТВЕТСТВЕННОСТИ THEME SPECIFICATION
================================================================================

    Theme Specification представляет собой декларативное описание темы.

    Она содержит исключительно знания, необходимые для последующего построения
        Intermediate Representation.

    Theme Specification не описывает:
        - процесс генерации;
        - внутреннее устройство Generator;
        - процесс публикации;
        - инфраструктуру сборки;
        - Runtime WordPress;
        - способы реализации артефактов.

    Все подобные вопросы относятся к последующим стадиям компиляции.

================================================================================
4. ОСНОВНАЯ ГИПОТЕЗА
================================================================================

    Theme Specification не является отображением фундаментальных IR-доменов.

    Она представляет собой самостоятельный декларативный язык описания темы,
        предназначенный для последующего преобразования в фундаментальную модель ThemeCore.

            Theme Specification
                    ↓
            Resolution
                    ↓
            Fundamental IR
                    ↓
            Artifact Generators
                    ↓
            WordPress Theme

    Таким образом Theme Specification и Intermediate Representation являются
        двумя различными уровнями одной архитектуры.

================================================================================
5. ЦЕЛЬ ИССЛЕДОВАНИЯ
================================================================================

    Проверить, достаточно ли существующей Theme Specification для полного
        описания любой WordPress-темы, входящей в область ответственности ThemeCore.

    Необходимо установить, может ли вся информация, необходимая для
        детерминированного построения фундаментального IR и последующей генерации
        артефактов, быть выражена средствами существующих каналов Theme Specification.

    При этом Resolution не должен получать информацию путём предположений или эвристик.

================================================================================
6. МЕТОД ИССЛЕДОВАНИЯ
================================================================================

    Для каждой концепции, обнаруженной в ходе исследования предметной области,
        необходимо последовательно ответить на следующие вопросы.

        1. Должна ли данная концепция вообще существовать в Theme Specification?
        2. Если должна — какая информация должна быть описана?
        3. Может ли эта информация быть выражена средствами существующих каналов?
        4. В каком канале она должна располагаться?
        5. Достаточна ли существующая структура данного канала?
        6. Требуется ли расширение существующего канала?
        7. Можно ли детерминированно построить фундаментальный IR без дополнительных предположений?
        8. Какие преобразования обязан выполнить Resolution?
        9. Какой фундаментальный IR должен быть построен?
        10. Какие Artifact Generators являются потребителями данной информации?

    Исследование ориентировано прежде всего на анализ информации, а не существующих каналов.

    Любое изменение каналов допускается только в случае невозможности выразить необходимую
        информацию существующей архитектурой.

================================================================================
7. КРИТЕРИИ ИЗМЕНЕНИЯ ARCHITECTURE
================================================================================

    Любое изменение Theme Specification допускается только после выполнения всех следующих условий.

        1. Недостаток подтверждён несколькими независимыми WordPress-темами.
        2. Проблема не может быть устранена средствами существующих каналов.
        3. Resolution не способен устранить проблему без нарушения принципа детерминированности.
        4. Изменение упрощает архитектуру, а не усложняет её.
        5. Изменение приводит к практическому улучшению ThemeCore.

    Исследование не должно приводить к необоснованному расширению DSL.

================================================================================
8. ПРАКТИЧЕСКИЙ РЕЗУЛЬТАТ
================================================================================

    По завершении исследования для каждого канала Theme Specification должны быть окончательно определены:
        - назначение;
        - область ответственности;
        - состав описываемых данных;
        - информация, которая принципиально не должна находиться в данном канале;
        - преобразования, выполняемые Resolution;
        - фундаментальные IR-узлы, формируемые Resolution;
        - Artifact Generators, использующие полученный IR;
        - статус канала (Confirmed / Extended / Rejected).

    Дополнительно должны быть зафиксированы все отрицательные результаты исследования.

        В частности:
            - какие концепции не должны присутствовать в Theme Specification;
            - какие концепции относятся к другим подсистемам;
            - какие задачи должны решаться Resolution;
            - какие задачи относятся исключительно к Artifact Generators.

================================================================================
9. КРИТЕРИЙ ЗАВЕРШЕНИЯ
================================================================================

    Исследование считается завершённым, если будет подтверждено, что любая WP тема,
        входящая в область ответственности ThemeCore, может быть
        полностью описана средствами существующей Theme Specification либо её
        минимально обоснованного расширения.

    При этом:
        - вся необходимая информация может быть выражена декларативно;
        - Resolution способен детерминированно построить фундаментальный IR
            без использования предположений;
        - каждый Artifact Generator получает всю необходимую информацию
            исключительно через Intermediate Representation;
        - не возникает необходимости вводить новые специализированные Definition-классы
            или нарушать существующую архитектуру.

    В этом случае Theme Specification рассматривается как окончательная декларативная модель темы,
        а Resolution — как единственный механизм преобразования Theme Specification
        в фундаментальное Intermediate Representation ThemeCore.
