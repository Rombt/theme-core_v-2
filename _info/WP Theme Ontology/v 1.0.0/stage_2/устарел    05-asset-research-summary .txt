1. ОБЪЕКТ ИССЛЕДОВАНИЯ
================================================================================

    Концепция: Asset

    В рамках Theme Specification Asset рассматривается как декларативное
    описание ресурсов темы.


2. ОСНОВНЫЕ РЕЗУЛЬТАТЫ
================================================================================

    2.1 Asset является фундаментальной концепцией.
    --------------------------------------------------------------------------------

        Asset невозможно вывести из других каналов Theme Specification.
        Информация о ресурсах темы является самостоятельной частью её описания.
        Следовательно, Asset подтверждается как фундаментальная концепция.


    2.2 Asset описывает ресурс, а не файл.
    --------------------------------------------------------------------------------

        Asset представляет собой логический ресурс темы.
        Файл является лишь одной из возможных форм его хранения или публикации.
        Поэтому Theme Specification должна описывать именно ресурс, а не его
        физическое расположение.


    2.3 Архитектура Theme Specification подтверждается.
    --------------------------------------------------------------------------------

        Для описания ресурсов уже существует специализированный канал: assets.php
        Необходимости вводить дополнительные каналы не выявлено.
        Архитектура Theme Specification признана достаточной.


    2.4 Недостаточной является только модель данных.
    --------------------------------------------------------------------------------

        Текущая структура assets.php пригодна для MVP и позволяет описывать лишь
        расположение отдельных файлов.
        Для описания современной коммерческой темы модель должна быть расширена.
        При этом расширяется исключительно содержимое канала.
        Архитектура Theme Specification остаётся неизменной.


3. RESOLUTION
================================================================================

    Resolution обязан:
        - проверить корректность описания ресурсов;
        - нормализовать Asset;
        - разрешить внутренние зависимости;
        - построить Asset IR. 

    Resolution не должен:
        - выполнять сборку ресурсов;
        - минифицировать файлы;
        - копировать файлы;
        - выполнять регистрацию ресурсов в WordPress.


4. FUNDAMENTAL IR
================================================================================

    Результатом Resolution является Asset IR.
    Asset IR представляет собой нормализованное описание всех ресурсов темы.
    Все последующие генераторы работают исключительно с Asset IR.


5. ARTIFACT GENERATORS
================================================================================

    Asset IR является источником информации для генераторов ресурсов.

    Минимально:

        - Asset Publisher;
        - functions.php Generator;
        - theme.json Generator (при необходимости);
        - Build Manifest Generator;
        - других генераторов, использующих ресурсы темы.


6. ПРОВЕРКА ОСНОВНОЙ ГИПОТЕЗЫ
================================================================================

    Подтверждена архитектурная цепочка:

        Theme Specification
                ↓
            Resolution
                ↓
            Asset IR
                ↓
        Artifact Generators
                ↓
        Published Assets

    Построение Asset IR выполняется детерминированно.

    Дополнительные предположения со стороны Resolution не требуются.


7. ИТОГОВЫЙ ВЕРДИКТ
================================================================================

    - Asset является самостоятельной фундаментальной концепцией.
    - assets.php является правильным каналом Theme Specification.
    - Архитектура Theme Specification изменяться не должна.
    - Требуется расширение модели данных внутри assets.php.
    - Resolution должен строить самостоятельный Asset IR.
    - Все генераторы ресурсов должны работать исключительно через Asset IR.

    Концепция получает статус: CONFIRMED
