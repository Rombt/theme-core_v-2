TEMPLATES RESOURCE STRATEGY

Ресурс узла является первичным источником его представления.

Theme Core не должен самостоятельно преобразовывать ресурс узла из одной архитектуры в другую
    и не должен заменять его встроенными блоками WordPress или собственными шаблонами.

Если проект поддерживает несколько архитектур генерации,
    то для каждой архитектуры автор темы должен предоставить собственный ресурс.

    Например:

    resources/
    └── component/
        └── site_title_01/
            ├── classic.php
            └── block.html


Один и тот же Node может участвовать в генерации нескольких артефактов.

Представление Node всегда определяется его ресурсом и зависит от целевой архитектуры.

Дополнительный код, не являющийся представлением (например, регистрация меню, сайдбаров,
    поддержек темы и других инфраструктурных возможностей WordPress),
    не должен находиться в ресурсе. 

Такой код определяется метаданными Node и генерируется соответствующим
    Artifact Generator в необходимые артефакты (например, functions.php).

Таким образом:
    - ThemeIR определяет, что должно быть сгенерировано.
    - Ресурс определяет, как выглядит Node в конкретной архитектуре.
    - Artifact Generator определяет, каким образом Node должен быть интегрирован
        в артефакты целевой архитектуры.


Структура ресурсов
    Каждый Node является самодостаточной сущностью.
    Все файлы, относящиеся к Node, располагаются в его собственной директории.

    Типичная структура:

        <node_name>/
        ├── README.md
        ├── style.css
        ├── script.js
        ├── classic.php
        └── block.html

    Где:
        README.md - Документация Node.
        style.css - Стили Node.
        script.js - Клиентская логика Node.
        classic.php - Представление Node для Classic Theme.
        block.html - Представление Node для Block Theme.


Причина

    Конечная цель проекта — генерация двух архитектур
        одной и той же темы с одинаковым внешним видом и поведением.

    Поскольку реализация представления является частью дизайна темы,
        только автор темы может определить её корректное представление для каждой архитектуры.

    Одновременно часть функциональности Node может требовать генерации
        дополнительной инфраструктуры WordPress, не связанной с представлением.
        Эти различия являются особенностью целевой архитектуры и должны решаться
        соответствующим Artifact Generator.

    Следовательно, задача Theme Core заключается не в преобразовании ресурсов,
        а в выборе и использовании ресурса, соответствующего целевой архитектуре,
        а также в генерации необходимой инфраструктуры средствами Artifact Generator.
