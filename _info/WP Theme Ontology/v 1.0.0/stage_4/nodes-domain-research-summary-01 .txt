theme-core v-2
NODES DOMAIN RESEARCH
SUMMARY
(v1.0.0)

Status: Research Completed

==================================================
1. PURPOSE
==================================================

    Целью исследования являлось определение роли
    самостоятельного домена Nodes в архитектуре
    theme-core v-2 и его границы относительно
    домена Composition.

==================================================
2. INITIAL HYPOTHESIS
==================================================

    Было предложено выделить новый домен Nodes.

    Предполагалось, что:

        Nodes
            содержит полный набор структурных элементов,
            доступных теме.

        Theme Components
            использует Nodes для построения Composition.

==================================================
3. RESEARCH RESULT
==================================================

    Гипотеза подтвердилась.

    Nodes представляет самостоятельный домен,
    существующий независимо от Composition.

==================================================
4. DOMAIN RESPONSIBILITY
==================================================

    В ходе исследования удалось провести чёткое
    разделение ответственности.

    Nodes отвечает на вопрос:

        "Какие структурные элементы существуют
        в данной теме?"

    Composition отвечает на вопрос:

        "Каким образом эти элементы организованы
        внутри представлений темы?"

==================================================
5. MINIMAL DOMAIN MODEL
==================================================

    Минимальная предметная модель Nodes
    содержит единственную фундаментальную сущность.

    --------------------------------------------------
    Node
    --------------------------------------------------

        Node представляет Composition Element,
        доступный теме.

        Node не содержит информации о:

            - расположении;
            - родителях;
            - потомках;
            - порядке;
            - представлениях (View).

        Все эти сведения принадлежат
        исключительно Composition.

==================================================
6. RELATIONSHIP WITH COMPOSITION
==================================================

    Было установлено следующее разделение.

        Nodes
            объявляет существующие Node.

        Composition
            использует только ранее объявленные Node.

    Composition больше не создаёт элементы,
    а лишь организует их структуру.

==================================================
7. IMPORTANT OBSERVATION
==================================================

    Один и тот же Node может использоваться
    в Composition многократно.

    Следовательно,

        Node
            не является экземпляром элемента
            внутри дерева Composition.

    Экземпляры возникают исключительно
    посредством Placement.

==================================================
8. IMPLEMENTATION DISCUSSION
==================================================

    Первоначально рассматривалась идея хранения
    содержимого Node непосредственно
    внутри nodes.php.

    Например:

        'site-title' => [
            'content' => '...'
        ]

    Данное решение было признано неудачным.

==================================================
9. FINAL ARCHITECTURAL DECISION
==================================================

    Было принято решение отказаться
    от хранения содержимого Node
    внутри конфигурационного файла.

    Вместо этого каждый Node должен
    представлять самостоятельную директорию,
    содержащую все необходимые ресурсы.

    Например:

        nodes/
            site-title/
                ...

            navigation/
                ...

            hero/
                ...

==================================================
10. CONSEQUENCES
==================================================

    Node перестаёт быть строкой
    с PHP-кодом.

    Node становится самостоятельной
    единицей темы.

    Каждый Node может содержать любые ресурсы,
    необходимые для своей работы.

    Например:

        - PHP;
        - HTML;
        - CSS;
        - JavaScript;
        - SVG;
        - изображения;
        - любые другие файлы.

==================================================
11. ARCHITECTURAL BENEFITS
==================================================

    Такое решение обеспечивает:

        - полную самостоятельность каждого Node;

        - возможность использовать произвольные
          типы ресурсов;

        - отсутствие генерации PHP-кода
          на раннем этапе развития проекта;

        - естественную масштабируемость системы;

        - сохранение чистой границы между
          Nodes и Composition.

==================================================
12. RESEARCH COMPLETION CRITERION
==================================================

    Исследование считается завершённым.

    Минимальная предметная модель домена Nodes
    определена.

    Также принято архитектурное решение
    о файловом представлении Node.

    Дальнейшая работа должна быть направлена
    на реализацию данной модели
    в архитектуре theme-core v-2.
