theme-core v-2
NODES DOMAIN
IMPLEMENTATION MODEL
(v1.0.0)

Status: Approved

==================================================
1. PURPOSE
==================================================

    Данный документ определяет целевую модель
    реализации домена Nodes, принятую
    для использования в theme-core v-2.

    Документ является прикладной спецификацией
    и предназначен непосредственно
    для реализации в коде.

==================================================
2. GENERAL PRINCIPLES
==================================================

    Node представляет самостоятельную единицу
    темы, содержащую собственные ресурсы.

    Каждый Node обладает собственной
    идентичностью и описывается независимым
    набором метаданных.

    Node не содержит информации
    о своём расположении внутри Composition.

    Node также не содержит информации
    о способе своей обработки.

    Его задача исключительно описывать
    существующий ресурс темы.

==================================================
3. REQUIRED PROPERTIES
==================================================

    Каждый Node обязан содержать
    следующий набор свойств.

--------------------------------------------------
id
--------------------------------------------------

    Уникальный идентификатор Node.

    Используется исключительно системой.

    Не зависит:

        - от имени Node;
        - от расположения ресурсов;
        - от структуры каталогов.

--------------------------------------------------
type
--------------------------------------------------

    Обязательное описание типа Node.

    Тип определяет семейство обработчиков,
    которое должно использоваться
    компилятором.

    Тип не описывает внешний вид Node.

--------------------------------------------------
resource
--------------------------------------------------

    Ссылка на набор ресурсов Node.

    Resource не является файловым путём.

    Resource представляет логическую ссылку,
    используемую ResourceResolver
    для поиска ресурсов Node.

--------------------------------------------------
name
--------------------------------------------------

    Краткое человекочитаемое имя Node.

    Используется исключительно
    для отображения разработчику.

==================================================
4. OPTIONAL PROPERTIES
==================================================

    Node может содержать дополнительные поля.

--------------------------------------------------
description
--------------------------------------------------

    Подробное описание Node.

--------------------------------------------------
capabilities
--------------------------------------------------

    Список поддерживаемых возможностей.

--------------------------------------------------
metadata
--------------------------------------------------

    Произвольные пользовательские данные.

==================================================
5. NODE TYPE
==================================================

    Каждый Node обязан принадлежать
    некоторому типу.

    Тип определяет:

        - семейство обработчиков;

        - правила обработки;

        - стратегию обработки по умолчанию.

    Тип является самостоятельной сущностью
    предметной модели.

==================================================
6. PROCESSING STRATEGY
==================================================

    Каждый тип Node содержит
    стратегию обработки.

    Если стратегия явно
    не указана в Node,
    используется стратегия,
    определённая типом.

    Таким образом:

        стратегия по умолчанию
        определяется типом,

        Node переопределяет её
        только при необходимости.

==================================================
7. STRATEGY OVERRIDE
==================================================

    При возникновении нестандартных случаев
    Node может определить собственную
    стратегию обработки.

    Например:

        type:

            name: component

            strategy: custom

    Подобное переопределение является
    исключением и должно использоваться
    только при необходимости.

==================================================
8. RESOURCE MODEL
==================================================

    Было принято решение отказаться
    от хранения файловых путей
    непосредственно внутри Node.

    Вместо этого вводится понятие
    Resource.

    Resource представляет логическую ссылку
    на набор ресурсов Node.

    Разрешение Resource выполняется
    исключительно посредством
    ResourceResolver.

==================================================
9. RESOURCE PACKAGE
==================================================

    Каждая тема обязана содержать
    собственный пакет ресурсов Node.

    Путь к данному пакету указывается
    в конфигурации темы.

    Например:

        resources_path

    Компилятор использует данный путь
    как корень поиска ресурсов.

==================================================
10. STANDARD DIRECTORY STRUCTURE
==================================================

    Внутри пакета ресурсов
    должна использоваться
    единая стандартная структура каталогов.

    Каталоги организуются
    по типам Node.

    Например:

        resources/

            components/

            layouts/

            queries/

            content/

            integrations/

            ...

    Конкретный набор каталогов
    определяется зарегистрированными
    типами Node.

==================================================
11. RESOURCE RESOLUTION
==================================================

    Для поиска ресурсов Node
    компилятор использует:

        - путь к пакету ресурсов;

        - тип Node;

        - идентификатор Node.

    На основании этих данных
    ResourceResolver определяет
    физическое расположение ресурсов.

    Таким образом,

        Node не содержит файловых путей,

        а ResourceResolver является
        единственной точкой,
        отвечающей за разрешение ресурсов.

==================================================
12. ARCHITECTURAL BENEFITS
==================================================

    Принятая модель обеспечивает:

        - минимальную модель Node;

        - отсутствие дублирования
          файловых путей;

        - единообразную организацию
          ресурсов всех тем;

        - возможность централизованного
          поиска ресурсов;

        - независимость предметной модели
          от структуры файловой системы;

        - простую реализацию
          ResourceResolver;

        - возможность изменения внутренней
          структуры хранения ресурсов
          без изменения модели Node.

==================================================
13. IMPLEMENTATION NOTES
==================================================

    При реализации рекомендуется
    придерживаться принципа:

        Convention over Configuration.

    Node описывает только действительно
    уникальные свойства.

    Все остальные сведения должны
    определяться соглашениями,
    принятыми в архитектуре проекта.

==================================================
14. IMPLEMENTATION CRITERION
==================================================

    Реализация домена Nodes считается
    соответствующей данной спецификации,
    если:

        - существует самостоятельная модель Node;

        - реализована модель NodeType;

        - реализован ResourceResolver;

        - поддерживаются стратегии по умолчанию;

        - поддерживается локальное переопределение стратегии Node;

        - поиск ресурсов выполняется исключительно посредством
            ResourceResolver;

        - все Node проходят обязательную валидацию перед использованием
            в pipeline.
