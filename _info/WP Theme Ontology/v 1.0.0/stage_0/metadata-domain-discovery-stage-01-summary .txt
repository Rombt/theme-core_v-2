Исследование фундаментального домена Metadata
Этап 3. Подведение итогов исследования


Цель
--------------------------------------------------------------------------------

    Проверить, укладывается ли фундаментальный домен Metadata в архитектурную
    гипотезу:

        Description
            ↓
        Resolution
            ↓
        Artifacts

    При этом целью исследования было не подтвердить гипотезу любой ценой,
    а попытаться найти случаи, в которых она перестаёт работать.


================================================================================
1. Основные выводы по домену Metadata
================================================================================

    1. Metadata описывает не WordPress и не файлы.
    --------------------------------------------------------------------------------

    Metadata описывает тему как самостоятельный продукт.

    Он отвечает на вопрос:
            "Что представляет собой данная тема?"
        а не:
            "Как она устроена?"
        или
            "Как она будет опубликована?"



    2. Metadata является платформенно-независимым описанием.
    --------------------------------------------------------------------------------

        Такие вещи как:

            - style.css
            - readme.txt
            - WordPress.org
            - Envato
            - package.json

        не являются частью Metadata.

    Они являются лишь различными представлениями одного и того же описания.

    Следовательно Metadata должна существовать независимо от любой конкретной
        платформы публикации.



    3. Description обнаружился естественным образом.
    --------------------------------------------------------------------------------

        Description Metadata представляет собой декларативное описание темы:

        - Name
        - Description
        - Version
        - Author
        - License
        - Homepage
        - Support
        - Compatibility
        - Localization
        - Tags
        - и т.д.

        Description ничего не знает о том,
        где и в каком формате эти сведения будут опубликованы.



    4. Resolution также проявился естественным образом.
    --------------------------------------------------------------------------------

        Description содержит только смысл.

        Resolution принимает решения,
        необходимые для публикации этого смысла.

        Например:
            - формат версии;
            - формат лицензии;
            - отображение полей;
            - выбор имени поля;
            - преобразование модели под требования конкретной платформы.

        Description при этом остаётся неизменным.



    5. Artifacts являются лишь фиксацией результата.
    --------------------------------------------------------------------------------

        Например:
            - style.css
            - readme.txt
            - marketplace manifest
            - package metadata

        не являются частью предметной модели.

        Они являются конечным результатом процесса Resolution.


================================================================================
2. Проверка архитектурной гипотезы
================================================================================

    Для домена Metadata цепочка

        Description
            ↓
        Resolution
            ↓
        Artifacts

    возникла естественным образом.

    На данном этапе она уже независимо подтвердилась на трёх фундаментальных доменах:
        - Composition
        - Asset
        - Metadata

    Вероятность случайного совпадения значительно уменьшилась.


================================================================================
3. Новые архитектурные принципы
================================================================================

    Принцип 1
    --------------------------------------------------------------------------------

        Description никогда не должно зависеть от формата конечного артефакта.

        Если при проектировании Description приходится думать:

            - как это попадёт в style.css;
            - как это будет выглядеть в theme.json;
            - как это окажется в HTML;
            - как это будет записано в JSON;

        значит нарушена граница между Description и Artifacts.

        Этот принцип предлагается считать одним из фундаментальных принципов
        архитектуры theme-core v-2.



    Принцип 2
    --------------------------------------------------------------------------------

        Resolution не изменяет смысл Description.

        Resolution лишь устраняет неопределённости,
        необходимые для получения конкретных артефактов.

        Он не создаёт новых знаний о предметной области.

        Он лишь делает уже существующее описание пригодным для публикации.



    Принцип №3
    --------------------------------------------------------------------------------

        Description содержит смысл.

        Resolution добавляет контекст.

        Artifacts фиксируют результат.

        Именно такое распределение ответственности наблюдается во всех исследованных
        доменах.


================================================================================
4. Более глубокое наблюдение
================================================================================

    Во всех исследованных доменах Description отвечает только на вопрос:

        "Что существует?"

    Он принципиально не отвечает на вопросы:

        - как;
        - где;
        - когда;
        - для кого;
        - в каком формате.

    Эти вопросы появляются исключительно на этапе Resolution.


================================================================================
5. Наиболее важное открытие исследования
================================================================================

    Появилась гипотеза более высокого уровня.

    Жизненный цикл любого фундаментального домена представляет собой процесс последовательного уменьшения неопределённости.

        Description
        ------------------
            Максимальная свобода. Декларативное описание предметной области.
        ↓
        Resolution
        ------------------
            Последовательное устранение неопределённостей. Выбор одного из допустимых вариантов представления.
        ↓
        Artifacts
        ------------------
            Полностью определённый результат. Неопределённостей больше не остаётся.


    Иными словами:
        Любой фундаментальный домен проходит путь от декларативного знания к полностью определённому представлению.


================================================================================
6. Текущее состояние исследования
================================================================================

    Исследованы:

        ✓ Composition
        ✓ Asset
        ✓ Metadata

    Все три домена естественным образом проходят жизненный цикл:

        Description
            ↓
        Resolution
            ↓
        Artifacts

    Следующим шагом предлагается исследовать Runtime.

    Именно Runtime является наиболее сложной проверкой гипотезы, поскольку
    это первый фундаментальный домен, который на первый взгляд кажется
    процессным, а не декларативным.

    Если и Runtime естественным образом уложится в эту модель,
    архитектурную гипотезу можно будет считать очень серьёзно подтверждённой
    и подготовить её к фиксации в качестве первого фундаментального принципа
    архитектуры theme-core v-2.
