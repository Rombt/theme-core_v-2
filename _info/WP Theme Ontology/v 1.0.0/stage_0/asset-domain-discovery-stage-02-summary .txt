===============================================================================
ИССЛЕДОВАНИЕ ФУНДАМЕНТАЛЬНОГО ДОМЕНА ASSET
ПРОМЕЖУТОЧНЫЙ ИТОГ №2
===============================================================================

Статус:
Рабочая архитектурная гипотеза.

Исследование не завершено.

-------------------------------------------------------------------------------
Исходная постановка вопроса
-------------------------------------------------------------------------------

       Первоначально предполагалось, что домен Asset отвечает за различные файлы,
       которые должны присутствовать в итоговой WordPress-теме:

       - изображения;
       - шрифты;
       - JavaScript;
       - CSS;
       - favicon;
       - preview image;
       - прочие статические ресурсы.

       Необходимо было определить, является ли Asset самостоятельным фундаментальным
       доменом или представляет собой инфраструктурную деталь процесса сборки.

-------------------------------------------------------------------------------
Главное открытие исследования
-------------------------------------------------------------------------------

Первоначальная гипотеза оказалась ошибочной.

Asset не следует рассматривать как физический файл.

Если рассматривать Asset как файл, домен практически не имеет собственной
предметной логики и быстро вырождается в инфраструктурную обёртку над файловой
системой.

Исследование показало, что более правильным является другой взгляд.

Asset представляет собой не файл, а описание ресурса темы.

-------------------------------------------------------------------------------
Новая интерпретация Asset
-------------------------------------------------------------------------------

Asset является декларативным описанием ресурса, необходимого теме.

Примеры:

- Logo
- Font
- Script
- Favicon
- Preview Image
- Icon
- Video

Asset описывает существование ресурса и его роль в теме.

Asset не описывает конкретный файл.

-------------------------------------------------------------------------------
Предварительная ответственность Asset
-------------------------------------------------------------------------------

На текущем этапе исследования предполагается, что Asset отвечает за описание:

1. Что представляет собой ресурс.

   Примеры:

   - Logo
   - Font
   - Script
   - Favicon

2. Какая роль ресурса в теме.

   Примеры:

   - primary logo
   - footer logo
   - preview image
   - main font

3. Какие требования предъявляются к ресурсу.

   Примеры:

   - svg required
   - font family required
   - script module

4. Каким образом ресурс используется темой.

   Примеры:

   - отображается как логотип
   - подключается как JavaScript
   - используется как favicon
   - используется как preview image

-------------------------------------------------------------------------------
Что НЕ является ответственностью Asset
-------------------------------------------------------------------------------

Asset не должен:

- копировать файлы;
- создавать директории;
- публиковать файлы;
- выполнять оптимизацию;
- выполнять минификацию;
- вычислять hash;
- работать с файловой системой.

Все подобные действия относятся к инфраструктуре сборки.

-------------------------------------------------------------------------------
Ключевая архитектурная идея
-------------------------------------------------------------------------------

Во время исследования была обнаружена неожиданная симметрия между доменами.

Composition описывает структуру темы.

Asset описывает ресурсы темы.

Ни один из этих доменов не должен знать о способе своей реализации.

-------------------------------------------------------------------------------
Симметрия доменов
-------------------------------------------------------------------------------

Composition

    Description
           ↓
    Resolver
           ↓
    Artifacts


Asset

    Description
           ↓
    Resolver
           ↓
    Artifacts

-------------------------------------------------------------------------------
Предварительная модель Composition
-------------------------------------------------------------------------------

Composition отвечает на вопрос:

    Из каких частей состоит тема?

Примеры:

- Header
- Footer
- Navigation
- Hero
- Sidebar

Composition ничего не знает:

- о PHP;
- о WordPress;
- о файловой системе.

Его реализацией занимается Composition Resolver
(на текущем этапе — Renderer).

-------------------------------------------------------------------------------
Предварительная модель Asset
-------------------------------------------------------------------------------

Asset отвечает на вопрос:

    Какими ресурсами обеспечивается тема?

Примеры:

- Logo
- Font
- Script
- Favicon

Asset ничего не знает:

- о путях к файлам;
- о package;
- о build;
- о файловой системе.

Его реализацией занимается Asset Resolver.

-------------------------------------------------------------------------------
Гипотеза Asset Resolver
-------------------------------------------------------------------------------

Предполагается существование отдельного слоя разрешения ресурсов.

Asset Resolver отвечает за поиск конкретной реализации ресурса.

Пример:

Logo Asset
      ↓
Asset Resolver
      ↓
package/assets/logo.svg

Таким образом домен Asset остаётся полностью независимым от физического
представления ресурса.

-------------------------------------------------------------------------------
Наиболее важное открытие исследования
-------------------------------------------------------------------------------

Возможно, фундаментом архитектуры theme-core v-2 являются не сами домены.

Возможно, фундаментом являются различные виды описаний темы.

ThemeDefinition начинает выглядеть как контейнер независимых описаний.

Пример:

ThemeDefinition

├── Composition Description
├── Asset Description
├── Metadata Description
├── Localization Description
├── Design Description
└── ...

Каждое описание:

- обладает собственным языком;
- обладает собственной моделью;
- имеет собственный Resolver;
- производит собственные артефакты.

-------------------------------------------------------------------------------
Рабочая гипотеза для дальнейших исследований
-------------------------------------------------------------------------------

Все фундаментальные домены theme-core v-2 должны проверяться на соответствие
следующему шаблону:

    Description
           ↓
    Resolution
           ↓
    Artifacts

Если домен естественным образом укладывается в данную модель, это является
сильным признаком его фундаментальности и архитектурной состоятельности.

Данная гипотеза должна использоваться как критерий проверки при исследовании
всех последующих фундаментальных доменов проекта.

-------------------------------------------------------------------------------
Текущий вывод
-------------------------------------------------------------------------------

На текущем этапе Asset больше не рассматривается как файловая модель.

Asset рассматривается как самостоятельный домен описания ресурсов темы.

Одновременно с этим появилась более общая гипотеза о том, что архитектура
theme-core v-2 может состоять из набора независимых описательных доменов,
каждый из которых проходит одинаковый жизненный цикл:

Описание → Разрешение → Артефакты.

Проверка данной гипотезы становится одной из ключевых задач дальнейшего
архитектурного исследования проекта.
