THEME-CORE V-2
МЕТОДОЛОГИЯ ИССЛЕДОВАНИЯ THEME COMPONENTS
(v1.0.0)

Статус:
Working Draft / Research Methodology

================================================================================
1. НАЗНАЧЕНИЕ
================================================================================

    Данная методология определяет единый подход к исследованию предметной области
        ThemeCore при проектировании системы ThemeComponents.

    Методология предназначена для последовательного перехода:

        исследование предметной области
                ↓
        выявление фундаментальных концепций
                ↓
        построение архитектурной модели
                ↓
        проектирование PHP-модели
                ↓
        реализация ThemeCore

    Исследование не является самоцелью.

    Его единственной целью является построение минимальной архитектурной модели,
        достаточной для качественной реализации ThemeCore.


================================================================================
2. ОСНОВНОЙ ПРИНЦИП
================================================================================

    Любой результат исследования должен приближать проект
        к реализации в коде.

    Исследование не должно приводить к построению абстрактных теорий,
        не имеющих практического применения.

    Если полученный вывод невозможно использовать
        при проектировании архитектуры или реализации системы,
        данный вывод считается не имеющим самостоятельной ценности.


================================================================================
3. ОБЪЕКТ ИССЛЕДОВАНИЯ
================================================================================

    Объектом исследования является не код,
        не PHP-классы,
        не существующая реализация ThemeCore.

    Исследуется исключительно предметная область.

    Основной вопрос исследования:

        Какие самостоятельные области знаний
            существуют внутри WordPress Theme?


================================================================================
4. ПРИНЦИП ИНФОРМАЦИОННОЙ НЕЗАВИСИМОСТИ
================================================================================

    Любая фундаментальная концепция рассматривается
        как самостоятельная область знаний.

    ThemeComponent определяется как:

        самостоятельная декларативная область знаний темы,
        обладающая собственной ответственностью
        и не выводимая полностью из других областей знаний.

    На данном этапе исследования не рассматриваются:

        - классы;
        - интерфейсы;
        - наследование;
        - структура PHP-моделей;
        - способы хранения данных.

    Все вопросы реализации относятся к последующим этапам.


================================================================================
5. ПРИНЦИП ФУНДАМЕНТАЛЬНОГО ВОПРОСА
================================================================================

    Самостоятельная область знаний определяется
        фундаментальным вопросом,
        на который отвечает исключительно она.

    Для каждой исследуемой концепции необходимо определить:

        На какой фундаментальный вопрос о теме
            отвечает данная концепция?

    Если два компонента отвечают
        на один и тот же фундаментальный вопрос,
        то:

        либо их ответственность пересекается;

        либо один из них является производным
            от другого.


================================================================================
6. КРИТЕРИИ ФУНДАМЕНТАЛЬНОСТИ
================================================================================

    Концепция признаётся самостоятельным ThemeComponent,
        только если выполняются все условия.

        1.
        Она отвечает
            на собственный фундаментальный вопрос.

        2.
        Она содержит знания,
            отсутствующие в других компонентах.

        3.
        Эти знания невозможно полностью вывести
            из других компонентов.

        4.
        Удаление компонента приводит
            к безвозвратной потере информации о теме.

        5.
        Компонент имеет собственную
            область ответственности.

        6.
        Полученная модель может быть
            непосредственно использована
            при проектировании ThemeCore.


================================================================================
7. КРИТЕРИИ ПРОИЗВОДНОЙ КОНЦЕПЦИИ
================================================================================

    Концепция не должна становиться
        самостоятельным ThemeComponent,
        если выполняется хотя бы одно условие.

        - полностью выводится
            из других компонентов;

        - является лишь способом представления
            другой информации;

        - описывает процесс,
            а не знания;

        - относится к реализации,
            а не предметной области;

        - существует исключительно
            ради последующей генерации.


================================================================================
8. ПРИНЦИП ФАЛЬСИФИКАЦИИ
================================================================================

    Любая архитектурная гипотеза
        должна проверяться попыткой её опровергнуть.

    Исследование должно искать не подтверждения,
        а ситуации,
        в которых предлагаемая модель перестаёт работать.

    Только гипотеза,
        успешно выдержавшая подобную проверку,
        может рассматриваться
        как архитектурный инвариант.


================================================================================
9. ПРИНЦИП МИНИМАЛЬНОСТИ
================================================================================

    Исследование направлено
        на поиск минимальной модели.

    Необходимо выявить минимальный набор
        фундаментальных компонентов,
        достаточный для описания любой темы,
        входящей в область ответственности ThemeCore.

    Появление новой концепции
        требует отдельного архитектурного обоснования.


================================================================================
10. ПЕРЕХОД К PHP-МОДЕЛИ
================================================================================

    Проектирование PHP-моделей
        начинается только после завершения
        исследования предметной области.

    Последовательность проектирования:

        Предметная область
                ↓

        Самостоятельные области знаний
                ↓

        Архитектурная модель ThemeComponent
                ↓

        PHP-модель
                ↓

        Реализация BuildThemeComponentsStage

    Таким образом архитектура определяет код,
        а не наоборот.


================================================================================
11. МЕТОД ИССЛЕДОВАНИЯ КАЖДОЙ КОНЦЕПЦИИ
================================================================================

    Для каждой новой концепции
        последовательно выполняются следующие шаги.

        Шаг 1.

            Определить,
                какой фундаментальный вопрос
                о теме отвечает данная концепция.

        Шаг 2.

            Определить,
                является ли этот вопрос уникальным.

        Шаг 3.

            Проверить,
                содержатся ли её знания
                в других компонентах.

        Шаг 4.

            Проверить,
                можно ли детерминированно
                вывести данную концепцию
                из других компонентов.

        Шаг 5.

            Определить,
                какая информация должна существовать
                после BuildThemeComponentsStage.

        Шаг 6.

            Определить,
                какой минимальный набор данных
                необходим следующей стадии Pipeline.

        Шаг 7.

            Только после этого
                проектировать PHP-модель.


================================================================================
12. КРИТЕРИЙ ЗАВЕРШЕНИЯ ИССЛЕДОВАНИЯ
================================================================================

    Исследование считается завершённым,
        если для каждой фундаментальной области знаний
        установлено:

        - её фундаментальный вопрос;

        - область ответственности;

        - уникальность знаний;

        - невозможность полного вывода
            из других компонентов;

        - минимальный состав информации,
            необходимый следующей стадии Pipeline;

        - возможность естественного
            проектирования PHP-модели.

    После этого BuildThemeComponentsStage
        может быть реализована
        без дополнительных архитектурных исследований.
