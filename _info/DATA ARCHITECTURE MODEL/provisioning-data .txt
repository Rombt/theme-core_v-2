==================================================
PROVISIONING DATA
==================================================

    Provisioning Data — это данные и инструкции, которые описывают:
        как система должна собрать,
        установить
        и подготовить сайт
        из всех остальных архитектурных слоёв.

    Проще говоря: Provisioning — это “процесс сборки сайта с нуля”.

        Это не сайт.
        Это не структура сайта.
        Это не контент.

    Это сценарий того, как сайт появляется в системе.

--------------------------------------------------
ГЛАВНАЯ ИДЕЯ PROVISIONING
--------------------------------------------------

Provisioning отвечает на вопрос:
    "Как система превращается из пустого состояния в полностью готовый сайт?"

--------------------------------------------------
ОЧЕНЬ ВАЖНОЕ РАЗДЕЛЕНИЕ
--------------------------------------------------

    Provisioning — это не runtime.

    Provisioning — это не configuration.

    Provisioning — это не composition.

    Provisioning — это процесс инициализации системы.

--------------------------------------------------
ПРОСТАЯ АНАЛОГИЯ
--------------------------------------------------

    Если представить theme-core v-2 как завод:

        Foundation = детали и стандарты
        Composition = чертежи сборки
        Configuration = выбор модели продукта
        Content = материалы и наполнение

    то Provisioning —
        это: процесс сборки на заводе

--------------------------------------------------
ПРОСТОЙ ПРИМЕР
--------------------------------------------------

    Когда устанавливается новый сайт, система должна сделать:

        создать страницы
        импортировать demo content
        применить composition templates
        включить presets
        зарегистрировать layouts
        подключить integrations
        настроить menus
        назначить homepage

    Всё это — и есть provisioning процесс.

--------------------------------------------------
ЧТО ИМЕННО ВХОДИТ В PROVISIONING DATA
--------------------------------------------------

    1. DEMO MANIFESTS
    --------------------------------------------------

        Это описание демо-сайта.

        Например:
            demo: startup-v1
                includes:
                    homepage
                    pricing page
                    blog
                uses:
                    composition set A
                    design preset dark-modern

    2. INSTALLATION STEPS
    --------------------------------------------------

        Последовательность установки:
            1. create pages
            2. register compositions
            3. import content
            4. apply configuration
            5. activate theme preset

    --------------------------------------------------
    3. IMPORT PIPELINES
    --------------------------------------------------

        Например:
            import:
                products from WooCommerce
                posts from demo source
                media library assets

    --------------------------------------------------
    4. SETUP QUEUES
    --------------------------------------------------

        Очереди задач установки:
            - create pages
            - assign layouts
            - attach content
            - register menus

    --------------------------------------------------
    5. INITIAL STATE DEFINITIONS
    --------------------------------------------------

        Начальное состояние сайта:
            homepage = landing-v2
            blog = editorial-v1
            theme_mode = dark

    --------------------------------------------------
    6. ONBOARDING FLOWS
    --------------------------------------------------

        Пошаговая настройка сайта:

            step 1: choose demo
            step 2: import content
            step 3: select design preset
            step 4: finalize configuration

    --------------------------------------------------
    7. ASSEMBLY RULES
    --------------------------------------------------

        Правила сборки сайта:

            if demo = ecommerce:
                enable WooCommerce integration

            if demo = blog:
                enable blog compositions

--------------------------------------------------
ЧТО PROVISIONING НЕ СОДЕРЖИТ
--------------------------------------------------

    Provisioning НЕ содержит:

        actual site structure (Composition)
        design rules (Foundation)
        content itself (Content)
        runtime state (Runtime)

--------------------------------------------------
ВАЖНОЕ РАЗДЕЛЕНИЕ
--------------------------------------------------

    Provisioning НЕ является частью работающего сайта.

    Provisioning — это процесс ДО того, как сайт стал активным.

--------------------------------------------------
ПРОСТОЙ ПРИМЕР
--------------------------------------------------

    BEFORE PROVISIONING:
        system is empty

    PROVISIONING:
        run demo installer
        create pages
        attach compositions
        import content
        apply configuration

    AFTER PROVISIONING:
        site is fully assembled
        runtime system takes over

--------------------------------------------------
PROVISIONING VS RUNTIME
--------------------------------------------------

    Provisioning:
        happens once (or rarely)
        during installation
        builds system state

    Runtime:
        happens constantly
        during user interaction
        executes system

--------------------------------------------------
ПОЧЕМУ PROVISIONING ВАЖЕН
--------------------------------------------------

    Без provisioning:

        каждый сайт пришлось бы собирать вручную
        нет автоматизации demo setup
        нет reproducible site builds
        нет migration system

    Provisioning позволяет:

        быстро разворачивать сайты
        создавать demo системы
        переносить конфигурации
        автоматизировать setup процесса

--------------------------------------------------
PROVISIONING И WORDPRESS
--------------------------------------------------

    В WordPress:

        Provisioning частично существует как:
            theme activation
            demo import plugins
            XML import
            WooCommerce setup wizards

    Но это:
        разрозненные системы

--------------------------------------------------
theme-core v-2 подход
--------------------------------------------------

    Provisioning становится:
        единым архитектурным слоем,
        который управляет всей сборкой сайта.

--------------------------------------------------
КЛЮЧЕВАЯ МЕНТАЛЬНАЯ МОДЕЛЬ
--------------------------------------------------

Если:

    Foundation = что возможно
    Composition = как устроено
    Configuration = что выбрано
    Content = чем заполнено
    Runtime = как выполняется

то Provisioning =
    как всё это собирается в первый раз

--------------------------------------------------
КЛЮЧЕВОЙ ВЫВОД
--------------------------------------------------

    Provisioning Data — это orchestration layer установки системы,
    
    который описывает:
        как из всех архитектурных слоёв
        собрать полностью готовый сайт
        из пустого состояния.
