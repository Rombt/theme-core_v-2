==================================================
RUNTIME DATA
==================================================

    Runtime Data — это временное состояние системы во время её выполнения.

    Проще говоря:

        Runtime — это всё, что существует только “в момент работы сайта”.

        Как только выполнение заканчивается — Runtime исчезает.

--------------------------------------------------
ГЛАВНАЯ ИДЕЯ RUNTIME DATA
--------------------------------------------------

Runtime отвечает на вопрос:

    "Что происходит прямо сейчас в процессе рендеринга и выполнения системы?"

    Runtime — это не структура.
    Runtime — это не конфигурация.
    Runtime — это не контент.

    Runtime — это состояние процесса.

--------------------------------------------------
ОЧЕНЬ ВАЖНОЕ РАЗДЕЛЕНИЕ
--------------------------------------------------

    В theme-core v-2:  Runtime ≠ Source of Truth

    Runtime — это результат работы системы, а не её исходные данные.

--------------------------------------------------
ПРОСТАЯ АНАЛОГИЯ
--------------------------------------------------

    Если представить сайт как кино:
        Foundation = правила съёмки
        Composition = сценарий сцены
        Configuration = выбор версии фильма
        Content = актёры и диалоги

    то Runtime — это: сам процесс проигрывания фильма

--------------------------------------------------
ПРОСТОЙ ПРИМЕР
--------------------------------------------------

    Composition говорит:
        Homepage:
            Hero
            Features

    Configuration говорит:
        use dark hero variant

    Content говорит:
        title = "AI Platform"

    Runtime — это момент, когда:
        Hero уже выбран
        данные уже подставлены
        renderer уже активен
        система уже вычислила layout
        и всё это сейчас отображается пользователю

--------------------------------------------------
ЧТО ИМЕННО ВХОДИТ В RUNTIME DATA
--------------------------------------------------

    1. RENDERING CONTEXT
    --------------------------------------------------

        Например:
            current page = homepage
            current section = Hero
            current renderer = HeroRenderer

    --------------------------------------------------
    2. RESOLVED STRUCTURE
    --------------------------------------------------

        Composition превращается в:
            фактическое дерево рендеринга с разрешенными компонентами и примененной конфигурацией

    --------------------------------------------------
    3. ACTIVE STATE
    --------------------------------------------------

        Например:
            hover state
            active tab
            opened modal
            expanded menu

    --------------------------------------------------
    4. UI STATE
    --------------------------------------------------

        Например:
            loading state
            error state
            success state

    --------------------------------------------------
    5. RESPONSIVE STATE
    --------------------------------------------------

        Например:
            viewport = mobile
            breakpoint = tablet

    --------------------------------------------------
    6. INTERACTION STATE
    --------------------------------------------------

        Например:
            clicked button
            opened dropdown
            scrolled position

    --------------------------------------------------
    7. COMPUTED DATA
    --------------------------------------------------

        Например:
            calculated layout sizes
            resolved spacing values
            computed styles
            merged configuration results

    --------------------------------------------------
    8. CACHE STATE
    --------------------------------------------------

        Например:
            cached composition tree
            cached renderer output
            memoized section data

    --------------------------------------------------
    9. HYDRATION STATE
    --------------------------------------------------

        Например:
            server-rendered HTML
            → client hydration status

--------------------------------------------------
ЧТО RUNTIME DATA НЕ СОДЕРЖИТ
--------------------------------------------------

    Runtime НЕ содержит:
        original composition definitions
        design tokens
        system schemas
        content storage

    Это все source layers.

--------------------------------------------------
ВАЖНОЕ РАЗДЕЛЕНИЕ
--------------------------------------------------

    Source layers:
        Foundation
        Composition
        Configuration
        Content

    Runtime layer:
        execution result of all above

--------------------------------------------------
ПРОСТОЙ ПРИМЕР ПЕРЕХОДА
--------------------------------------------------

    FOUNDATION:
        HeroSection supports title

    COMPOSITION:
        Homepage: Hero

    CONFIGURATION:
        hero = dark variant

    CONTENT:
        title = "Modern Platform"

    RUNTIME:
        HeroRenderer is executing
            → selects dark variant
            → applies layout rules
            → injects title
            → computes final DOM
            → renders HTML

--------------------------------------------------
ПОЧЕМУ RUNTIME ВАЖЕН
--------------------------------------------------

    Runtime нужен потому что: система не является статичной

    Есть:
        пользовательские действия
        динамическое поведение
        адаптивные изменения
        асинхронные данные
        client-side interactions

--------------------------------------------------
RUNTIME И WORDPRESS
--------------------------------------------------

    В WordPress:
        Runtime скрыт внутри:
            PHP execution
            WP loop
            hooks execution
            template rendering
        Но он не выделен как отдельный архитектурный слой.

--------------------------------------------------
theme-core v-2 подход
--------------------------------------------------

    Runtime становится явным слоем, чтобы:
        контролировать rendering process
        отслеживать state changes
        управлять hydration
        оптимизировать rendering
        поддерживать multi-renderer architecture

--------------------------------------------------
КЛЮЧЕВАЯ МЕНТАЛЬНАЯ МОДЕЛЬ
--------------------------------------------------

    Если:
        Foundation = что возможно
        Composition = как устроено
        Configuration = что выбрано
        Content = чем заполнено

    то Runtime = как это всё сейчас выполняется

--------------------------------------------------
ЕЩЁ ПРОЩЕ
--------------------------------------------------

    Runtime — это “живой момент системы”.

--------------------------------------------------
КЛЮЧЕВОЙ ВЫВОД
--------------------------------------------------

    Runtime Data — это временный execution layer, 
        который существует только во время работы системы и отражает:
            текущее состояние рендеринга,
            пользовательские взаимодействия
            и вычисленные результаты всех других слоёв.
