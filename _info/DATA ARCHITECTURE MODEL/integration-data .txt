==================================================
INTEGRATION DATA
==================================================

    Integration Data — это слой данных, который отвечает за связь
        между theme-core v-2 и 
        внешними системами.

    Проще говоря:
        Integration — это “переводчик” между архитектурой theme-core и 
            другими платформами, плагинами или ecosystem tools.

--------------------------------------------------
ГЛАВНАЯ ИДЕЯ INTEGRATION DATA
--------------------------------------------------

    Integration отвечает на вопрос:
        "Как theme-core взаимодействует с внешними системами?"

--------------------------------------------------
ОЧЕНЬ ВАЖНОЕ ПОНИМАНИЕ
--------------------------------------------------

    theme-core v-2 — это самостоятельная архитектурная система.

    Но она существует внутри WordPress ecosystem, где уже есть:
        WooCommerce
        Gutenberg
        Elementor
        ACF
        WPML
        SEO plugins
        third-party systems

    Integration layer нужен для того, чтобы:
        связать всё это между собой, не разрушая core architecture.

--------------------------------------------------
ПРОСТАЯ АНАЛОГИЯ
--------------------------------------------------

    Если theme-core — это собственный язык архитектуры,
        то Integration — это система переводчиков для общения с другими языками.

--------------------------------------------------
ПРОСТОЙ ПРИМЕР
--------------------------------------------------

    Допустим, внутри theme-core существует: HeroSection

    Но Elementor работает через: Elementor widgets

    Нужен adapter, который скажет:
        HeroSection ↔ ElementorWidget

    Вот это и есть integration layer.

--------------------------------------------------
ЧТО ИМЕННО ВХОДИТ В INTEGRATION DATA
--------------------------------------------------

    --------------------------------------------------
    1. EXTERNAL MAPPINGS
    --------------------------------------------------

        Например:
            HeroSection
                maps to: ElementorHeroWidget
                или: ProductGridSection maps to: WooCommerceProductLoop

    --------------------------------------------------
    2. ADAPTER CONFIGURATIONS
    --------------------------------------------------

        Например:
            WooCommerceAdapter: enable product bindings enable cart integration

    --------------------------------------------------
    3. FIELD BINDINGS
    --------------------------------------------------

        Например:
            HeroSection.title ↔ ACF field: hero_title

    --------------------------------------------------
    4. EXTERNAL DATA CONNECTIONS
    --------------------------------------------------

        Например:
            ProductSection uses: WooCommerce products

    --------------------------------------------------
    5. COMPATIBILITY RULES
    --------------------------------------------------

        Например:
            if Elementor active: enable ElementorRenderer

    --------------------------------------------------
    6. GUTENBERG BINDINGS
    --------------------------------------------------

        Например:
            HeroSection ↔ Gutenberg block

    --------------------------------------------------
    7. MULTILINGUAL INTEGRATIONS
    --------------------------------------------------

        Например: WPML integration Polylang bindings

    --------------------------------------------------
    8. SEO INTEGRATIONS
    --------------------------------------------------

        Например: Yoast mappings RankMath metadata bindings

--------------------------------------------------
ЧТО ВАЖНО ПОНЯТЬ
--------------------------------------------------

    Integration Data — не изменяют core architecture.
        Они: только создают bridge между системами.

--------------------------------------------------
ПОЧЕМУ ЭТО КРИТИЧЕСКИ ВАЖНО
--------------------------------------------------

    Без отдельного Integration layer:
        WooCommerce logic
        Elementor logic
        Gutenberg logic

    начнут проникать в core architecture.

    В результате:
        sections станут зависимыми
        rendering станет platform-specific
        architecture станет загрязнённой

--------------------------------------------------
INTEGRATION LAYER ИЗОЛИРУЕТ ЭТУ ПРОБЛЕМУ
--------------------------------------------------

    Core architecture остаётся:
        clean
        reusable
        renderer-independent

    А вся platform-specific логика изолируется внутри integrations.

--------------------------------------------------
ПРОСТОЙ ПРИМЕР
--------------------------------------------------

    ПЛОХО: HeroSection напрямую зависит от Elementor API

--------------------------------------------------

    ХОРОШО: HeroSection ↔ Integration Adapter ↔ Elementor

--------------------------------------------------
INTEGRATION И RENDERING
--------------------------------------------------

    Иногда integration влияет на rendering.

    Например:
        GutenbergRenderer
        ElementorRenderer
        WooCommerceRenderer

    Но:
        renderer implementation всё равно остаётся частью runtime/rendering architecture.

    Integration только связывает системы.

--------------------------------------------------
INTEGRATION И CONTENT
--------------------------------------------------

    Integration может получать content из внешних источников.

    Например:
        WooCommerce products
        ACF fields
        external APIs

    Но сам Content layer остаётся независимым.

--------------------------------------------------
INTEGRATION И REGISTRY
--------------------------------------------------

    Integrations обычно: регистрируются через Registry System.

    Например:
        register_integration(
            WooCommerceAdapter
        )

--------------------------------------------------
INTEGRATION И WORDPRESS
--------------------------------------------------

    WordPress ecosystem полностью построен на integrations.

    Но обычно integrations: хаотично смешиваются с core theme logic.

--------------------------------------------------
theme-core v-2 подход
--------------------------------------------------

    Все external dependencies изолируются в отдельном architectural layer.

--------------------------------------------------
ЧТО ЭТО ДАЁТ
--------------------------------------------------

    Это позволяет:

        менять integrations
        отключать integrations
        поддерживать multiple builders
        сохранять чистую architecture
        не загрязнять core

--------------------------------------------------
ПРОСТАЯ МЕНТАЛЬНАЯ МОДЕЛЬ
--------------------------------------------------

    Если:
        Foundation = architectural rules
        Composition = structural assembly
        Configuration = active choices
        Runtime = execution engine

    то Integration = мост между theme-core и внешними системами.

--------------------------------------------------
ЕЩЁ ПРОЩЕ
--------------------------------------------------

    Integration — это слой совместимости.

--------------------------------------------------
КЛЮЧЕВОЙ ВЫВОД
--------------------------------------------------

    Integration Data — это изолированный adapter layer,
        который обеспечивает взаимодействие между theme-core v-2 и
            внешними платформами,
            plugins,
            ecosystem services,
        не загрязняя core architecture системы.
