==================================================
CONTENT DATA
==================================================

    Content Data — это все данные, которые наполняют сайт реальной информацией.

    Проще говоря: Content — это то, что пользователь в итоге видит, читает, смотрит или с чем взаимодействует на сайте.

--------------------------------------------------
ГЛАВНАЯ ИДЕЯ CONTENT DATA
--------------------------------------------------

    Content отвечает на вопрос:
        "Чем заполнена структура сайта?"

    Content — это не архитектура.

    Content — это наполнение архитектуры.

--------------------------------------------------
ОЧЕНЬ ВАЖНОЕ ПОНИМАНИЕ
--------------------------------------------------

    В theme-core v-2: Content ≠ Site

    Это фундаментальный architectural shift.

--------------------------------------------------
СТАРЫЙ WORDPRESS MINDSET
--------------------------------------------------

    Обычно WordPress мыслит так: content = сайт

    Есть:
        страницы
        posts
        изображения

    и вокруг них строится вся система.

--------------------------------------------------
theme-core v-2 mindset
--------------------------------------------------

    В theme-core v-2:
        сайт определяется:
            composition
            configuration
            foundation architecture

    А Content — только заполняет уже существующую систему.

--------------------------------------------------
ПРОСТОЙ ПРИМЕР
--------------------------------------------------

    Composition говорит:
        Homepage:
            Hero
            Features
            CTA

    Foundation говорит:
        HeroSection accepts:
            title
            subtitle
            image

    Content говорит:
        title = "Modern AI Platform"
        subtitle = "Composable architecture for WordPress"

--------------------------------------------------

--------------------------------------------------
ЧТО ВАЖНО ПОНЯТЬ
--------------------------------------------------

    Content — это instance-level data.

--------------------------------------------------
ПРИМЕР
--------------------------------------------------

    Foundation:
        HeroSection supports title

    Content:
        title = "AI Website Builder"

--------------------------------------------------
ЕЩЁ ОДИН ПРИМЕР
--------------------------------------------------

    Foundation:
        PricingSection supports plans

    Content:
        plan_1:
            title = "Starter"
            price = "$19"

--------------------------------------------------
CONTENT НЕ СОДЕРЖИТ
--------------------------------------------------

    Content НЕ содержит:
        layout structure
        section hierarchy
        page composition

    Это Composition Data.

--------------------------------------------------

    Content НЕ содержит:
        design tokens
        typography systems
        spacing rules

    Это Foundation Data.

--------------------------------------------------

    Content НЕ содержит:
        renderer selection
        active presets
        feature toggles

    Это Configuration Data.

--------------------------------------------------

    Content НЕ содержит:
        runtime state
        cache
        rendering context

    Это Runtime Data.

--------------------------------------------------
ВАЖНОЕ АРХИТЕКТУРНОЕ РАЗДЕЛЕНИЕ
--------------------------------------------------

    Composition отвечает:
        где расположен блок.

    Foundation отвечает:
        какие данные блок умеет принимать.

    Content отвечает:
        какими именно значениями заполнен блок.

--------------------------------------------------
ПРИМЕР ПОЛНОГО РАЗДЕЛЕНИЯ
--------------------------------------------------

    FOUNDATION:
        HeroSection supports:
            title
            subtitle
            image

    COMPOSITION:
        Homepage:
            Header
            Hero
            CTA

    CONFIGURATION:
        active hero preset:
            dark

    CONTENT:
        title:
            "Build Modern WordPress Sites"
        subtitle:
            "Composable architecture platform"
        image:
            hero-image.jpg

    RUNTIME:
        renderer generates final output

--------------------------------------------------
ПОЧЕМУ CONTENT ДОЛЖЕН ОСТАВАТЬСЯ WORDPRESS-NATIVE
--------------------------------------------------

    Это очень важная часть philosophy проекта.

    theme-core v-2
        не пытается заменить WordPress CMS.

--------------------------------------------------
ИДЕЯ ТАКАЯ
--------------------------------------------------

    WordPress уже умеет:
        хранить контент
        управлять медиа
        работать с posts
        работать с products
        управлять taxonomy
        обеспечивать editing workflows

    Нет смысла:
        строить собственную CMS поверх CMS.

--------------------------------------------------
ПОЭТОМУ CONTENT DATA ДОЛЖНЫ
--------------------------------------------------

    использовать WordPress ecosystem
    использовать WordPress workflows
    использовать WordPress storage model

--------------------------------------------------
ЧТО ЭТО ДАЁТ
--------------------------------------------------

    Это позволяет:

        сохранить совместимость
        использовать WP plugins
        использовать WooCommerce
        использовать Gutenberg
        использовать existing content pipelines

--------------------------------------------------
КЛЮЧЕВАЯ МЕНТАЛЬНАЯ МОДЕЛЬ
--------------------------------------------------

    Если Foundation — это строительные правила,

    Composition — это structural схема,

    Configuration — это assembly decisions,

    Content — это материалы, которыми заполняется готовая структура.

--------------------------------------------------
КЛЮЧЕВОЙ ВЫВОД
--------------------------------------------------

Content Data — это пользовательское и business-level наполнение сайта.

Content не определяет:
    архитектуру,
    структуру
    или rendering.

Content только заполняет уже существующую architectural system реальными данными.
