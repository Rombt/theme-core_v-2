==================================================
REGISTRY SYSTEM
==================================================

    Registry System — это центральная система регистрации
        и обнаружения архитектурных возможностей theme-core v-2.

    Проще говоря:
        Registry — это “единый каталог системы”.

    Именно Registry сообщает системе какие
        sections существуют
        layouts доступны
        renderers можно использовать
        integrations подключены
        presets зарегистрированы

--------------------------------------------------
ГЛАВНАЯ ИДЕЯ REGISTRY
--------------------------------------------------

    Registry отвечает на вопрос:
        "Что вообще доступно системе  и как это можно найти?"

--------------------------------------------------
ПРОСТАЯ АНАЛОГИЯ
--------------------------------------------------

    Если представить theme-core v-2 как операционную систему, то Registry — это что-то вроде:
        system directory
        package registry
        service container

--------------------------------------------------
ЕЩЁ ПРОЩЕ
--------------------------------------------------

    Допустим, в системе есть:
        HeroSection
        PricingSection
        FAQSection

    Как система узнает, что они вообще существуют?
        Через Registry.

--------------------------------------------------
БЕЗ REGISTRY
--------------------------------------------------

    Система не знает какие
        components доступны
        renderers существуют
        integrations подключены
        layouts можно использовать

    Всё пришлось бы: жёстко прописывать вручную.

--------------------------------------------------
REGISTRY РЕШАЕТ ЭТУ ПРОБЛЕМУ
--------------------------------------------------

Registry создаёт: централизованный discovery layer.

--------------------------------------------------
ЧТО ИМЕННО РЕГИСТРИРУЕТСЯ
--------------------------------------------------

    1. SECTIONS
    --------------------------------------------------

        Например:
            HeroSection
            CTASection
            PricingSection
            BlogGridSection

    2. LAYOUTS
    --------------------------------------------------

        Например:
            TwoColumnLayout
            SidebarLayout
            LandingLayout

    3. RENDERERS
    --------------------------------------------------

        Например:
            HeroRenderer
            GridRenderer
            MasonryRenderer

    4. DESIGN PRESETS
    --------------------------------------------------

        Например:
            dark-modern
            startup-light
            editorial-clean

    5. COMPOSITION TYPES
    --------------------------------------------------

        Например:
            homepage-composition
            product-page-composition
            blog-layout-composition

    6. INTEGRATIONS
    --------------------------------------------------

        Например:
            WooCommerceAdapter
            ElementorAdapter
            GutenbergAdapter

    7. CAPABILITIES
    --------------------------------------------------

        Например:
            supports-animation
            supports-dark-mode
            supports-responsive-grid

--------------------------------------------------
КАК ЭТО ВЫГЛЯДИТ КОНЦЕПТУАЛЬНО
--------------------------------------------------

    Например:
        register_section(
            id: hero,
            schema: HeroSchema,
            renderer: HeroRenderer
        )

    или:
        register_layout(
            id: two-column,
            slots:
                sidebar
                content
        )

--------------------------------------------------
ПОЧЕМУ ЭТО ОЧЕНЬ ВАЖНО
--------------------------------------------------

    Без Registry архитектура становится:

        жёсткой
        плохо расширяемой
        tightly coupled

--------------------------------------------------
С REGISTRY
--------------------------------------------------

    Система становится:
        extensible
        discoverable
        plugin-friendly
        composable

--------------------------------------------------
ПРОСТОЙ ПРИМЕР РАСШИРЕНИЯ
--------------------------------------------------

    Допустим, ты создаёшь новый модуль:
        AdvancedTestimonials

    Модуль просто делает:
        register_section(
            testimonials-advanced
        )

    И система автоматически: начинает видеть новый section.

--------------------------------------------------
БЕЗ НЕОБХОДИМОСТИ
--------------------------------------------------

    менять core
    переписывать templates
    редактировать routing
    менять renderer engine

--------------------------------------------------
REGISTRY И PLUGIN ARCHITECTURE
--------------------------------------------------

    Registry — это основа plugin-oriented architecture.

    Потому что: любые extensions могут регистрировать себя внутри системы.

--------------------------------------------------
ВАЖНОЕ ПОНИМАНИЕ
--------------------------------------------------

    Registry — это НЕ storage layer.

    Registry — это НЕ content database.

    Registry — это НЕ runtime cache.

    Registry — это architectural discovery mechanism.

--------------------------------------------------
REGISTRY И FOUNDATION
--------------------------------------------------

    Foundation определяет: architectural rules.

    Registry определяет:
        какие конкретные реализации зарегистрированы внутри системы.

--------------------------------------------------
ПРИМЕР
--------------------------------------------------

FOUNDATION:
    Section must support schema

REGISTRY:
    HeroSection registered
    PricingSection registered

--------------------------------------------------
REGISTRY И COMPOSITION
--------------------------------------------------

    Composition может ссылаться только на то, что зарегистрировано в Registry.

    Например:
        Homepage:
            Hero
            CTA

    Во время выполнения система проверяет зарегистрированы ли:
        Hero
        CTA

--------------------------------------------------
REGISTRY И RUNTIME
--------------------------------------------------

    Во время runtime:
        renderer engine
        composition resolver
        provisioning system

    все используют Registry для поиска нужных system parts.

--------------------------------------------------
REGISTRY И WORDPRESS
--------------------------------------------------

    В WordPress похожие идеи существуют:

        register_post_type()
        register_taxonomy()
        add_theme_support()

    Но:
        они ограничены WP API.

--------------------------------------------------
theme-core v-2 подход
--------------------------------------------------

    Registry становится: полноценным architectural coordination layer.

--------------------------------------------------
КЛЮЧЕВАЯ МЕНТАЛЬНАЯ МОДЕЛЬ
--------------------------------------------------

    Если Foundation — это архитектурные правила,

    то Registry — это список всего, что реально доступно системе в рамках этих правил.

--------------------------------------------------
ЕЩЁ ПРОЩЕ
--------------------------------------------------

    Foundation говорит:
        "Section может существовать"

    Registry говорит:
        "Вот конкретные sections, которые сейчас доступны"

--------------------------------------------------
КЛЮЧЕВОЙ ВЫВОД
--------------------------------------------------

    Registry System — это централизованная система
        регистрации,
        обнаружения
        и координации
    всех архитектурных возможностей  theme-core v-2.

    Registry делает систему:
        расширяемой,
        модульной,
        composable
        и plugin-friendly.
