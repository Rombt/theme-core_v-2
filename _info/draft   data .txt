==================================================
1. CONFIGURATION DATA
==================================================

Главный тип данных системы.

    Это: описание того, как должен быть собран сайт.

    Примеры
        - страницы сайта
        - дерево композиции
        - размещение секций
        - назначения компоновки
        - сопоставления рендерера
        - предустановленные выделения
        - настройки дизайна

--------------------------------------------------
Особенности
--------------------------------------------------

    - декларативный
    - детерминированный
    - сериализуемый
    - многократно используемый
    - версионируемый

--------------------------------------------------
Ключевая идея
--------------------------------------------------

Данные конфигурации — это основной источник правды для приложения.


==================================================
2. DESIGN SYSTEM DATA
==================================================

Данные visual architecture.

    Примеры
        - дизайн-токены
        - типографические шкалы
        - правила межстрочного интервала
        - цветовые палитры
        - адаптивные контрольные точки
        - правила компоновки

    Особенности
        - централизованный
        - многоразовый
        - глобально общий
        - независимый от рендерера

    Ключевая идея

        Design Data не должны зависеть:
        - от страниц
        - от секций
        - от renderers


==================================================
3. COMPOSITION DATA
==================================================

Структурные данные сайта.

    Примеры
        - дерево композиции
        - иерархия разделов
        - размещение регионов
        - назначение слотов
        - структура компоновки

    Особенности
        - структурный
        - иерархический
        - многоразовый
        - независимый от рендерера

Ключевая идея
    Composition — это отдельный слой данных, не HTML.


==================================================
4. CONTENT DATA
==================================================

Пользовательский контент.

    Примеры
        - тексты
        - изображения
        - products
        - posts
        - metadata

    Особенности
        - dynamic
        - user-managed
        - WordPress-native

    Ключевая идея
        Content Data должны 
            оставаться внутри WordPress ecosystem 
            базироваться на WordPress ecosystem
            использовать WordPress ecosystem
        НЕ нужно строить свою CMS!!


==================================================
5. RENDERING DATA
==================================================

Данные runtime rendering.

    Примеры
        - контекст рендерера
        - параметры рендеринга
        - разрешенные сопоставления
        - состояние рендерера во время выполнения

    Особенности
        - временный
        - только во время выполнения
        - ориентированный на выполнение

    Ключевая идея
        Rendering Data — не configuration source.


==================================================
6. PROVISIONING DATA
==================================================

Данные site assembly.

    Примеры
        - демонстрационные предустановки
        - состояние настройки
        - манифесты подготовки
        - очереди сборки

    Особенности
        - процедурный
        - ориентированный на инициализацию
        - частично переходный

Ключевая идея
    Provisioning — это orchestration process, а не постоянное состояние сайта.


==================================================
7. REGISTRY DATA
==================================================

Системные registration definitions.

    Примеры
        - зарегистрированные разделы
        - зарегистрированные макеты
        - зарегистрированные средства рендеринга
        - зарегистрированные пресеты
        - зарегистрированные адаптеры

    Особенности
        - централизованный
        - обнаруживаемый
        - расширяемый

    Ключевая идея
        Registry — это механизм архитектурной координации.


==================================================
8. SYSTEM STATE DATA
==================================================

Runtime state системы.

    Примеры
        - активный контекст сайта
        - активный рендерер
        - кэш времени выполнения
        - состояние среды

    Особенности
        - temporary
        - mutable
        - execution-scoped

    Ключевая идея

        State ≠ Configuration.


==================================================
9. INTEGRATION DATA
==================================================

Данные внешних integrations.

    Примеры
        - Elementor mappings
        - WooCommerce bindings
        - Gutenberg bindings

    Особенности
        - adapter-scoped
        - isolated
        - integration-specific

    Ключевая идея
        Integration Data не должны заражать core architecture.


==================================================
10. ASSET DATA
==================================================

Данные asset system.

    Примеры
        - манифесты
        - карты ресурсов
        - результаты сборки
        - графы зависимостей

    Особенности
        - ориентированный на сборку
        - ориентированный на развертывание

    Ключевая идея
            Assets — это инфраструктурный уровень, а не composition layer.


==================================================
КЛЮЧЕВОЙ АРХИТЕКТУРНЫЙ ВЫВОД
==================================================

Для theme-core v-2
главный architectural shift такой:

--------------------------------------------------

WordPress mindset:

CONTENT = SITE

--------------------------------------------------

theme-core v-2 mindset:

CONFIGURATION + COMPOSITION + DESIGN = SITE

CONTENT только наполняет систему.
