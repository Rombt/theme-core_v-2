ARTIFACT OUTPUT TYPES AND FILE STRUCTURE
ARCHITECTURAL DESCRIPTION
(v1.0.0)

Status: Architectural Foundation

==================================================
1. PURPOSE
==================================================

   Данный документ фиксирует архитектурное решение
   по классификации элементов Theme Configuration
   для определения структуры результирующих файлов
   генерируемой WordPress Theme.

   Решение предназначено прежде всего для
   Classic Theme Architecture.

   Основная цель:

    отделить семантическую классификацию элементов
    от физического пути результирующего файла

    обеспечить автоматическое определение
    директории Artifact

    сохранить конфигурацию независимой
    от конкретной файловой структуры темы

    обеспечить масштабирование конфигурационного
    пакета без необходимости вручную указывать
    пути сохранения каждого элемента.

==================================================
2. CORE PRINCIPLE
==================================================

    Поле type конфигурационного элемента
    используется как семантический классификатор.

    type определяет роль элемента
    в результирующей теме.

    type НЕ определяет физический путь файла.

    Физическое расположение Artifact определяется
    Artifacts Layer на основании типа элемента
    и его архитектуры.

    Таким образом:

        Theme Configuration
            ↓
        semantic type
            ↓
        ThemeIR
            ↓
        Architecture-specific Artifacts
            ↓
        output file structure


    Конфигурация не должна содержать
физические пути результирующих файлов.

==================================================
3. TYPE
==================================================

    type — закрытая семантическая классификация Node
        по его основной предметной и структурной роли.
    
    Выбор производится по наиболее специфичной семантике.

    Для классификации элементов принимается
    минимальный набор из восьми типов:

        template
        layout
        post
        page
        product
        navigation
        form
        common

    Набор типов является закрытым.

    Набор типов является минимальным
        и не должен расширяться без необходимости.

    Новый тип вводится только в случае,
    если существующие типы не позволяют
    однозначно классифицировать новый элемент
    и определить его место в структуре темы.

==================================================
4. TYPE: TEMPLATE
==================================================

    template обозначает основной шаблон WordPress Theme.

    Такие элементы материализуются в корне темы.

    Примеры:

        index.php
        single.php
        page.php
        category.php
        tag.php
        archive.php
        404.php

==================================================
5. TYPE: LAYOUT
==================================================

    layout обозначает крупную структурную часть страницы или шаблона.

    Для Classic Theme элементы данного типа материализуются внутри:

        template-parts/layout/


    Примеры:

        layout
        hero
        section
        grid

==================================================
6. TYPE: POST
==================================================

    post обозначает элементы,
        предназначенные для представления записи
        или работы с её содержимым.

    Для Classic Theme элементы данного типа материализуются внутри:

        template-parts/post/


    Примеры:

        post-loop
        post-title
        post-content
        post-card
        post-meta

==================================================
7. TYPE: PAGE
==================================================

    page обозначает элементы,
    специфичные для представления страницы.

    Для Classic Theme элементы данного типа
    материализуются внутри:

        template-parts/page/


    Примеры:

        page-title
        page-content

==================================================
8. TYPE: PRODUCT
==================================================

    product обозначает элементы,
    относящиеся к представлению товара
    и функциональности e-commerce.

    Для Classic Theme элементы данного типа материализуются внутри:

        template-parts/product/


    Примеры:

        product-card
        product-price
        product-gallery


    Тип product вводится с учётом перспективы
        поддержки WooCommerce и других
        e-commerce сценариев.

==================================================
9. TYPE: NAVIGATION
==================================================

    navigation обозначает элементы,
    предназначенные для навигации сайта.

    Для Classic Theme элементы данного типа материализуются внутри:

        template-parts/navigation/


    Примеры:

        primary-navigation
        footer-navigation
        mobile-navigation

==================================================
10. TYPE: FORM
==================================================

    form обозначает элементы, относящиеся к формам и их составным элементам.

    Для Classic Theme элементы данного типа
    материализуются внутри:

        template-parts/forms/


    Тип form включает, в частности:

        form
        input
        textarea
        select
        checkbox
        radio
        button


    Отдельные типы input, button, textarea
    и другие разновидности элементов формы
    не создаются.

==================================================
11. TYPE: COMMON
==================================================

    common обозначает универсальные элементы,
        которые не относятся однозначно
        к специализированному домену.

    Для Classic Theme элементы данного типа материализуются внутри:

        template-parts/common/


    Примеры:

        no-posts
        pagination
        separator


    Тип common используется только тогда,
        когда элемент действительно не имеет
        более конкретной семантической принадлежности.

===================================================
12. SPECIAL WORDPRESS FILES
===================================================

    Некоторые элементы Classic Theme
        имеют специальные стандартные файлы WordPress.

    К ним относятся:

        header.php
        footer.php
        sidebar.php


    Их расположение определяется
        специальной семантикой Artifacts, а не отдельными типами.

    Создание типов:

        header
        footer
        sidebar

    не требуется.

==================================================
13. NODE AND TYPE
==================================================

    Node содержит type, который описывает семантическую роль Node.

    Пример:

        post_title_01

            type:
                post

    type не должен содержать:

        имя директории
        имя файла
        расширение файла
        абсолютный путь
        относительный путь


    Таким образом Node остаётся частью декларативной модели Theme Configuration.

==================================================
14. COMPOSITION AND TYPE
==================================================

    Каждая Composition должна иметь поле type.

    type Composition определяется в соответствии с её семантической ролью
        в результирующей теме.

    Composition использует тот же утверждённый набор типов, что и Node.



    Таким образом Node и Composition используют
        единую систему семантической классификации типов.

    Различие между Node и Composition определяется их структурной ролью:
        Node
            атомарный элемент

        Composition
            составной элемент

    Поле type не содержит физический путь результирующего файла.

    Физическое расположение определяется
        Artifacts Layer на основании type
        и правил конкретной архитектуры.

==================================================
15. RELATION TO RENDERING
==================================================

    type и rendering имеют разные значения.

    type отвечает на вопрос:

        "К какой семантической категории относится элемент?"

    rendering отвечает на вопрос:

        "Как элемент должен быть материализован в рамках текущей архитектуры?"


    Пример:

        type:
            post

        rendering:
            template-part


    Эти два свойства не являются взаимозаменяемыми.

==================================================
16. ARCHITECTURE DEPENDENCY
==================================================

    Правила преобразования type
        в физическую файловую структуру
        принадлежат Artifacts Layer.

    Поэтому одна и та же семантическая классификация
        может материализоваться по-разному в разных архитектурах.

    Например:

        Classic Theme

            post
                ↓
            template-parts/post/


    Block Theme может иметь другую структуру материализации.


    Theme Configuration при этом не изменяется.

==================================================
17. CURRENT CLASSIC OUTPUT STRUCTURE
==================================================

    Базовая структура Classic Theme:

        theme/
        │
        ├── style.css
        ├── functions.php
        │
        ├── index.php
        ├── single.php
        ├── page.php
        ├── category.php
        ├── tag.php
        ├── archive.php
        ├── 404.php
        ├── header.php
        ├── footer.php
        └── sidebar.php
        │
        └── template-parts/
            │
            ├── layout/
            │
            ├── post/
            │
            ├── page/
            │
            ├── product/
            │
            ├── navigation/
            │
            ├── forms/
            │
            └── common/


    Конкретные файлы внутри этих каталогов определяются Artifacts Layer.

==================================================
18. ARTIFACT FILENAME
==================================================

    Имя Artifact определяется Artifacts Layer
        на основании семантики Node или Composition
        и правил соответствующей архитектуры.


    Для файлов, имеющих стандартное назначение
        в WordPress Template Hierarchy,
        используются стандартные имена WordPress.

    Примеры:

        index.php
        single.php
        page.php
        archive.php
        category.php
        tag.php
        404.php
        header.php
        footer.php
        sidebar.php


    Для пользовательских файлов темы
        используются имена, соответствующие
        WordPress и Envato требованиям:

            только lowercase
            слова разделяются дефисами
            camelCase и underscore не используются


    Имя исходного Node или Composition
        не обязано напрямую определять имя Artifact.

    Artifacts Layer может преобразовать
        внутренний идентификатор элемента
        в подходящее имя файла.


        Примеры:

            post_title_01
                ↓
            post-title-01.php


            post_loop_01
                ↓
            post-loop-01.php


            page_content_01
                ↓
            page-content-01.php


    Имя Artifact не должно содержать внутренние соглашения конфигурационного пакета,
        если они не являются частью семантического имени результирующего элемента.


    Расширение файла определяется соответствующей архитектурой:

        Classic Theme
            → .php

        Block Theme
            → .html

==================================================

    На текущем конфигурационном пакете:

        index
        single
        page
        category
        tag
            → template


        layout_01
            → layout


        post_loop_01

===================================================
19. ARCHITECTURAL CONSTRAINT
===================================================

    Конфигурационный пакет не должен
    описывать физические пути результирующих
    файлов темы.

    Пути должны определяться правилами
    соответствующей Artifacts Architecture.

    Добавление нового Node должно требовать
    только его семантической классификации,
    если для данного типа уже существует
    правило материализации.

    Добавление нового физического каталога
    должно происходить только при появлении
    новой семантической категории,
    которую невозможно корректно разместить
    в существующих типах.

==================================================
20. UNKNOWN TYPE
==================================================

    type является закрытым набором.

    Допустимые значения:

        template
        layout
        post
        page
        product
        navigation
        form
        common


    Если Node или Composition содержит неизвестный type:

        диагностируется ERROR
            Artifact для данного элемента не создаётся
            обработка остальных элементов продолжается
            выполнение Build в целом не прерывается


    Неизвестный type не должен автоматически преобразовываться в common
        или любой другой допустимый type.


    Ошибка Unknown Type учитывается  в итоговом Build Status.


    Отсутствующий type и неизвестный type  рассматриваются как ошибочные состояния.

    Node или Composition без type
        не должен получать Artifact
        до устранения ошибки конфигурации.


==================================================
21. STATUS
==================================================

    Решение принято как архитектурная основа для дальнейшей реализации структуры
        Classic Theme Artifacts.

    Набор типов:

        template
        layout
        post
        page
        product
        navigation
        form
        common

    считается текущим минимальным набором
        и может быть пересмотрен при появлении
        новых требований.
