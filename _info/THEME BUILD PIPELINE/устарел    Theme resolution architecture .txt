THEME-CORE V-2
RESOLUTION ARCHITECTURE
(v1.0.0)

Status: Research

==================================================
1. PURPOSE
==================================================

    Resolution является второй архитектурной стадией Build Pipeline.

    Её единственная ответственность — преобразование декларативной модели Theme Components
        во внутреннюю модель компилятора Theme IR.

    Resolution не выполняет загрузку конфигурации.
    Resolution не генерирует артефакты.
    Resolution не записывает файлы.
    Resolution является исключительно стадией преобразования архитектурной модели.

==================================================
2. POSITION IN PIPELINE
==================================================

    Pipeline имеет следующий вид:

        Theme Configuration
                ↓
        Theme Components
                ↓
            Resolution
                ↓
            Theme IR
                ↓
        Artifact Generation
                ↓
        Theme Artifacts
                ↓
        Artifact Writing
                ↓
        WordPress Theme

    Resolution работает исключительно с результатом стадии Loading.

    Следующая стадия работает исключительно с результатом Resolution.

==================================================
3. INPUT MODEL
==================================================

    Входом Resolution является: ThemeDefinition

    ThemeDefinition содержит:
        ThemeMetadata
        ThemeComponentCollection

    Resolution не получает:
        Configuration Domains
        Package
        ValidatedPackage
        PHP Configuration
        файловую систему

    Все сведения о конфигурации уже должны быть преобразованы
        в Theme Components во время Loading.

==================================================
4. OUTPUT MODEL
==================================================

    Результатом Resolution является: Theme IR

    Theme IR представляет собой внутреннюю модель компилятора.
        Theme IR не является конфигурацией.
        Theme IR не является декларативной моделью.

    Theme IR существует исключительно для генерации Theme Artifacts.

==================================================
5. CENTRAL RESPONSIBILITY
==================================================

    Resolution выполняет единственную задачу:
        построение Theme IR на основе Theme Components.

    Все остальные задачи находятся за пределами данной стадии.

==================================================
6. RESOLUTION MODEL
==================================================

    Архитектурная схема стадии:

        ThemeDefinition
                ↓
        ThemeComponentCollection
                ↓
        ThemeIrBuilder
                ↓
        ThemeIrResolverRegistry
                ↓
            ThemeIrResolver...
                ↓
            Theme IR

    ThemeIrBuilder координирует процесс построения Theme IR.

    ThemeIrBuilder не содержит логики преобразования отдельных компонентов.

    Преобразование выполняют специализированные Resolver.

==================================================
7. BUILDER
==================================================

ThemeIrBuilder является координатором стадии Resolution.

    Builder отвечает за:
        создание Theme IR
        запуск процесса Resolution
        передачу Theme IR Resolver'ам
        возврат готовой Theme IR

    Builder не знает:
        конкретные типы компонентов
        детали преобразования
        внутреннюю структуру отдельных частей Theme IR

==================================================
8. RESOLVERS
==================================================

    Каждый Resolver отвечает только за один архитектурный компонент.

        Например:
            AssetsResolver
            CompositionResolver
            EntityResolver
            QueryResolver
            DesignSystemResolver

    Каждый Resolver:
        получает Theme Components
        анализирует только собственные компоненты
        дополняет Theme IR
        Resolver не взаимодействует с другими Resolver.

==================================================
9. REGISTRY
==================================================

    ThemeIrResolverRegistry содержит зарегистрированные Resolver.

    Builder не знает, какие Resolver существуют.

    Builder работает только с Registry.

    Добавление нового Resolver не требует изменения Builder.

==================================================
10. BUILD PROCESS
==================================================

    Построение Theme IR выглядит следующим образом.

    Шаг 1
        создаётся пустая Theme IR.

    Шаг 2
        Builder получает список Resolver.

    Шаг 3
        каждый Resolver выполняет собственное преобразование.

    Шаг 4
        после завершения всех Resolver Theme IR считается полностью построенной.

==================================================
11. ARCHITECTURAL EXTENSIBILITY
==================================================

    Добавление нового архитектурного компонента должно состоять из следующих действий.
        создать новый Theme Component
        создать новый ThemeIrResolver
        зарегистрировать Resolver
        Builder при этом не изменяется.

    Таким образом Resolution
        соответствует принципу Open / Closed.

==================================================
12. FORBIDDEN DEPENDENCIES
==================================================

    Resolution запрещено зависеть от:
        Theme Configuration
        Configuration Domains
        Package
        ValidatedPackage
        файловой системы
        генераторов артефактов
        Writer
        WordPress

==================================================
13. FORBIDDEN OPERATIONS
==================================================

    Resolution запрещено:
        читать конфигурацию
        выполнять загрузку компонентов
        выполнять запись файлов
        генерировать артефакты
        выполнять toArray()
        использовать IrExportableInterface
        переносить массивы конфигурации в Theme IR

    Theme IR должна строиться
        как самостоятельная архитектурная модель,
        а не как агрегированная копия конфигурации.

==================================================
14. DESIGN PRINCIPLES
==================================================

    Resolution строится на следующих принципах.

    Каждая ответственность имеет собственный объект.

    Builder отвечает за координацию.

    Resolver отвечает за преобразование.

    Registry отвечает за расширяемость.

    Theme IR отвечает за внутреннее представление компилятора.

    Ни один объект не должен совмещать несколько архитектурных ролей.

==================================================
15. RESULT
==================================================

    После завершения Resolution Pipeline получает полностью построенную Theme IR.

    Дальнейшие стадии Build Pipeline не используют Theme Components.

    Генераторы артефактов работают исключительно с Theme IR.

    Таким образом Build Pipeline полностью соответствует архитектурной формуле:

        Theme Configuration
                ↓
        Theme Components
                ↓
            Theme IR
                ↓
        Theme Artifacts
                ↓
        WordPress Theme
