THEME-CORE V-2
АРХИТЕКТУРНАЯ МОДЕЛЬ КОНВЕЙЕРА КОМПИЛЯЦИИ
ThemeComponentCollection И ThemeIR
(v1.0.0)

МЕСТО В АРХИТЕКТУРЕ

ThemeCore реализует последовательный конвейер преобразования декларативного
    описания темы во внутреннюю модель, пригодную для генерации артефактов.

    Theme Specification
            ↓
        Loader
            ↓
    ThemeComponentCollection
            ↓
        Resolution
            ↓
         Theme IR
            ↓
        Artifact Generators
            ↓
        Generated Theme

ОБЩИЕ ПРИНЦИПЫ

    ThemeComponentCollection и Theme IR
        относятся к различным стадиям жизненного цикла данных.

    Они не конкурируют между собой.

    Каждая из моделей имеет собственную область ответственности
        и существует исключительно на своём этапе конвейера компиляции.

ThemeComponentCollection

    Назначение

        ThemeComponentCollection представляет собой результат работы Loader.

        Его задача заключается в объединении всех загруженных декларативных компонентов Theme Specification
            в единую структуру, пригодную для последующего Resolution.

    Источник данных
        Единственным источником данных является Theme Specification - конфигурационный пакет.
            - package.php
            - compositions.php
            - assets.php
            - integrations.php
            - другие декларативные каналы

    Область ответственности

        ThemeComponentCollection обязан:
            - хранить загруженные доменные конфигурации;
            - обеспечивать единый доступ к ним;
            - передавать их в Resolution.

    ThemeComponentCollection не должен:

        - выполнять преобразования;
        - разрешать зависимости;
        - выполнять нормализацию;
        - содержать вычисленные данные;
        - использоваться Artifact Generators.

    Архитектурный статус

        ThemeComponentCollection является инфраструктурной моделью стадии загрузки.

        Он не является частью фундаментального Intermediate Representation.

THEME IR

    Назначение
        Theme IR представляет собой результат работы Resolution.

    Он является фундаментальной внутренней моделью темы,
        полностью подготовленной для последующей генерации артефактов.

    Источник данных
        Единственным источником Theme IR является Resolution.

    Theme IR не может строиться напрямую из Theme Specification.

    Область ответственности

        Theme IR обязан:
            - содержать полностью разрешённую модель темы;
            - хранить результаты нормализации;
            - объединять все фундаментальные IR-домены;
            - быть единственным источником данных для Artifact Generators.

        Theme IR не должен:
            - содержать необработанные данные Theme Specification;
            - выполнять генерацию артефактов;
            - зависеть от Loader.

    Архитектурный статус
        Theme IR является центральной моделью архитектуры ThemeCore.

        Все Artifact Generators работают исключительно с Theme IR.

ВЗАИМОСВЯЗЬ

    ThemeComponentCollection является входной моделью Resolution.

    Theme IR является выходной моделью Resolution.

    Следовательно, ThemeComponentCollection и Theme IR представляют собой
        последовательные стадии преобразования одной и той же информации.

        Theme Specification
                ↓
        ThemeComponentCollection
                ↓
            Resolution
                ↓
            Theme IR

    КРИТЕРИЙ РАЗГРАНИЧЕНИЯ

        Простое правило определения принадлежности данных.

    Если данные полностью соответствуют Theme Specification
        и ещё не прошли Resolution, они относятся к ThemeComponentCollection.

    Если данные являются результатом детерминированного преобразования,
        выполненного Resolution, они относятся к Theme IR.

ИТОГОВЫЙ ВЫВОД

    ThemeComponentCollection и Theme IR не являются альтернативными моделями.

    ThemeComponentCollection представляет инфраструктурную модель стадии загрузки.
    Theme IR представляет фундаментальную внутреннюю модель ThemeCore, формируемую Resolution.

    Одновременное существование обеих сущностей является архитектурно оправданным
        и соответствует принятой модели компиляции ThemeCore.
