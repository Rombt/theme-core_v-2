FUNCTIONS SETUP DOMAIN ARCHITECTURE
ARCHITECTURAL DESCRIPTION
(v1.0.0)

Status: Architectural Foundation

==================================================
1. PURPOSE
==================================================

    Данный документ фиксирует архитектурные решения
        для корневого блока `setup` домена `Functions` в Configuration Package.

    Блок `setup` предназначен для декларативного описания базовой настройки темы.

    Реализация декларации определяется через Resource Architecture.

==================================================
2. ROOT SETUP DECLARATION
==================================================

    `setup` является корневой декларацией типа:

        type = setup

    Корневой блок `setup` обязательно содержит:

        type
        resource
        name

        Пример:

            'setup' => [
                'type' => 'setup',
                'resource' => 'theme_setup',
                'name' => 'Theme Setup',
            ]

==================================================
3. ROOT RESOURCE
==================================================

    Поле `resource` корневого блока `setup` является обязательным.

    Оно определяет Resource,
        отвечающий за реализацию setup-функциональности,
        если соответствующий подблок не определяет собственный Resource.

    Например:

        'resource' => 'theme_setup'

    определяет:

        theme_setup

==================================================
4. SETUP SUB-BLOCKS
==================================================

    Корневой `setup` может содержать произвольное количество
        семантических подблоков.

    Подблоки не образуют закрытый заранее определённый список.

    Пример:

        'setup' => [
            'type' => 'setup',
            'resource' => 'theme_setup',
            'name' => 'Theme Setup',

            'supports' => [...],
            'image_sizes' => [...],
            'textdomain' => 'blog-theme',
            'content_width' => 1200,
            'something' => [...],
        ]

    Core pipeline не должен требовать заранее знания
        каждого возможного подблока.

==================================================
5. SUB-BLOCK RESOURCE
==================================================

    Каждый подблок может иметь собственное поле:
        resource

    Если подблок содержит `resource`,
        для его реализации используется указанный Resource.

    Например:

        'supports' => [
            'resource' => 'theme_supports',

            ...
        ]

==================================================
6. RESOURCE INHERITANCE
==================================================

    Если подблок не содержит собственного `resource`,
        используется Resource корневого блока `setup`.

    Правило выбора Resource:

        sub-block.resource exists
            ↓
        use sub-block Resource


        sub-block.resource does not exist
            ↓
        use root setup Resource


    Таким образом, Resource корневого блока является
        Resource по умолчанию для его подблоков.

==================================================
7. RESOURCE ARCHITECTURE
==================================================

    Каждый Resource может иметь архитектурно-зависимые реализации.

    Например:

        theme_setup
            ├── classic
            └── block

        theme_supports
            ├── classic
            └── block

    Выбор архитектурной реализации выполняется
        на Artifacts Layer.

==================================================
8. RESPONSIBILITY OF ROOT RESOURCE
==================================================

    Корневой Resource `setup` отвечает за реализацию:
        корневой setup-декларации

    а также за те подблоки, которые не имеют собственного Resource.

    Например:

        setup
            resource = theme_setup

            image_sizes
            textdomain
            content_width

    означает:

        theme_setup
            ├── image_sizes
            ├── textdomain
            └── content_width

==================================================
9. RESPONSIBILITY OF SUB-BLOCK RESOURCE
==================================================

    Если подблок определяет собственный Resource,
        его реализация отделяется от корневого Resource.

    Например:

        setup
            resource = theme_setup

            supports
                resource = theme_supports

    означает:

        theme_setup
            └── остальные подблоки без собственного Resource

        theme_supports
            └── supports

==================================================
10. EXTENSIBILITY
==================================================

    Добавление нового подблока не должно требовать
        изменения core pipeline.

    Новый подблок может:
        использовать существующий Resource корневого `setup`

    либо:
        определить собственный Resource.

    Таким образом, расширение декларации `setup`
        не требует внесения нового поля во все слои приложения.

==================================================
11. STRUCTURAL PRINCIPLE
==================================================

    Декларация `setup` разделяется на:

        structural part
            type
            resource
            name

        semantic payload
            произвольные подблоки


    Core должен сохранять и передавать semantic payload,
        не требуя заранее знания всех его элементов.

==================================================
12. EXAMPLE
==================================================

    Пример декларации:

        'setup' => [
            'type' => 'setup',
            'resource' => 'theme_setup',
            'name' => 'Theme Setup',

            'supports' => [
                'resource' => 'theme_supports',

                'items' => [
                    'title-tag',
                    'post-thumbnails',
                    'custom-logo',
                ],
            ],

            'image_sizes' => [
                [
                    'name' => 'featured-large',
                    'width' => 1200,
                    'height' => 800,
                    'crop' => true,
                ],
            ],

            'textdomain' => 'blog-theme',

            'content_width' => 1200,
        ]


    В данном случае:

        supports
            → theme_supports Resource

        image_sizes
            → theme_setup Resource

        textdomain
            → theme_setup Resource

        content_width
            → theme_setup Resource

==================================================
13. RESULT
==================================================

    `setup` является открытой декларативной структурой.

    Корневой `setup` обязательно определяет Resource.

    Подблок может определить собственный Resource.

    При отсутствии собственного Resource
        подблок реализуется Resource корневого `setup`.

    Это обеспечивает:

        минимальное количество обязательных полей

        возможность расширения семантики

        отсутствие необходимости изменять core pipeline при добавлении новых подблоков

        возможность разделения реализаций между отдельными Resources

        поддержку Resource Architecture для Classic и Block.
