FUNCTIONS DOMAIN AND RESOURCE ARCHITECTURE
ARCHITECTURAL DESCRIPTION
(v1.0.0)

Status: Architectural Foundation

==================================================
1. PURPOSE
==================================================

    Данный документ фиксирует архитектурное решение
        по введению домена `functions` в Theme Configuration и определяет принцип формирования
        результирующего `functions.php`.

    Основная цель:

        обеспечить декларативное описание PHP-функциональности темы

        исключить необходимость заранее фиксировать содержимое `functions.php`

        обеспечить формирование пустого
            `functions.php` при отсутствии соответствующих деклараций

        обеспечить добавление функциональности через Configuration Package

        обеспечить возможность различных реализаций одной и той же декларации

        сохранить архитектурную симметрию с концепцией Templates.


==================================================
2. CORE PRINCIPLE
==================================================

   `functions` является доменом декларации PHP-функциональности темы.

    Домен `functions` описывает:

        ЧТО должна делать тема.

    Домен `functions` НЕ содержит непосредственную реализацию PHP-кода.

    Реализация PHP-функциональности определяется через Resource.

    Resource содержит архитектурно-зависимое представление декларации.

    Таким образом:

        Theme Configuration
            ↓
        functions declaration
            ↓
        ThemeIR
            ↓
        Resource
            ↓
        architecture-specific implementation
            ↓
        Artifact Generator
            ↓
        functions.php


==================================================
3. FUNCTIONS DOMAIN
==================================================

    В Configuration Package вводится новый домен:

        functions

    Структура Configuration Package принимает вид:

        nodes
        compositions
        design-systems
        assets
        integrations
        functions

    Домен `functions` является самостоятельным конфигурационным доменом.

    Существующие домены не определяют фиксированное содержимое `functions.php`.

    В частности:

        nodes
        compositions
        design-systems
        assets
        integrations

    не должны рассматриваться как структура результирующего `functions.php`.


==================================================
4. DECLARATION AND IMPLEMENTATION
==================================================

    Декларация `functions` определяет семантическую PHP-функциональность.

    Resource определяет её реализацию.

        Принцип:

            declaration = WHAT

            resource = HOW

    Декларация не должна содержать архитектурно-зависимый PHP-код,
        если соответствующая реализация может быть вынесена в Resource.


==================================================
5. RESOURCE ARCHITECTURE
==================================================

    Для домена `functions` применяется тот же принцип Resource Architecture,
        который используется для Templates.

    Один semantic resource может иметь несколько архитектурных реализаций.

        Например:

            function resource
                ├── classic
                └── block

    Каждая реализация определяет, каким образом одна и та же декларация
        представляется в конкретной архитектуре.

        Таким образом:

            functions declaration
                    ↓
            ┌───────┴────────┐
            ↓                ↓
            Classic           Block
            Resource          Resource
            ↓                ↓
        implementation    implementation


==================================================
6. ARCHITECTURAL SYMMETRY WITH TEMPLATES
==================================================

    Домен `functions` проектируется по тому же
        архитектурному принципу, что и Templates.

    Templates:

        declaration
            ↓
        Resource
            ↓
        architecture implementation
            ↓
        Artifact


    Functions:

        declaration
            ↓
        Resource
            ↓
        architecture implementation
            ↓
        Artifact


    Таким образом, различные типы генерируемого содержимого используют
        единый принцип разделения:
            declaration
            resource
            architecture implementation
            artifact


==================================================
7. FUNCTIONS.PHP
==================================================

    `functions.php` является результирующим Artifact,
        содержащим материализованную PHP-функциональность темы.

    `functions.php` не имеет обязательного заранее определённого содержимого.

        При отсутствии деклараций домена `functions` результатом является
            минимальный пустой `functions.php`.

        При наличии деклараций домена `functions` соответствующие Resource
            implementations материализуются в `functions.php`.

    Таким образом:

        no declarations
            ↓
        empty functions.php


        declarations
            ↓
        resources
            ↓
        functions.php
        with required functionality


==================================================
8. SEPARATION OF RESPONSIBILITIES
==================================================

    Theme Configuration отвечает за:

        декларативное описание требуемой функциональности.


    ThemeIR отвечает за:

        представление деклараций в семантической форме.


    Resource отвечает за:

        конкретную реализацию декларации.


    Artifacts Layer отвечает за:

        выбор архитектурного представления
        материализацию Resource
        формирование итогового Artifact.


    `functions.php` не должен самостоятельно интерпретировать Theme Configuration.


==================================================
9. EXTENSIBILITY
==================================================

    Новая PHP-функциональность должна добавляться через декларацию домена
        `functions` и соответствующий Resource.

    Добавление новой функциональности не должно требовать изменения
        базового механизма формирования `functions.php`, если существующий
        механизм позволяет представить её как новую декларацию.

    Архитектура должна позволять расширять набор PHP-функциональности
        без превращения `functions.php` в монолитный заранее определённый файл.


==================================================
10. ARCHITECTURAL CONSTRAINTS
==================================================

    Не допускается:

    хранение готового PHP-кода непосредственно в декларации `functions`

    жёсткое связывание Configuration с физической структурой `functions.php`

    обязательное наличие заранее фиксированного набора секций
    в `functions.php`

    смешивание декларации функциональности и её архитектурной реализации.


==================================================
11. RESULT
==================================================

    Домен `functions` становится частью Theme Configuration и предназначается
        для декларативного описания PHP-функциональности темы.

    Реализация функциональности выполняется
        через Resource Architecture.

    `functions.php` является итоговым Artifact, а не источником архитектурных правил.

    Принятый общий принцип:

            configuration declaration
                ↓
            semantic model
                ↓
            resource
                ↓
            architecture implementation
                ↓
            artifact


==================================================
12. STATUS
==================================================

    Решение принято.

    Домен `functions` должен проектироваться по принципу
        архитектурной симметрии с Templates.

    Детальная структура деклараций домена `functions`, состав его типов
        и формат Resources являются отдельным следующим этапом проектирования.
