theme-core v-2
THEME ARTIFACTS STAGE
(ARCHITECTURAL SPECIFICATION v1.0.0)

Status: Architecture Specification


==================================================
1. PURPOSE
==================================================

    Данный документ определяет строгую инженерную модель
        стадии Artifacts

    Стадия Artifacts преобразует результат работы Theme IR
        в физические артефакты WordPress-темы.

    Конечный результат build pipeline:

        Theme Configuration
                ↓
        Theme Components
                ↓
            Theme IR
                ↓
          Theme Artifacts
                ↓
        WordPress Theme


==================================================
2. PRIMARY RESPONSIBILITY
==================================================

    Основная ответственность Artifacts:

        материализовать Theme IR в полностью работоспособную WordPress-тему.

    Artifacts НЕ строит новое дерево темы.

    Artifacts НЕ разрешает зависимости, определённые Configuration.

    Artifacts НЕ раскрывает Composition.

    Artifacts получает от Theme IR уже разрешённую и структурированную модель,
        необходимую для генерации конечных файлов.


==================================================
3. ARCHITECTURAL BOUNDARY
==================================================

    Theme IR отвечает на вопрос:

        ЧТО должно присутствовать в результирующей теме
            и как элементы темы структурно связаны.

    Artifacts отвечает на вопрос:
        КАК представить это содержимое в конкретной архитектуре WordPress
            и записать его в конечный файл.

    Следовательно:

        Theme IR = resolution + structural model

        Artifacts = materialization + artifact generation


==================================================
4. INPUT
==================================================

    Основным входом Artifacts является Theme IR.

    Для Templates основным входом является:

        Template
            ↓
        TemplateTree
            ↓
        TemplateNode

    TemplateNode уже содержит:

        id;
        nodeId;
        compositionId;
        Resource;
        Rendering;
        Slot;
        children.

    Artifacts не должен повторно получать исходные 
        Configuration для разрешения этих зависимостей.


==================================================
5. TEMPLATE TREE
==================================================

    TemplateTree, полученный из Theme IR, является готовым деревом зависимостей.

    Например:

        index
          ├── header
          │     ├── site-title
          │     └── navigation
          │
          ├── layout
          │     ├── post-loop
          │     │     ├── post-title
          │     │     └── no-posts
          │     │
          │     └── sidebar
          │           └── widgets
          │
          └── footer
                └── copyright


    Artifacts должен использовать это дерево как единственный источник структурной информации.

    Повторное разрешение Composition, Node или других зависимостей запрещено.


==================================================
6. MATERIALIZATION
==================================================

    Materialization — это рекурсивное преобразование готового TemplateTree 
        в строковое содержимое конечного Artifact.

    Для каждого TemplateNode выполняется:

        1. определить Resource;
        2. получить Resource для выбранной архитектуры;
        3. прочитать содержимое Resource;
        4. материализовать допустимые children;
        5. сопоставить children с их slots;
        6. заменить соответствующие @slot_N;
        7. получить материализованное содержимое Node.

    Materialization не изменяет TemplateTree.


==================================================
7. RESOURCE
==================================================

    Resource является источником представления Node в конкретной архитектуре.

    Для Classic:

        Resource
            ↓
        classic resource file
            ↓
        PHP content


    Для Block:

        Resource
            ↓
        block resource file
            ↓
        HTML / block markup


    Архитектура выбирается Artifacts.

    Theme IR не генерирует архитектурный файл.


==================================================
8. RESOURCE AVAILABILITY
==================================================

    Для корректной materialization Node или Composition необходим доступный Resource.

    Если:
        Resource отсутствует;
        архитектурная реализация Resource отсутствует;
        файл Resource не существует;
        файл Resource невозможно прочитать;
        содержимое Resource невозможно получить;

    корректная materialization данного Node невозможна.


    В таком случае Artifacts обязан:

        1. зарегистрировать диагностическое сообщение через систему диагностики;

        2. указать контекст ошибки
           (Template, Node/Composition, Resource, architecture и причину, если она известна);

        3. не выдумывать содержимое Node;

        4. не использовать Resource другой архитектуры;

        5. не продолжать materialization данного Node как будто ошибки не произошло;

        6. продолжить обработку остальных элементов build pipeline.


    Ошибка materialization одного элемента не должна аварийно завершать выполнение приложения.


==================================================
9. CHILDREN AND SLOTS
==================================================

    Каждый child принадлежит только тому месту, которое определено его Slot.

    Slot является единственным механизмом размещения child внутри Resource родителя.

    Если Node имеет:
        slot = N

    он может быть размещён только в:
        @slot_N

    соответствующего Resource родителя.


    Запрещено:
        добавлять child после Resource;
        добавлять child перед Resource;
        добавлять child в произвольное место;
        автоматически размещать child в первый свободный slot;
        автоматически создавать отсутствующий slot.

==================================================
10. CHILD WITHOUT SLOT
==================================================

    Если child существует в TemplateTree, но Resource родителя не содержит
        соответствующего @slot_N,

    child не должен быть материализован в содержимое родителя.

    Artifacts обязан:
        1. зарегистрировать диагностическое сообщение;
        2. указать родительский Node/Composition;
        3. указать child;
        4. указать его Slot;
        5. продолжить выполнение.

    Child не должен появляться в каком-либо другом месте результата.


==================================================
11. RESOURCE WITHOUT CHILDREN
==================================================

    Если Resource не содержит slots и у Node отсутствуют children:
        Resource материализуется непосредственно.

    Это нормальный случай.


==================================================
12. RESOURCE WITH SLOTS
==================================================

    Если Resource содержит:

        @slot_1
        @slot_2
        ...
        @slot_N


    Artifacts должен определить содержимое каждого соответствующего child
       и выполнить точечную подстановку.

    Например:

        Resource:

            <header>
                @slot_1
                @slot_2
            </header>


        Tree:

            header
                site-title  slot=1
                navigation  slot=2


        Result:

            <header>
                [site-title]
                [navigation]
            </header>


==================================================
13. UNUSED SLOTS
==================================================

    Если Resource содержит @slot_N,
        но соответствующего child в TemplateNode нет,

    @slot_N не должен становиться частью конечного Artifact.

    Он должен быть удалён в процессе materialization.
        при этом необходимо добавить соответствующее сообщение в систему диагностики

    Результат не должен содержать неразмещённых @slot_N.


==================================================
14. RENDERING
==================================================

    Поле Rendering является частью Theme IR и передаёт Artifacts семантику Node.

    Rendering не используется для построения дерева.

    Дерево уже построено Theme IR.

    Rendering определяет способ materialization Node в рамках архитектуры.

    Artifacts должен учитывать Rendering при выборе способа представления Node,
        если конкретная архитектура требует специальной обработки.


==================================================
15. COMPOSITION
==================================================

    Composition раскрывается в Theme IR.

    После завершения Theme IR:

        Composition
            ↓
        TemplateNode
            ↓
        children


    Artifacts не должен повторно искать или раскрывать Composition.

    Например:

        index
          └── layout
                ├── post-loop
                └── sidebar


    Artifacts получает именно эту структуру.


==================================================
16. RECURSIVE MATERIALIZATION
==================================================

    Materialization выполняется рекурсивно от корневых Node к листовым Node.


    Для Node:

        materialize(Node)
            ↓
        materialize(children)
            ↓
        substitute slots
            ↓
        Node content


    Поэтому результат дочернего Node становится входом для materialization
        его непосредственного родителя.


    Полученный результат затем становится частью materialization следующего уровня.


==================================================
17. ROOT NODES
==================================================

    Корневые Node TemplateTree не имеют родительского Resource.

    Каждый root Node materialизуется самостоятельно.

    После materialization корневые Node объединяются в порядке, определённом TemplateTree.

    Artifacts не должен менять порядок корневых Node.


==================================================
18. TEMPLATE ARTIFACT GENERATION
==================================================

    Template Artifact Generator отвечает за создание Artifact конкретного Template.


    Его ответственность:

        определить Artifact identity;

        определить destination;

        выбрать архитектурный renderer;

        передать TemplateTree renderer;

        создать Artifact с полученным содержимым.


    Например:

        Classic:

            Template
                ↓
            ClassicTemplateTreeRenderer
                ↓
            %s.php


        Block:

            Template
                ↓
            BlockTemplateTreeRenderer
                ↓
            templates/%s.html


==================================================
19. ARCHITECTURE SEPARATION
==================================================

    Classic и Block являются независимыми стратегиями materialization.

    Общая для них модель:

        Template
            ↓
        TemplateTree
            ↓
        recursive materialization


    Архитектурно специфичными являются:

        Resource representation;

        Resource reading;

        Rendering semantics;

        Artifact destination;

        конечный формат файла.


    Classic renderer не должен генерировать Block representation.

    Block renderer не должен генерировать Classic representation.


==================================================
20. DIAGNOSTICS
==================================================

    Artifacts является частью build pipeline и обязан использовать существующую
        систему диагностики и логирования.


    Диагностироваться должны как минимум:

        отсутствующий Resource;

        отсутствующая архитектурная реализация Resource;

        нечитаемый Resource;

        отсутствующий Slot для существующего child;

        невозможность корректной materialization;

        другие нарушения, препятствующие созданию корректного Artifact.


    Диагностическое сообщение должно содержать достаточный контекст для определения:

        какой Artifact строился;

        какой Template обрабатывался;

        какой Node или Composition участвовал;

        какой Resource использовался;

        какая architecture выбрана;

        какая операция завершилась ошибкой.


==================================================
21. ERROR ISOLATION
==================================================

    Диагностическая ошибка Artifacts не должна автоматически останавливать
        выполнение всего приложения.

    Ошибка локализуется на максимально узком уровне,
        на котором невозможно получить корректный результат.

    После регистрации ошибки обработка остальных независимых
        Artifact продолжается.


    Artifacts не должен:

        скрывать ошибку;

        молча подменять содержимое;

        создавать фиктивный Resource;

        использовать Resource другой архитектуры;

        произвольно перестраивать дерево.


==================================================
22. OUTPUT
==================================================

    Результатом Artifacts являются полностью сформированные Artifact objects.


    Каждый Artifact содержит:

        identity;

        type;

        destination;

        materialized content;

        status.


    После успешного завершения стадии Artifact Writer записывает Artifact в файловую систему.

    Совокупность записанных Artifact должна образовывать работоспособную WordPress-тему.


==================================================
23. BUILD COMPLETENESS
==================================================

    Artifacts отвечает не только за генерацию отдельных строк.

    Его конечная задача — сформировать полный набор необходимых файлов темы.

    Для Template domain это означает:

        каждый требуемый Template должен быть преобразован
            в соответствующий Artifact.

    Другие домены Theme IR должны аналогично преобразовываться
        в свои Artifact.


    В результате:

        Theme IR
            ↓
        Artifact Collection
            ↓
        Artifact Writer
            ↓
        WordPress Theme


==================================================
24. INVARIANTS
==================================================

    Стадия Artifacts обязана сохранять следующие инварианты:

        1. Структура TemplateTree не изменяется.

        2. Composition не разрешается повторно.

        3. Node не разрешается повторно.

        4. Child может быть размещён только в назначенном Slot.

        5. Child без соответствующего Slot не попадает в результат.

        6. Неразмещённые @slot_N не попадают в результат.

        7. Отсутствующий Resource не заменяется фиктивным содержимым.

        8. Resource другой архитектуры не используется как fallback.

        9. Ошибка materialization регистрируется системой диагностики.

        10. Локальная ошибка не останавливает обработку независимых Artifact.

        11. Порядок Node определяется Theme IR и не изменяется Artifacts.

        12. Результатом успешной стадии является набор физических Artifact,
                достаточный для формирования целевой WordPress-темы.


==================================================
25. RESPONSIBILITY MODEL
==================================================

    Theme Configuration:
        WHAT IS DECLARED

    Theme Components:
        WHAT COMPONENTS EXIST

    Theme IR:
        WHAT THE FINAL STRUCTURE IS

    Artifacts:
        HOW THAT STRUCTURE BECOMES A WORDPRESS THEME

    Artifact Writer:
        HOW GENERATED ARTIFACTS BECOME FILES

    Таким образом:

        Configuration
            ↓
        Components
            ↓
            IR
            ↓
        Materialization
            ↓
        Artifacts
            ↓
          Files
            ↓
        WordPress Theme


==================================================
26. CORE PRINCIPLE
==================================================

    Theme IR строит истину о структуре темы.

    Artifacts не должен эту истину заново устанавливать.

    Artifacts должен её материализовать.

    Поэтому основная операция стадии:

        TemplateTree
            ↓
        architecture-specific
        recursive materialization
            ↓
        Artifact


    Именно это является основной ответственностью
        Artifacts stage.
