THEME-CORE V-2
ASSETS DOMAIN RESEARCH
STAGE 1

PRACTICAL MATERIALIZATION MODEL
(v1.0.0)

Status: Research Summary

==================================================
1. PURPOSE
==================================================

   Данный документ фиксирует результаты первого этапа исследования домена Assets.

   Исследование направлено на определение:
    - практического результата материализации Assets;
    - основных типов ресурсов WordPress Theme;
    - различия между ресурсом, его форматом, назначением и способом использования.

==================================================
2. PRACTICAL RESULT OF ASSETS MATERIALIZATION
==================================================

    Результатом материализации Assets должна быть
        готовая WordPress Theme, содержащая необходимые
        физические ресурсы и обеспечивающая их корректное подключение и использование.

    Материализация включает два основных результата:

        1. Физическое размещение ресурсов.
            Ресурсы:
                - копируются;
                - либо при необходимости трансформируются;
            после чего размещаются в соответствующих
                директориях итоговой темы.

        2. Обеспечение корректного использования ресурсов.
            Для ресурсов, требующих регистрации или
                подключения WordPress, создаётся необходимая
                инфраструктура использования.
            В частности, это может включать соответствующий
                код в `functions.php`.

    Не каждый Asset требует регистрации или подключения через `functions.php`.

    Некоторые ресурсы используются непосредственно
        шаблонами, CSS, JavaScript, `theme.json`
        или другими механизмами WordPress.

==================================================
3. ASSETS DOMAIN BOUNDARY
==================================================

    Assets Domain отвечает за описание ресурсов темы.

    Assets Domain не отвечает непосредственно за:

        - копирование физических файлов;
        - трансформацию файлов;
        - создание директорий;
        - публикацию ресурсов;
        - регистрацию ресурсов в WordPress;
        - enqueue;
        - bundling;
        - оптимизацию.

    Эти операции относятся к последующим уровням
        материализации и генерации.

    Assets Domain определяет семантическую информацию,
        необходимую для выполнения этих операций.

==================================================
4. RESOURCE CATEGORIES
==================================================

    Исследование показало, что WordPress Theme может
        содержать широкий спектр ресурсов.

    Основные категории ресурсов, которые необходимо
        учитывать при проектировании Assets Domain:

        - Stylesheet;
        - JavaScript;
        - Font;
        - Image;
        - SVG;
        - Video;
        - Audio;
        - Data;
        - WebAssembly;
        - Translation resources;
        - Site Icon / favicon;
        - Theme screenshot.

    Дополнительно могут существовать другие произвольные
        файлы, необходимые конкретной теме.

==================================================
5. RESOURCE FORMAT
==================================================

    Формат определяет физическое представление ресурса.

    Примеры:

        Stylesheet:
            CSS

        JavaScript:
            JS

        Font:
            WOFF2
            WOFF
            TTF
            OTF

        Image:
            PNG
            JPEG
            WebP
            AVIF
            GIF

        SVG:
            SVG

        Video:
            MP4
            WebM

        Audio:
            MP3
            OGG
            WAV

        Data:
            JSON
            XML

        WebAssembly:
            WASM

        Translation:
            MO
            PO
            POT
            JSON

    Формат ресурса не определяет его семантическое назначение.

==================================================
6. RESOURCE PURPOSE
==================================================

    Один физический формат может использоваться
        для различных семантических целей.

    Например:

        SVG
            может быть:
                Logo;
                Icon;
                Illustration;
                Sprite.

        Image
            может быть:
                Logo;
                Preview Image;
                Background;
                Content Image.

        JavaScript
            может быть:
                Navigation Script;
                Interaction Script;
                Frontend Script;
                Editor Script.

        Font
            может быть:
                Primary Font;
                Secondary Font;
                Icon Font.

    Следовательно:
        Resource Format не является
            Resource Purpose.

==================================================
7. RESOURCE USAGE
==================================================

    Один и тот же ресурс может использоваться
        различными механизмами темы.

    Возможные способы использования:
        - WordPress enqueue;
        - template;
        - CSS;
        - JavaScript;
        - `theme.json`;
        - WordPress API;
        - другие механизмы темы.

    Следовательно:
        Resource Type
        Resource Format
        Resource Purpose
        Resource Usage

    являются различными аспектами описания ресурса
        и не должны автоматически объединяться в одну характеристику.

==================================================
8. SPECIAL RESOURCE CASES
==================================================

    Некоторые ресурсы имеют специальное значение
        в структуре WordPress Theme.

    К ним относятся:
        - `style.css`;
        - `theme.json`;
        - translation resources;
        - Site Icon / favicon;
        - theme screenshot.

    Для таких ресурсов способ материализации может
        определяться специальными правилами WordPress,
        а не общей схемой размещения Assets.

==================================================
9. ARCHITECTURAL CONCLUSION
==================================================

    Практический результат работы Assets в составе
        компилятора — итоговая WordPress Theme, в которой:

        - необходимые физические ресурсы присутствуют;
        - ресурсы размещены в требуемых местах;
        - ресурсы, требующие регистрации или подключения, 
            корректно зарегистрированы и подключены;
        - тема может использовать ресурсы согласно
            их назначению.

    При этом Assets Domain должен оставаться отделённым
        от конкретного способа физической материализации.

==================================================
10. RESEARCH CONCLUSION
==================================================

    Первый этап исследования подтвердил:

        1. Assets должны приводить к физическим ресурсам
        в итоговой WordPress Theme.

        2. Для части ресурсов необходим механизм их
        регистрации или подключения.

        3. Не все ресурсы требуют `functions.php`.

        4. Ресурс, его физический формат, семантическое
        назначение и способ использования являются
        различными понятиями.

        5. Список физических типов ресурсов не должен
        автоматически становиться моделью доменной
        сущности Asset.

    Следующий этап исследования должен определить,
        какие из этих характеристик действительно относятся
        к Assets Domain и должны присутствовать в его декларативной модели.
