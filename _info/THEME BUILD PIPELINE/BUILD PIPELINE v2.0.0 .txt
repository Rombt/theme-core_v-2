theme-core v-2
BUILD PIPELINE
ARCHITECTURAL DESCRIPTION
(v2.0.0)

Status: Architectural Foundation

==================================================
1. PURPOSE
==================================================

    Build Pipeline v2.0.0 является архитектурной основой
        системы компиляции WordPress Theme.

    Основная цель версии:
        преобразовать декларативное описание темы
        во внутреннее представление компилятора,
        а затем в готовую WordPress Theme.

    Версия v2.0.0 закрепляет основную архитектурную модель системы:

        Theme = Compiled Architecture

    Компиляция рассматривается как последовательное
        преобразование архитектурных моделей.

==================================================
2. SCOPE
==================================================

    Build Pipeline v2.0.0 решает следующие задачи:

        загрузка Theme Configuration
        построение декларативной модели темы
        построение Theme IR
        генерация Theme Artifacts
        запись Theme Artifacts
        создание WordPress Theme

    Каждая задача выполняется отдельным архитектурным этапом.

==================================================
3. PIPELINE MODEL
==================================================

    Pipeline состоит из пяти последовательных стадий, архитектурных моделей, 
        (стадии названы по результату, а не по процессу):

        Theme Configuration (подготовки входных данных пользователем)
            ↓
        Theme Components (загрузка конфигурационного пакета)
            ↓
        Theme IR
            ↓
        Theme Artifacts
            ↓
        WordPress Theme (материализация результатов компиляции)

    Каждая стадия выполняет только одну
        архитектурную ответственность.

    Pipeline является полностью детерминированным.

    Одинаковая конфигурация всегда должна создавать
        одинаковую Theme IR,
        одинаковые Theme Artifacts
        и одинаковую WordPress Theme.

    Pipeline работает с абстрактными моделями, а не со структурой конфигурационного пакета. 
    Поэтому изменение или расширение Theme Configuration 
    не должно требовать изменения существующих стадий Pipeline.

    изменяется Configuration — адаптируется только загрузчик/маппинг, а не Pipeline

==================================================
4. THEME CONFIGURATION
==================================================

    На этой стадии происходит подготовка входных данных пользователем

    Theme Configuration является источником истины.

    Конфигурация описывает декларативную структуру темы.

    Конфигурация не содержит поведения.


    Конфигурация определяет:
        компоненты темы
        связи между компонентами
        параметры генерации
        настройки сборки

    Pipeline не содержит захардкоженного описания темы.

==================================================
5. THEME COMPONENTS
==================================================

    На этом этапе происходит загрузка конфигурационного пакета:
        получение сырых данных от пользователя в установленном формате
        нормализация полученных данных 
        валидация полученных данных
        построение связей между компонентами

    В результате получается данные в понятийной модели предметной области (пользователя):
        Header
        Navigation
        Footer
        Blog
        Sidebar

    Theme Components являются декларативной моделью темы.

    Данная модель является результатом стадии Loading.

    Theme Components описывают:
        из чего состоит тема
        какие архитектурные компоненты существуют
        как они связаны между собой

    Theme Components не являются внутренней моделью компилятора.

    Theme Components не содержат информации, необходимой для генерации артефактов. 
    Это значит что на данном этапе ещё отсутствуют какие-либо сведения о 
        процессе компиляции, 
        генерации артефактов 
        структуре Theme IR.

==================================================
6. THEME IR
==================================================

    Theme IR является Intermediate Representation.

    Theme IR представляет собой внутреннюю модель компилятора.

    Theme IR создаётся исключительно
        путём преобразования Theme Components.

    Построение Theme IR является стадией Resolution.

    Theme IR является единственным источником данных
        для генераторов артефактов.

==================================================
7. ARTIFACT GENERATION
==================================================

    Artifact Generation отвечает за создание Theme Artifacts.

    Генерация выполняется исключительно на основе Theme IR.

    Генераторы не работают напрямую
        с Theme Configuration
        или Theme Components.

    Результатом стадии является коллекция Theme Artifacts.

==================================================
8. ARTIFACT MODEL
==================================================

    Artifact является архитектурной единицей результата.

    Artifact не является файлом.

    Artifact содержит:
        идентификатор
        тип
        содержимое
        путь назначения
        дополнительные метаданные

    Pipeline работает исключительно с артефактами.

    Файлы являются способом материализации артефактов.

==================================================
9. ARTIFACT WRITING
==================================================

    Artifact Writing отвечает исключительно
        за материализацию Theme Artifacts.

    Writer отвечает за:

        создание каталогов
        запись файлов
        обновление существующих файлов

    Writer не участвует
        в построении Theme IR
        и не генерирует содержимое артефактов.

==================================================
10. ARCHITECTURAL BOUNDARIES
==================================================

    Между стадиями существуют строгие границы ответственности.

    Theme Configuration
        отвечает только за описание темы.

    Theme Components
        отвечают только за декларативную архитектурную модель.

    Theme IR
        отвечает только за внутреннее представление компилятора.

    Theme Artifacts
        отвечают только за описание результата генерации.

    WordPress Theme
        является физической материализацией Theme Artifacts.

==================================================
11. NON-GOALS
==================================================

    Build Pipeline v2.0.0 не допускает:

        генерацию артефактов из Theme Configuration
        генерацию артефактов из Theme Components
        смешивание Loading и Resolution
        смешивание декларативной модели и Theme IR
        смешивание Theme IR и физических файлов

    Каждая архитектурная модель существует
        только в пределах собственной ответственности.

==================================================
12. FINAL DEFINITION
==================================================

    Build Pipeline v2.0.0 является системой последовательного
        преобразования архитектурных моделей.

    Центральным объектом стадии Loading является:

        Theme Components

    Центральным объектом стадии Resolution является:

        Theme IR

    Центральным объектом стадии Generation является:

        Theme Artifacts

    Центральным результатом Pipeline является:

        WordPress Theme

    Архитектурная формула Build Pipeline v2.0.0:

        Theme Configuration
            ↓
        Theme Components
            ↓
        Theme IR
            ↓
        Theme Artifacts
            ↓
        WordPress Theme

    Каждая последующая стадия работает
        исключительно с результатом предыдущей.

    Ни одна стадия Pipeline не должна
        нарушать установленную архитектурную границу.
