theme-core v-2
GLOSSARY (MINIMUM ENGINEERING VERSION)
==================================================

ЦЕЛЬ ГЛОССАРИЯ
--------------------------------------------------
Глоссарий фиксирует точные значения ключевых понятий системы.

Он нужен для того, чтобы:
- все части системы работали с одинаковыми понятиями
- не возникало путаницы между слоями
- архитектура оставалась стабильной и расширяемой

Глоссарий — это часть архитектуры, а не документация.


==================================================
ОСНОВНЫЕ ПОНЯТИЯ СИСТЕМЫ
==================================================


1. СИСТЕМА (theme-core v-2)
--------------------------------------------------
Надстройка над WordPress, которая управляет созданием сайтов.

Задачи:
- сборка сайтов из конфигураций
- управление структурой страниц
- управление дизайном через единые правила
- организация демо и шаблонов сборки

НЕ является:
- темой WordPress в классическом смысле
- визуальным редактором
- CMS


--------------------------------------------------


2. САЙТ
--------------------------------------------------
Конкретный результат работы системы.

Сайт — это:
- набор страниц
- набор секций на страницах
- применённый дизайн
- применённая конфигурация

Сайт НЕ является:
- статическим демо
- набором файлов темы


--------------------------------------------------


3. КОНФИГУРАЦИЯ САЙТА
--------------------------------------------------
Описывает, как должен быть собран сайт.

Содержит:
- какие страницы существуют
- какие секции используются
- какие настройки дизайна применены

Конфигурация НЕ содержит HTML и не содержит шаблонов.


--------------------------------------------------


4. СЕКЦИЯ
--------------------------------------------------
Базовый строительный блок страницы.

Секция — это:
- блок контента (например: hero, pricing, faq)
- переиспользуемый элемент интерфейса

Секция НЕ является:
- страницей
- шаблоном страницы
- контейнером дизайна


--------------------------------------------------


5. РАСКЛАДКА (LAYOUT)
--------------------------------------------------
Правила размещения секции на странице.

Определяет:
- ширину
- отступы
- позиционирование
- поведение на адаптиве

Layout НЕ содержит контент.


--------------------------------------------------


6. ДИЗАЙН-СИСТЕМА
--------------------------------------------------
Набор единых правил визуального оформления.

Содержит:
- цвета
- типографику
- отступы
- радиусы
- общие визуальные правила

Используется всеми частями системы.


--------------------------------------------------


7. ПРЕСЕТ (PRESET)
--------------------------------------------------
Готовый набор настроек дизайна и структуры.

Используется для:
- быстрого создания сайтов
- переключения стилей сайта
- создания демо-версий

Пример: "Agency", "Shop", "SaaS"


--------------------------------------------------


8. РЕНДЕРЕР
--------------------------------------------------
Механизм, который выводит секцию на экран.

Рендерер может быть:
- PHP шаблон
- Gutenberg блок
- Elementor элемент

Рендерер НЕ определяет структуру сайта.


--------------------------------------------------


9. МАППИНГ РЕНДЕРЕРА
--------------------------------------------------
Связь между секцией и тем, как она отображается.

Пример:
секция "hero"
→ Elementor шаблон №12


--------------------------------------------------


10. СБОРКА САЙТА (ASSEMBLY)
--------------------------------------------------
Процесс создания сайта из конфигурации.

Включает:
- чтение конфигурации
- выбор секций
- применение layout
- применение дизайна
- вызов рендереров


--------------------------------------------------


11. ДЕМО
--------------------------------------------------
Предустановленный набор конфигурации сайта.

Демо — это НЕ сайт.

Демо — это:
- готовая конфигурация
- набор секций
- дизайн-пресет


--------------------------------------------------


12. Provisioning (процесс автоматической подготовки и сборки системы (сайта) из конфигурации)
--------------------------------------------------
Процесс создания нового сайта системой.

Включает:
- применение демо-конфигурации
- создание структуры сайта
- настройку дизайна
- сборку страниц

НЕ является импортом XML.


--------------------------------------------------


13. MULTISITE-CAPABLE (ОПЦИОНАЛЬНО)
--------------------------------------------------
Система может работать поверх WordPress Multisite.

Это означает:
- один WordPress → много сайтов
- каждый сайт имеет свою конфигурацию
- система управляет созданием сайтов

Но Multisite НЕ является обязательной частью системы.


==================================================
КЛЮЧЕВОЙ ПРИНЦИП СИСТЕМЫ
==================================================

Система не хранит готовые сайты.

Система хранит правила их сборки.
