==================================================
META
==================================================

НАЗНАЧЕНИЕ
--------------------------------------------------

META — это инфраструктурный раздел входного пакета.

Он описывает:
    - сам input package,
    - его происхождение,
    - совместимость,
    - версию,
    - контекст сборки,
    - системные параметры.

META не описывает:
    - сайт,
    - UI,
    - composition,
    - content,
    - rendering.

META описывает:
    “контекст существования входных данных”.

Это системный контракт пакета.


==================================================
РОЛЬ META В АРХИТЕКТУРЕ
==================================================

META нужен чтобы система понимала:

    - что это за пакет,
    - к какой версии ядра он относится,
    - совместим ли пакет с runtime,
    - как был собран пакет,
    - какие зависимости требуются,
    - какие feature flags активны,
    - в каком окружении пакет был создан.

Без META невозможно:
    - безопасно валидировать input,
    - выполнять миграции,
    - контролировать совместимость,
    - гарантировать корректный provisioning,
    - выполнять стабильный registry resolving.


==================================================
META В DATA ARCHITECTURE MODEL
==================================================

META относится прежде всего к:

    INFRASTRUCTURE DATA

и частично к:

    INTEGRATION DATA

Причина:

META описывает не бизнес-данные сайта,
а инфраструктурные свойства системы и input package.


==================================================
СТРУКТУРА META
==================================================

META
│
├── schema
│   Версии и совместимость схем.
│
├── project
│   Информация о проекте/теме.
│
├── build
│   Информация о генерации пакета.
│
├── environment
│   Контекст окружения.
│
├── dependencies
│   Зависимости input-пакета.
│
└── flags
    Служебные feature/runtime flags.


==================================================
ПОДРАЗДЕЛЫ
==================================================

--------------------------------------------------
schema
--------------------------------------------------

Описывает:
    - версию input schema,
    - версию ядра,
    - правила совместимости,
    - migration compatibility.

Нужен для:
    - version control,
    - schema evolution,
    - backward compatibility.


--------------------------------------------------
project
--------------------------------------------------

Описывает:
    - идентификатор проекта,
    - название темы,
    - автора,
    - vendor,
    - package identity.

Нужен для:
    - идентификации пакета,
    - multisite ecosystem,
    - marketplace/distribution.


--------------------------------------------------
build
--------------------------------------------------

Описывает:
    - время генерации,
    - build id,
    - generator version,
    - source pipeline.

Нужен для:
    - debugging,
    - reproducible builds,
    - CI/CD integration.


--------------------------------------------------
environment
--------------------------------------------------

Описывает:
    - target platform,
    - runtime environment,
    - deployment context.

Нужен для:
    - environment-aware provisioning,
    - runtime compatibility.


--------------------------------------------------
dependencies
--------------------------------------------------

Описывает:
    - registry dependencies,
    - required modules,
    - renderer dependencies,
    - external integrations.

Нужен для:
    - dependency resolution,
    - module loading,
    - ecosystem compatibility.


--------------------------------------------------
flags
--------------------------------------------------

Описывает:
    - feature flags,
    - experimental capabilities,
    - runtime toggles.

Нужен для:
    - staged rollout,
    - feature control,
    - development/testing modes.


==================================================
АРХИТЕКТУРНЫЕ СВОЙСТВА META
==================================================

META должен быть:

    - минимальным,
    - стабильным,
    - декларативным,
    - независимым от runtime state,
    - независимым от UI,
    - независимым от content.

META — это:
    system contract layer.


==================================================
ГЛАВНАЯ АРХИТЕКТУРНАЯ ИДЕЯ
==================================================

META делает input package:

    - переносимым,
    - валидируемым,
    - версионируемым,
    - совместимым,
    - интерпретируемым системой.

META — это точка входа
для всего lifecycle input package.
