Gutenberg это обычное SPA!!


Чтобы блок не просто существовал в файлах, а «ожил» в интерфейсе Gutenberg, должна сработать цепочка событий.
Если хотя бы одно звено выпадет, блок либо не появится в списке, либо выдаст ошибку при вставке.

Серверный уровень (PHP)
    WordPress должен узнать, что блок вообще существует
        Хук init: Регистрация должна происходить именно на этом событии.
        Функция register_block_type( $path ): Она принимает путь к папке, где лежит block.json
        Чтение block.json:
            WP открывает этот файл и парсит его.
            Если в JSON есть синтаксическая ошибка, блок не зарегистрируется.
    Уровень манифеста (block.json)
        Это паспорт блока в нем обязательно должны быть:
            name: Уникальный идентификатор с пространством имен (например, my-engine/my-block).
            title: Название, которое пользователь увидит в поиске блоков.
            editorScript: Указание на JS-файл (например, "file:./index.js").
                Это тот самый скрипт, который «скажет» React-приложению Gutenberg: «Привет, я здесь, отрисуй меня».
    Клиентский уровень (JavaScript / React)
        Даже если блок динамический, на PHP, редактору Gutenberg нужен JavaScript (JS-файл который указан в editorScript)
        который опишет блок в админке (внешний вид, логика, данные прочее)
        Функция registerBlockType:
            import { registerBlockType } from '@wordpress/blocks';
            import Edit from './edit';
            import metadata from './block.json';

            registerBlockType( metadata.name, {
                edit: Edit, // Компонент, отвечающий за вид в редакторе
                save: () => null, // Для динамических блоков всегда null
            } );
