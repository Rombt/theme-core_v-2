theme-core v-2

APPLICATION CONTEXT
ARCHITECTURAL DESCRIPTION
(v1.0.0)

==================================================
1. PURPOSE
==================================================

    ApplicationContext является верхним lifecycle-контекстом системы.

    Его задача — предоставлять единое место хранения объектов,  
        которые являются application-wide и должны быть доступны 
        на различных стадиях жизненного цикла приложения.

    ApplicationContext предназначен для хранения объектов,
        создающихся на ранних этапах работы приложения и существующих 
        на протяжении всего его жизненного цикла.

    ApplicationContext устраняет необходимость искусственного распространения application-wide объектов 
        через множество архитектурных слоёв и компонентов.

    ApplicationContext не предназначен для хранения бизнес-состояния, execution-состояния,
        временных данных сборки или бизнес-сервисов.

==================================================
2. POSITION IN LIFECYCLE
==================================================

    ApplicationContext является первым контекстом системы.

    Схема жизненного цикла:

        Application Startup
            ↓
        ApplicationContext Created
            ↓
        Bootstrap Phase
            ↓
        Business Execution
            ↓
        Finalization
            ↓
        Application Shutdown

    ApplicationContext создаётся до начала Bootstrap Phase 
        и уничтожается после полного завершения работы приложения.

    ApplicationContext является единственным контекстом,
        существующим на протяжении всего жизненного цикла системы.

==================================================
3. POSITION IN CONTEXT HIERARCHY
==================================================

    ApplicationContext является верхним контекстом системы.

    Иерархия контекстов:

        ApplicationContext
            ↓
        KernelContext
            ↓
        BuildSession

    Контексты могут распространяться только сверху вниз.

    Нижележащие контексты могут использовать объекты из вышележащих контекстов.

    Вышележащие контексты не должны зависеть от существования нижележащих.

    ApplicationContext не должен содержать  ссылок на KernelContext, BuildSession
        или любые объекты, принадлежащие им.

==================================================
4. OBJECT CATEGORIES
==================================================

    В ApplicationContext допускается размещение
    только application-wide объектов двух категорий.

    4.1 APPLICATION STATE
    --------------------------------------------------

        Объекты, описывающие состояние приложения и существующие на протяжении всего
            жизненного цикла системы.

        Примеры:
            - Configuration
            - Environment
            - ProjectRoot
            - ApplicationVersion
            - Clock

        После регистрации в ApplicationContext такие объекты должны рассматриваться
            как неизменяемые.

    4.2 CORE INFRASTRUCTURE SERVICES
    --------------------------------------------------

        Инфраструктурные сервисы,
            необходимые различным подсистемам на протяжении всего жизненного цикла.
            но не относящиеся к бизнес-логике приложения,

        Примеры:
            - Diagnostics
            - Logger
            - другие application-wide инфраструктурные сервисы

        Конкретный состав таких сервисов определяется отдельно.

==================================================
5. INCLUSION RULES
==================================================

        Объект может быть помещён в ApplicationContext только если одновременно выполняются все следующие условия:

            1. Object is application-wide.

            2. Object создаётся до начала Business Execution.

            3. Object существует на протяжении всего жизненного цикла приложения.

            4. Object не зависит от BuildSession.

            5. Object не зависит от KernelContext.

            6. Object не представляет бизнес-функциональность.

            7. Object является частью application state либо относится
                к application-wide infrastructure.

        Если хотя бы одно условие не выполняется, объект не должен
            размещаться в ApplicationContext.

==================================================
6. PROHIBITED OBJECTS
==================================================

    В ApplicationContext запрещено размещать:

            - объекты бизнес-домена;
            - объекты Theme Generation;
            - объекты Artifact Generation;
            - объекты Pipeline Execution;
            - объекты BuildSession;
            - объекты KernelContext;
            - execution state;
            - runtime state;
            - временные данные сборки;
            - результаты сборки;
            - объекты, существующие только
            - рамках конкретной стадии;
            - объекты, жизненный цикл которых меньше жизненного цикла приложения.

==================================================
7. ARCHITECTURAL RULES
==================================================

    ApplicationContext не является Service Locator.

    ApplicationContext не является контейнером сервисов.

    ApplicationContext не является заменой Dependency Injection.

    ApplicationContext не создаёт объекты.

    ApplicationContext не управляет жизненным циклом объектов.

    ApplicationContext выполняет только одну задачу:
        хранение application-wide объектов, удовлетворяющих правилам включения.

    Все обычные зависимости приложения должны передаваться через Composition Runtime
        и стандартный Dependency Injection.

==================================================
8. ARCHITECTURAL GUARANTEES
==================================================

    Использование ApplicationContext обеспечивает:

        - единое место хранения application-wide объектов;
        - контролируемое распространение глобальных зависимостей;
        - соблюдение иерархии контекстов;
        - отсутствие искусственного dependency propagation;
        - изоляцию BuildSession от application-wide состояния;
        - предсказуемую модель жизненного цикла объектов;
        - возможность расширения системы без изменения архитектурных границ.
