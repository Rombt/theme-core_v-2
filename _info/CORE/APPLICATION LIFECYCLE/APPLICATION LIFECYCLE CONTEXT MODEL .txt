theme-core v-2
APPLICATION LIFECYCLE CONTEXT MODEL
(v1.0.0)

==================================================
1. PROBLEM
==================================================

    В системе существуют данные и сервисы, которые 
        создаются на ранних этапах жизненного цикла приложения, 
        но должны быть доступны множеству подсистем на разных архитектурных слоях.

        Примеры:
            - Configuration
            - Clock
            - Environment
            - ProjectRoot
            - ApplicationVersion
            - Diagnostics
            - Logger
            - и другие аналогичные объекты

    Попытка передавать такие объекты через обычный DI приводит к тому, 
        что они начинают искусственно протаскиваться через множество слоёв,
        не являясь частью их ответственности.

    Необходимо создать единый механизм распространения подобных объектов
        через всё приложение при сохранении строгих архитектурных границ.

==================================================
2. LIFECYCLE MODEL
==================================================

    Приложение состоит из нескольких основных lifecycle стадий.

    2.1 APPLICATION STARTUP
    --------------------------------------------------

        Отвечает за первоначальную инициализацию приложения.

        Примеры:
            - загрузка конфигурации
            - создание системных сервисов
            - подготовка окружения

    2.2 APPLICATION BUILD
    --------------------------------------------------

        Отвечает за подготовку системы к выполнению бизнес-процессов.

        Примеры:
            - bootstrap sequence
            - composition runtime creation
            - runtime preparation

    2.3 BUSINESS EXECUTION
    --------------------------------------------------

        Отвечает за выполнение основной работы приложения.

        Примеры:
            - pipeline execution
            - stages execution
            - theme generation
            - artifact generation

    2.4 FINALIZATION
    --------------------------------------------------

        Отдельная стадия жизненного цикла.

        Будет рассмотрена позже.

==================================================
3. CONTEXT HIERARCHY
==================================================

    Каждая lifecycle стадия обладает собственным контекстом.

    Контексты образуют иерархию.

    3.1 APPLICATION CONTEXT
    --------------------------------------------------

        Глобальный контекст приложения.

        Создаётся первым.

        Живёт всё время существования приложения.

        Содержит application-wide объекты.

        Примеры:
            - Configuration
            - Clock
            - Environment
            - ProjectRoot
            - ApplicationVersion
            - Diagnostics
            - Logger
            - другие глобальные объекты

        Должен быть доступен во всех последующих слоях.

    3.2 KERNEL CONTEXT
    --------------------------------------------------

        Контекст bootstrap стадии.

        Создаётся после ApplicationContext.

        Живёт только во время bootstrap.

        Содержит bootstrap-specific состояние 
            является хранилищем для всего необходимого на стадии bootstrap.

        Примеры:
            - bootstrap status
            - current bootstrapper
            - bootstrap exception
            - executed bootstrappers

        Доступен только внутри bootstrap слоя.

    3.3 BUILD SESSION
    --------------------------------------------------

        Контекст выполнения сборки.

        Создаётся непосредственно перед запуском бизнес-процессов.

        Живёт только в рамках одной сборки.

        Содержит execution-specific состояние.

        Примеры:
            - theme model
            - generated artifacts
            - build results
            - execution resources

        Доступен только во время выполнения бизнес-логики.

==================================================
4. DEPENDENCY FLOW
==================================================

    Контексты могут распространяться только сверху вниз.

    Разрешено:

        ApplicationContext
            ↓
        KernelContext
            ↓
        BuildSession

    Запрещено:

        BuildSession
            ↓
        KernelContext

        KernelContext
            ↓
        ApplicationContext

    Нижележащий слой может использовать вышележащий контекст.

    Вышележащий слой НЕ должен знать о существовании нижележащих.

==================================================
5. ARCHITECTURAL RULE
==================================================

    ApplicationContext является единственной точкой хранения объектов, которые:
        - создаются рано
        - живут долго
        - нужны многим подсистемам
        - должны быть доступны на всех слоях

    Все остальные зависимости должны передаваться через обычный DI.

    Таким образом достигается:
        - строгая изоляция слоёв
        - контролируемое распространение данных
        - отсутствие глобальных service locator
        - единая модель жизненного цикла
        - расширяемость без изменения архитектуры
