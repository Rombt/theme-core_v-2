THEME-CORE V-2
CONFIGURATION OUTPUT PATH MODEL
(v1.0.0)

Status: Architecture Specification


==================================================
1. PURPOSE
==================================================

    Данный документ фиксирует механизм задания
        пути для сохранения сгенерированной Theme.

    Механизм предназначен для поддержки различных
        вариантов расположения директории вывода:

        - внутри корня приложения;
        - вне корня приложения;
        - относительно заранее определённой базовой директории.

    Основная задача механизма — отделить семантику
        пути вывода от физического расположения
        приложения.


==================================================
2. OUTPUT CONFIGURATION
==================================================

    Путь вывода задаётся единым полем:

        paths.output

    Поле `output` является типизированной конфигурацией.

    Одновременно может быть задан только один
        тип пути.

    Поддерживаются три типа:

        - relative;
        - absolute;
        - base.

    Пример:

        'paths' => [
            'output' => [
                'relative' => 'build/themes',
            ],
        ]


==================================================
3. RELATIVE OUTPUT PATH
==================================================

    Тип `relative` задаёт путь относительно
        корня приложения.

    Пример:

        'output' => [
            'relative' => 'build/themes',
        ]

    Если корень приложения:

        D:/projects/theme-core

    результирующий путь:

        D:/projects/theme-core/build/themes

    Этот режим является стандартным и сохраняет
        существующее поведение системы.


==================================================
4. ABSOLUTE OUTPUT PATH
==================================================

    Тип `absolute` задаёт полный физический путь
        файловой системы.

    Пример:

        'output' => [
            'absolute' => 'D:\web\multisite\wp-content\themes',
        ]

    В данном случае путь используется непосредственно
        и не дополняется корнем приложения.

    Результирующий путь:

        D:\web\multisite\wp-content\themes

    Этот режим предназначен прежде всего для случаев,
        когда Theme должна генерироваться непосредственно
        в существующую файловую структуру сайта.


==================================================
5. BASE OUTPUT PATH
==================================================

    Тип `base` позволяет задать путь относительно
        именованной базовой директории.

    Базовые директории определяются отдельно
        в конфигурации `paths.bases`.

    Пример:

        'paths' => [

            'bases' => [
                'wordpress' => '../local.wp',
            ],

            'output' => [
                'base' => 'wordpress',
                'path' => 'wp-content/themes',
            ],

        ]

    Если корень приложения:

        D:/projects/theme-core

    то базовая директория:

        D:/projects/local.wp

    а результирующий путь:

        D:/projects/local.wp/wp-content/themes


==================================================
6. PURPOSE OF BASE PATHS
==================================================

    Named base paths предназначены для устранения
        зависимости конфигурации Theme от конкретного
        физического расположения директории.

    Вместо указания:

        D:/web/site/wp-content/themes

    можно определить:

        'bases' => [
            'wordpress' => 'D:/web/site',
        ]

    и использовать:

        'output' => [
            'base' => 'wordpress',
            'path' => 'wp-content/themes',
        ]

    Это позволяет одной и той же конфигурации
        использовать различные расположения проекта
        или окружения.


==================================================
7. MUTUAL EXCLUSIVITY
==================================================

    `paths.output` должен содержать ровно один
        из следующих ключей:

        - relative;
        - absolute;
        - base.

    Допустимый вариант:

        'output' => [
            'absolute' => 'D:/web/site/wp-content/themes',
        ]

    Недопустимый вариант:

        'output' => [
            'relative' => 'build/themes',
            'absolute' => 'D:/web/site/wp-content/themes',
        ]

    Недопустимым также является отсутствие
        типа вывода:

        'output' => []


==================================================
8. BASE OUTPUT STRUCTURE
==================================================

    Тип `base` состоит из двух частей:

        base
        path

    `base` определяет имя зарегистрированной
        базовой директории.

    `path` определяет путь относительно этой
        директории.

    Пример:

        'output' => [
            'base' => 'wordpress',
            'path' => 'wp-content/themes',
        ]

    Значение `base`:

        wordpress

    Значение `path`:

        wp-content/themes


==================================================
9. CONFIGURATION VALIDATION
==================================================

    Проверка конфигурации выполняется до начала
        основной работы приложения.

    `ConfigurationValidator` проверяет:

        - что `output` является массивом;
        - что определён ровно один тип;
        - что значение `relative` является строкой;
        - что значение `absolute` является строкой;
        - что значение `base` является строкой;
        - что для `base` задан `path`;
        - что `path` является строкой.

    Таким образом, некорректная конфигурация
        не должна попадать в последующие стадии
        обработки.


==================================================
10. OUTPUT PATH RESOLUTION
==================================================

    После валидации конфигурации выполняется
        разрешение (`resolution`) пути.

    Для `relative`:

        projectRoot
            +
        relative path

    Для `absolute`:

        absolute path

    Для `base`:

        resolved base path
            +
        relative path


==================================================
11. NORMALIZED RESULT
==================================================

    После нормализации система получает единый
        физический путь для дальнейшего использования.

    Независимо от исходного типа:

        relative
        absolute
        base

    последующие компоненты системы работают
        с разрешённым filesystem path.

    Например:

        Configuration
            |
            v
        ConfigurationNormalizer
            |
            v
        resolved output path
            |
            v
        Build / Artifact pipeline


==================================================
12. SEPARATION OF RESPONSIBILITIES
==================================================

    Configuration отвечает за описание того,
        где должна находиться директория вывода.

    ConfigurationValidator отвечает за проверку
        корректности структуры `output`.

    ConfigurationNormalizer отвечает за разрешение
        логического пути в физический filesystem path.

    Build и Artifact layers не должны самостоятельно
        интерпретировать типы:

        relative
        absolute
        base

    Они получают уже разрешённый путь.


==================================================
13. DEFAULT BEHAVIOUR
==================================================

    Если `output` не задан явно, используется:

        'output' => [
            'relative' => 'build',
        ]

    Это сохраняет существующее поведение приложения,
        при котором директория `build` находится
        относительно корня приложения.


==================================================
14. BACKWARD COMPATIBILITY
==================================================

    Новый механизм сохраняет основной принцип
        существующей конфигурации:

        относительный путь
            ->
        относительно корня приложения.

    При этом появляется возможность явно указать
        абсолютный путь или именованную базовую
        директорию.

    Изменение механизма не требует изменения
        последующих Build и Artifact компонентов,
        поскольку они получают уже разрешённый путь.


==================================================
15. CURRENT SUPPORTED MODEL
==================================================

    На текущем этапе поддерживаются:

        1. Relative

            'output' => [
                'relative' => 'build/themes',
            ]

        2. Absolute

            'output' => [
                'absolute' => 'D:\web\multisite\wp-content\themes',
            ]

        3. Base

            'paths' => [
                'bases' => [
                    'wordpress' => '../local.wp',
                ],

                'output' => [
                    'base' => 'wordpress',
                    'path' => 'wp-content/themes',
                ],
            ]


==================================================
16. EXTENSIBILITY
==================================================

    `output` является расширяемой типизированной
        моделью.

    В дальнейшем могут быть добавлены другие
        способы определения директории вывода,
        если появится соответствующая архитектурная
        необходимость.

    Новые варианты должны добавляться как новые
        типы `output`, а не как независимые поля
        верхнего уровня конфигурации.

    Например, потенциально могут быть добавлены:

        - environment-based path;
        - workspace-based path;
        - project-based path;
        - другие специализированные источники
          базовой директории.

    Добавление новых типов не должно нарушать
        существующие:

        relative
        absolute
        base


==================================================
17. DESIGN PRINCIPLE
==================================================

    Основной принцип модели:

        Один `output`
            ->
        один способ определения пути
            ->
        один разрешённый filesystem path.

    Конфигурация описывает намерение.

    Configuration layer разрешает это намерение
        в конкретный физический путь.

    Остальная система не должна знать,
        каким способом этот путь был получен.
