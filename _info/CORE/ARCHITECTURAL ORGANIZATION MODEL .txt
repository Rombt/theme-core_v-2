==================================================
1. FOUNDATION LAYER
==================================================

        НАЗНАЧЕНИЕ
        --------------------------------------------------
        Фундаментальный системный слой.

                Foundation Layer предоставляет:
                        - базовые архитектурные механизмы
                        - системные контракты
                        - инфраструктуру выполнения
                        - механизмы композиции модулей

                Это самый нижний слой platform architecture.


        ПОЧЕМУ СЛОЙ ВОЗНИК
        --------------------------------------------------
                Когда система становится:
                        - modular
                        - extensible
                        - composition-oriented
                        - pipeline-driven

                появляется необходимость в:
                        - единых контрактах
                        - единых lifecycle правилах
                        - стабильной orchestration infrastructure

                Без Foundation Layer:
                        - модули начинают зависеть друг от друга напрямую
                        - нарушаются архитектурные границы
                        - система теряет предсказуемость


        ОТВЕТСТВЕННОСТЬ СЛОЯ
        --------------------------------------------------

                - контракты модулей
                - инициализация жизненного цикла
                - контейнер зависимостей
                - система событий
                - система хуков
                - конвейерный движок
                - общие интерфейсы
                - системные абстракции
                - примитивы координации выполнения
                - общие архитектурные утилиты

        ЧТО НЕ ДОЛЖНО НАХОДИТЬСЯ В СЛОЕ
        --------------------------------------------------

                - domain logic
                - Логика рендеринга
                - Композиция сайта
                - Логика предоставления ресурсов
                - Специфическое для WordPress поведение бизнес-процессов


        ПРИМЕРЫ ПОДСИСТЕМ
        --------------------------------------------------

                - Контейнер
                - Шина событий
                - Диспетчер хуков
                - Менеджер конвейера
                - Ядро модуля
                - Реестр контрактов
                - Общие интерфейсы
                - Менеджер жизненного цикла


        АРХИТЕКТУРНАЯ РОЛЬ
        --------------------------------------------------

                Foundation Layer обеспечивает:
                        - стабильность платформы
                        - единые правила взаимодействия
                        - управляемую модульность
                        - предсказуемую orchestration model


==================================================
2. CORE SERVICES LAYER
==================================================

        НАЗНАЧЕНИЕ
        --------------------------------------------------
        Общий инфраструктурный сервисный слой.

                Содержит reusable services,
                которые используются всеми остальными слоями,
                но не принадлежат конкретному домену.


        ПОЧЕМУ СЛОЙ ВОЗНИК
        --------------------------------------------------

                В platform-oriented systems быстро появляются:
                        - повторяющиеся инфраструктурные задачи
                        - shared technical services
                        - cross-cutting concerns

                Если их не централизовать:
                        - возникает дублирование
                        - модули становятся нестабильными
                        - orchestration усложняется


        ОТВЕТСТВЕННОСТЬ СЛОЯ
        --------------------------------------------------

                - Загрузка конфигурации
                - Проверка схемы
                - Абстракция файловой системы
                - Кэширование
                - Сериализация
                - Диагностика
                - Ведение журналов
                - Управление ресурсами
                - Службы разрешения имен
                - Разрешение путей
                - Службы метаданных


        ЧТО НЕ ДОЛЖНО НАХОДИТЬСЯ В СЛОЕ
        --------------------------------------------------

                - сущности предметной области
                - оркестровка рендеринга
                - логика композиции
                - семантика пользовательского интерфейса
                - адаптеры рендерера


        ПРИМЕРЫ ПОДСИСТЕМ
        --------------------------------------------------

                - Загрузчик конфигурации
                - Валидатор схемы
                - Менеджер кэша
                - Менеджер ресурсов
                - Разрешение файлов
                - Разрешение метаданных
                - Центр диагностики
                - Логгер


        АРХИТЕКТУРНАЯ РОЛЬ
        --------------------------------------------------

                Core Services Layer:
                        - устраняет инфраструктурное дублирование
                        - стабилизирует execution environment
                        - предоставляет reusable technical capabilities

3. CONFIGURATION LAYER
==================================================

        НАЗНАЧЕНИЕ
        --------------------------------------------------
        Слой описания архитектуры сайта.

                Configuration Layer хранит и обрабатывает:
                        - правила сборки сайта
                        - structural definitions
                        - orchestration configuration

                Главный принцип:
                        Site = Configuration-defined Architecture.


        ПОЧЕМУ СЛОЙ ВОЗНИК
        --------------------------------------------------

                theme-core v-2 строится как: configuration-driven platform.

                Следовательно: конфигурация становится главным источником истины.


        ОТВЕТСТВЕННОСТЬ СЛОЯ
        --------------------------------------------------

                - Конфигурация сайта
                - Конфигурация демоверсии
                - Конфигурация предустановок
                - Сопоставление макетов
                - Сопоставление рендереров
                - Правила композиции
                - Наследование конфигурации
                - Переопределения
                - Нормализация
                - Конфигурация на основе схемы


        ЧТО НЕ ДОЛЖНО НАХОДИТЬСЯ В СЛОЕ
        --------------------------------------------------

                - готовый HTML
                - rendering execution
                - runtime state
                - visual rendering implementation
                - WordPress lifecycle logic


        ПРИМЕРЫ ПОДСИСТЕМ
        --------------------------------------------------

                - SiteConfig
                - DemoConfig
                - PresetConfig
                - LayoutMapping
                - RendererMapping
                - ConfigNormalizer
                - ConfigResolver
                - ConfigSchemaRegistry


        АРХИТЕКТУРНАЯ РОЛЬ
        --------------------------------------------------

        Configuration Layer:
                - определяет архитектуру сайта
                - управляет assembly rules
                - делает систему declarative

        ЧТО НЕ ДОЛЖНО НАХОДИТЬСЯ В СЛОЕ
        --------------------------------------------------

                - rendering execution
                - business workflows
                - runtime orchestration
                - configuration assembly


        ПРИМЕРЫ ПОДСИСТЕМ
        --------------------------------------------------

                - SectionRegistry
                - RendererRegistry
                - LayoutRegistry
                - PresetRegistry
                - CapabilityResolver
                - ManifestLoader


        АРХИТЕКТУРНАЯ РОЛЬ
        --------------------------------------------------

                Registry Layer:

                        - поддерживает dynamic discovery

==================================================
12. ГЛАВНЫЙ ПРИНЦИП АРХИТЕКТУРЫ
==================================================

theme-core v-2 строится как:

        configuration-driven
        composition-oriented
        platform architecture.

--------------------------------------------------

        Слои системы существуют НЕ ради:
                - технической формальности
                - enterprise-сложности
                - абстракций ради абстракций

--------------------------------------------------

        Слои существуют для:
                - orchestration
                - isolation
                - scalability
                - deterministic assembly
                - renderer independence
                - reusable architecture
                - platform extensibility

--------------------------------------------------

Главная идея:

        Сайт является:
                не набором templates, а assembled architecture,
                которая собирается из:
                        - configuration
                        - composition
                        - design system
                        - rendering orchestration
                        - provisioning pipelines
