------------------------------------------------------------
THEME-CORE V-2 — ОПИСАНИЕ АРХИТЕКТУРЫ 
------------------------------------------------------------


1. ФУНДАМЕНТ СИСТЕМЫ: MODULAR MONOLITH
------------------------------------------------------------

Theme-core v-2 построен как модульный монолит.

Это означает, что система развертывается как единое приложение, но внутри разделена на изолированные модули.

Ключевые характеристики:
    - Один единый deploy (WordPress theme / plugin runtime)
    - Внутренняя модульная структура
    - Жёсткая изоляция модулей
    - Взаимодействие только через контракты (интерфейсы / события / пайплайны)

Цель: получить гибкость микросервисов без сложности распределённой системы.


------------------------------------------------------------
2. СЕМАНТИЧЕСКАЯ МОДЕЛЬ: LIGHTWEIGHT DDD
------------------------------------------------------------

Используется облегчённый подход Domain-Driven Design.

Это означает:
    доменные модели есть, но без тяжёлой enterprise-сложности.

Принципы:
    - каждая сущность отражает реальный смысл системы
    - минимум сложных агрегатов
    - доменная логика близка к структуре данных
    - без избыточного DDD-overengineering

Цель: ясность модели без перегрузки архитектуры.


------------------------------------------------------------
3. ИНТЕГРАЦИИ: SELECTIVE HEXAGONAL BOUNDARIES
------------------------------------------------------------

Внешние интеграции реализуются через выборочную гексагональную архитектуру.

Это значит: Hexagonal применяется не везде, а только там, где это необходимо.

Принцип:
    - ядро системы изолировано
    - внешние системы подключаются через адаптеры (ports / adapters)
    - доменная логика не зависит от внешних источников

Цель: защитить ядро от внешней нестабильности.


------------------------------------------------------------
4. МОДЕЛЬ ВЫПОЛНЕНИЯ: PIPELINE-ORIENTED FLOWS
------------------------------------------------------------

Вся обработка данных и рендеринг построены как пайплайны.


Особенности:
    - каждый шаг изолирован
    - шаги можно заменять и расширять
    - поток детерминирован
    - легко отлаживать этапы выполнения

Цель:
предсказуемый и расширяемый процесс рендеринга.


------------------------------------------------------------
5. ФИЛОСОФИЯ АРХИТЕКТУРЫ В ЦЕЛОМ: COMPOSITION-ORIENTED ARCHITECTURE
------------------------------------------------------------

Определение: всё в системе строится через композицию независимых и переиспользуемых частей.

Применение:

    Композиция модулей
        - система состоит из независимых модулей
        - модули не наследуются друг от друга
        - модули собираются через контракты и конфигурации

    Композиция домена
        - Page состоит из Sections
        - Sections состоят из Blocks
        - Blocks состоят из логики + данных

    Композиция пайплайна
        - пайплайн = набор независимых шагов
        - шаги можно заменять и комбинировать

    Композиция интеграций
        - внешние системы подключаются через адаптеры
        - ядро остаётся неизменным

    Композиция UI
        - интерфейс = динамический граф композиции
        - ничего не “жёстко задано”

Главная идея: композиция это принцип который объединяет ВСЕ уровни архитектуры.


------------------------------------------------------------
6. ОБЩАЯ МОДЕЛЬ СИСТЕМЫ
------------------------------------------------------------

Theme-core v-2 можно описать так:

- Modular Monolith (структура системы)
- Lightweight DDD (семантика)
- Selective Hexagonal (интеграции)
- Pipeline Execution Model (выполнение)
- Composition-Oriented Architecture (единый принцип сборки)

Система должна получается:
    - модульной, но не распределённой
    - гибкой, но контролируемой
    - расширяемой, но не хаотичной
    - структурированной, но не перегруженной


------------------------------------------------------------
7. ЦЕЛЬ АРХИТЕКТУРЫ
------------------------------------------------------------

Цель theme-core v-2:

    систему которая поддерживает:

            - композиционную сборку демо-контента
            - динамические layout и section графы
            - структурированный rendering pipeline
            - разделение данных, структуры и представления
            - расширяемую интеграцию внешних источников

    при этом сохраняя:
        - простоту деплоя
        - предсказуемость выполнения
        - строгую модульность
