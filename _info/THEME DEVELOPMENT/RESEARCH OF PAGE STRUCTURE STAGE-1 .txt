THEME-CORE V-2
TEMPLATES DOMAIN RESEARCH
STAGE 1

PAGE STRUCTURE ORGANIZATION MODEL
(v1.0.0)

Status: Research Summary

==================================================
1. PURPOSE
==================================================

    Данный документ фиксирует результаты первого этапа
        исследования способов организации структуры страницы.

    Исследование направлено на определение:

        - принципа построения иерархии элементов страницы;
        - семантики различных уровней этой иерархии;
        - подходящей терминологии;
        - отношения структуры страницы к существующим концептам theme-core v-2;
        - границ между структурой композиции и способом её последующей материализации.

    Исследование проводится без привязки к конкретной
        WordPress Theme Architecture, Elementor или другому runtime / page builder.

    Целью является определение архитектурно-независимого способа
        описания структуры страницы, который может быть использован существующим
        ThemeIR без введения новых концептов.

==================================================
2. RESEARCHED ORGANIZATION MODELS
==================================================

    В ходе исследования были рассмотрены несколько
        распространённых способов организации UI-структуры:

        - Atomic Design;
        - BEM;
        - Page Builder / Elementor model;
        - Template Parts / Components;
        - смешанные component-oriented модели.

    Для дальнейшего исследования наиболее релевантными оказались:

        1. Page Builder model.
        2. Template Parts / Components model.

    Причина:

        Page Builder model рассматривает страницу как
            иерархию вложенных элементов.

        Template Parts / Components model рассматривает
            отдельные части интерфейса как самостоятельные
            и потенциально переиспользуемые структуры.

    Общим для этих подходов является композиционная природа структуры:

         Parent
            ↓
         Child
            ↓
         Child

    При этом Page Builder в большей степени отвечает на вопрос:

        «Из каких элементов построена страница?»

    Template Parts / Components в большей степени отвечает на вопрос:

        «Какие части структуры являются
            самостоятельными и переиспользуемыми?»

==================================================
3. IMPORTANT ARCHITECTURAL DISTINCTION
==================================================

    В ходе исследования было установлено, что:

    структура страницы и  способ её
        последующего использования или материализации
        являются разными аспектами.

    Поэтому:
        Page Builder
        Template Parts
        WordPress templates
        Elementor
        Classic Theme
        Block Theme

    не должны определять саму внутреннюю модель
        структуры страницы в theme-core v-2.

    Они могут выступать способами последующей
        материализации или потребления уже существующей структуры.

    Следовательно, theme-core должен описывать:

        ЧТО представляет собой структура страницы,

        а не:

        КАК эта структура будет реализована
            конкретным WordPress-механизмом.

==================================================
4. CORE IDEA OF PAGE STRUCTURE
==================================================

    Страница рассматривается как иерархически
        организованная композиция элементов.

    Внешний уровень определяет общую структуру страницы.

    Следующие уровни формируют отдельные крупные части
        этой структуры.

    Каждый вложенный элемент отвечает за формирование
        собственной внутренней структуры.

    Таким образом, действует рекурсивный принцип:

        родительский элемент
            определяет контекст и правила своей структуры;

        дочерние элементы
            формируют эту структуру;

        каждый дочерний элемент
            одновременно является частью структуры
            своего родителя и самостоятельной структурой
            относительно собственных детей.

==================================================
5. ACCEPTED HIERARCHY
==================================================

    Для описания структуры страницы принята следующая
        терминология:

            Page
                ↓
            Section
                ↓
            Block
                ↓
            Element


    Данная последовательность описывает уровни
        композиционной структуры страницы.

    Это не означает введение четырёх новых концептов в theme-core v-2.

    Термины:

        Page
        Section
        Block
        Element

    используются как семантическое описание уровней
        иерархии.

    Существующие концепты theme-core v-2 сохраняются
        без изменения.

==================================================
6. PAGE
==================================================

    Page — внешний уровень структуры.

    Page задаёт общий контекст страницы и её базовую организацию.

    На этом уровне могут определяться, например:

        - общая структура страницы;
        - общий background;
        - общая ширина;
        - общие внешние отступы;
        - общие ограничения пространства;
        - общий flow страницы.

    Page не должна отвечать за внутреннее устройство
        конкретных Section, Block или Element.

    Её ответственность ограничивается созданием
        внешнего structural context.

==================================================
7. SECTION
==================================================

    Section — крупная самостоятельная часть страницы.

    Page формируется из набора Section.

    Section задаёт правила формирования собственного
        внутреннего пространства и структуры.

    Типичными примерами Section могут быть:

        - Header;
        - Hero;
        - Content;
        - Sidebar;
        - Products;
        - Testimonials;
        - Features;
        - Pricing;
        - Footer.

    Section не определяется только физическим размером.

    Основным признаком Section является её
        самостоятельная структурная роль внутри Page.

==================================================
8. BLOCK
==================================================

    Block — самостоятельная составная часть Section
        или другого Block.

    Block определяет собственную внутреннюю структуру
        и правила её формирования.

    Например:

        Products Section
            ↓
        Product Block

        Testimonials Section
            ↓
        Testimonial Block

    Block может содержать:

        - другие Block;
        - Element;
        - комбинацию Block и Element.

    Поэтому Block не должен рассматриваться как
        строго фиксированный уровень глубины.

==================================================
9. ELEMENT
==================================================

    Element — самостоятельный элемент композиции,
        который является частью более крупной структуры.

    Element может представлять, например:

        - heading;
        - text;
        - link;
        - button;
        - image;
        - icon;
        - price;
        - rating;
        - menu item.

    При этом Element не обязан рассматриваться
        исключительно как визуально минимальный объект.

    Основным критерием является его роль в структуре
        конкретного родителя.

==================================================
10. RECURSIVE STRUCTURE
==================================================

    Принятая модель не предполагает фиксированную
        глубину вложенности.

    Базовая схема:

      Page
        ↓
      Section
        ↓
      Block
        ↓
      Element

    является терминологическим представлением
        уровней, а не жёстким ограничением структуры.

    Block может содержать Block:

        Section
            └── Block
                └── Block
                    └── Element

    Но секция не может содержать секцию

    Аналогично, структура может содержать
        несколько последовательных уровней Block.

    Поэтому ключевым принципом является не количество
        уровней, а рекурсивная композиция:

            каждый составной элемент
                задаёт собственную внутреннюю структуру.

==================================================
11. STRUCTURAL RESPONSIBILITY
==================================================

    Для каждого уровня действует принцип локальной
        структурной ответственности.

    Page отвечает за:

        - общий контекст страницы.

    Section отвечает за:
        - структуру своей крупной области.

    Block отвечает за:
        - структуру своего локального блока.

    Element отвечает за:
        - собственную локальную структуру и представление.

    Таким образом:
        родитель задаёт контекст размещения;
        элемент формирует собственную внутреннюю структуру;
        дочерние элементы реализуют эту структуру.

==================================================
12. INDEPENDENT STYLING
==================================================

    Одним из исходных требований модели является то,
        что каждый элемент должен иметь собственный
        независимый набор стилей.

    Стиль элемента рассматривается как часть его
        локальной ответственности.

    Это позволяет строить структуру:

        Page
            └── Section
                └── Block
                    └── Element

    таким образом, чтобы каждый уровень мог определять
        собственные правила оформления, не превращая
        родительский уровень в единый набор правил для всех потомков.

    При этом внешний контекст родителя может влиять
        на условия размещения дочернего элемента.

    Следовательно, необходимо различать:

        - собственные стили элемента;
        - структурные ограничения родителя;
        - правила взаимодействия элемента
            с родительской структурой.

==================================================
13. DECORATIVE ELEMENTS
==================================================

    Декоративные элементы не выделяются в обязательный
        самостоятельный последний уровень иерархии.

    Например:

        - image;
        - icon;
        - background image;
        - декоративная графика

    могут находиться на разных уровнях структуры.

    Поэтому модель:

        Page
            ↓
        Section
            ↓
        Block
            ↓
        Element
            ↓
        Decorative Element

    не принимается как обязательная.

    Декоративный характер является свойством элемента,
        а не отдельным уровнем иерархии.

==================================================
14. TEMPLATE PARTS
==================================================

    Template Part не включается в принятую
        иерархию:

            Page
                ↓
            Section
                ↓
            Block
                ↓
            Element

    Причина заключается в различии семантики.

    Иерархия:

        Page / Section / Block / Element

    описывает:

        «где и как элемент участвует  в структуре страницы».

    Template Part описывает:

        «является ли определённая часть структуры
            самостоятельной переиспользуемой частью  шаблона».

    Поэтому Template Part рассматривается как
        независимый аспект возможной реализации,
        а не как дополнительный уровень композиционной
        иерархии.

==================================================
15. PAGE BUILDER RELATIONSHIP
==================================================

    Page Builder рассматривается как практическая
        реализация идеи иерархического построения
        интерфейса.

    Однако terminology конкретного Page Builder
        не должна становиться моделью theme-core.

    Были рассмотрены, в частности:

        - Section;
        - Container;
        - Widget;
        - Element.

    Термины Container и Widget не принимаются
        в качестве основы модели theme-core v-2.

    Причина:

        - они связаны с конкретными builder-моделями;
        - они вводят ненужную дополнительную семантику;
        - Container описывает в первую очередь layout
        mechanism;
        - Widget часто обозначает готовый функциональный
        компонент.

    Для theme-core требуется более нейтральная
        и архитектурно-независимая терминология.

==================================================
16. ACCEPTED TERMINOLOGY
========================

Принят следующий словарь:

    Page
        внешний контекст страницы.

    Section
        крупная самостоятельная часть страницы.

    Block
        самостоятельная составная часть структуры.

    Element
        самостоятельный элемент внутри структуры.

Данная терминология выбрана как компромисс между:

    - понятностью в web/UI ecosystem;
    - использованием в ThemeForest / Envato-среде;
    - архитектурной нейтральностью;
    - отсутствием привязки к конкретному builder.

==================================================
17. RELATION TO EXISTING THEME-CORE CONCEPTS
============================================

    Принятая терминология не создаёт новых
        domain concepts.

    В theme-core v-2 уже существуют:

        - Node;
        - Composition;
        - Templates.

    Эти концепты сохраняются.

    Особенно важно:

        Composition состоит из Nodes.

    Поэтому Page / Section / Block / Element должны
        рассматриваться как семантические роли или
        уровни организации существующей модели,
        а не как новые типы сущностей.

    На данном этапе не принимается решение о том,
        какая конкретно существующая сущность должна
        соответствовать каждому термину.

    Это является следующим этапом исследования.

==================================================
18. ARCHITECTURAL INDEPENDENCE
==================================================

    Принятая модель не зависит от:

        - Classic Theme;
        - Block Theme;
        - FSE;
        - Elementor;
        - другого Page Builder;
        - конкретного формата физического файла;
        - способа materialization.

    Одна и та же композиционная структура должна
        концептуально допускать различные способы
        последующей реализации.

    Следовательно:

        Page structure
            является внутренней архитектурной моделью,

        а:

            WordPress templates;
            template parts;
            Elementor structures;
            PHP;
            HTML;
            другие artifacts

                являются возможными результатами
                последующей materialization.

==================================================
19. DECISIONS OF STAGE 1
==================================================

    В рамках Stage 1 приняты следующие решения:

        1. Структура страницы рассматривается как
            иерархическая композиция элементов.

        2. Каждый составной элемент отвечает за
            формирование собственной внутренней структуры.

        3. Иерархия является рекурсивной и не ограничена
            фиксированным количеством уровней.

        4. Для описания уровней принята терминология:

                Page
                    ↓
                Section
                    ↓
                Block
                    ↓
                Element

        5. Независимые стили рассматриваются как
            характеристика отдельных элементов.

        6. Декоративные элементы не образуют
            обязательного отдельного уровня.

        7. Template Part не рассматривается как уровень
            композиционной иерархии.

        8. Container и Widget не принимаются в качестве
            терминов модели theme-core v-2.

        9. Новые domain concepts не вводятся.

        10. Существующие Node, Composition и Templates
                остаются основой модели.

        11. Page structure должна оставаться
                архитектурно-независимой.

==================================================
20. RESULT OF STAGE 1
==================================================

Результатом первого этапа исследования является
    принятая концептуальная модель:

        Page
            ↓
        Section
            ↓
        Block
            ↓
        Element

Модель описывает не WordPress Theme hierarchy,
    а структуру композиции интерфейса.

Главный принцип модели:

    Каждый элемент является частью структуры
        своего родителя и одновременно определяет
        правила формирования собственной внутренней
        структуры.

Следующий этап исследования должен определить,
    как эта модель выражается существующими
    концептами theme-core v-2:

        Node
        Composition
        Templates

без введения новых концептов.
