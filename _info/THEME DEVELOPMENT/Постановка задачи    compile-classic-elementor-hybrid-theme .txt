Theme Core v-2
Roadmap этапа разработки
Компиляция WordPress Theme указанных архитектур

сейчас рассматриваются вот эти архитектуры
    Classic Theme + Elementor-first + Hybrid Features
    Block Architectures

Назначение документа

    Данный документ определяет цель текущего этапа разработки theme-core v-2.
    Он не является полной спецификацией проекта и не пересматривает существующую архитектуру компилятора.

    Его задача — служить единым ориентиром при разработке кода, принятии архитектурных решений и оценке прогресса.

Во время реализации все новые изменения должны отвечать одному вопросу:
    Приближают ли они компилятор к возможности автоматически собрать целевую WordPress-тему?

    Если ответ отрицательный — подобные изменения не относятся к текущему этапу.

Цель этапа

Развить существующую реализацию theme-core v-2 до состояния,
    при котором приложение способно по одному конфигурационному пакету
    автоматически скомпилировать готовую к использованию WordPress-тему заданной архитектуры

Базовая архитектура компилятора считается подтверждённой (MVP).
    В рамках данного этапа она развивается, а не заменяется новой архитектурной моделью.
    При этом отдельные домены и их реализации могут уточняться по мере их исследования и реализации.

Основная задача этапа — расширение реализации, а не поиск новой архитектурной модели.

Архитектурная модель этапа

На протяжении данного этапа считается принятой следующая схема компиляции:
    Configuration
            ↓
    ThemeConfigurationPackage
            ↓
    Domain Collections
            ↓
    Domain Resolution
            ↓
    ThemeIR
            ↓
    Artifact Generation
            ↓
    Artifact Collection
            ↓
    Artifact Writing
            ↓
    Ready-to-install WordPress Theme

    ThemeIR является архитектурным контрактом между Domain Resolution и Artifacts.
    Domain Resolution формирует нормализованное представление информации темы в ThemeIR.
    Artifact Generators не работают напрямую с Theme Configuration или исходными Domain Collections. Они получают необходимые данные через ThemeIR.
    Архитектурно-зависимая генерация выполняется на уровне Artifacts.
    
    Все изменения должны органично развивать именно эту модель.
    Уточнение конкретных доменов, их моделей и механизмов Resolution допускается, 
        если оно не нарушает установленные границы слоёв.

    Замена базовой архитектурной модели компилятора в рамках данного этапа не предусматривается.

Что считается результатом компиляции
    Результатом работы компилятора является готовая к установке классическая WordPress-тема,
        полностью сформированная автоматически.

    Под "готовой темой" понимается файловая структура WordPress Theme, которая:
        устанавливается без ручной подготовки;
        корректно активируется;
        соответствует требованиям WordPress;
        пригодна как стартовая основа коммерческой разработки.

Компилятор создаёт именно тему.

Компилятор не создаёт сайт.

Целевая архитектура темы
    На данном этапе целевой результат имеет следующую архитектуры.

        Classic Theme
                +
        Elementor-first
                +
        Hybrid Features

        и

        Block Theme
            +
        Full Site Editing
                +
        Hybrid Features

Именно такую архитектуру должна уметь воспроизводить существующая система компиляции.

Границы ответственности

Для данного этапа фиксируется следующее разделение ответственности.
    Theme отвечает за:
        файловую структуру;
        инфраструктуру WordPress;
        регистрацию возможностей;
        глобальные настройки;
        дизайн-систему;
        шаблоны;
        layout-инфраструктуру;
        стили инфраструктуры.


    Elementor
        Отвечает исключительно за построение пользовательских страниц.

    Компилятор не должен:
        создавать Elementor Templates;
        генерировать страницы;
        строить интерфейс сайта;
        размещать виджеты;
        описывать структуру Landing Pages.


Gutenberg
    Используется исключительно как стандартный редактор контента.
    Компилятор обеспечивает его поддержку, но не создаёт содержимое редактора.

Возможности, которыми должна обладать скомпилированная тема

    1. Classic Theme

        Компилятор должен обеспечивать возможность генерации полного набора классических шаблонов WordPress.

            Минимальный набор включает 
                для Classic Theme
                    functions.php
                    index.php
                    front-page.php
                    home.php
                    page.php
                    single.php
                    archive.php
                    category.php
                    tag.php
                    author.php
                    search.php
                    404.php
                    header.php
                    footer.php
                    sidebar.php

                для Block Theme
                    style.css
                    functions.php
                    theme.json
                    templates/index.html
                    templates/single.html
                    templates/archive.html
                    templates/category.html
                    templates/404.html

        При необходимости допускается генерация дополнительных шаблонов.


    2. Elementor-first

        Полученная тема должна быть совместима с Elementor как основной системой построения страниц.

        Это означает, что тема:
            не навязывает собственный page layout;
            не конфликтует со стилями Elementor;
            корректно работает с Full Width;
            корректно работает с Canvas;
            предоставляет только инфраструктуру, необходимую Elementor.


    3. Gutenberg Support

        Компилятор должен обеспечивать полноценную поддержку Block Editor.

            В частности:
                editor styles;
                editor assets;
                block alignment;
                wide/full alignment;
                block styles;
                стандартные WordPress API.


    4. theme.json

        Компилятор не должен формировать theme.json
        theme.json генерируется отдельным приложением Tokvex
        и предоставляется theme-core v-2 уже в полностью готовом виде.

        theme.json становится единственным источником глобальных дизайн-токенов.

        В частности:
            palette;
            typography;
            spacing;
            layout;
            shadows;
            border;
            appearance tools;
            настройки редактора.


    5. Design System

        Компилятор не должен автоматически транслировать единую декларативную дизайн-систему в:

        theme.json;
        CSS Custom Properties;
        базовые стили темы;
        настройки редактора.

        всё что связано с Design System и токенами дизайн системы
        есть продуктом Tokvex и поставляется theme-core v-2 в уже готовом виде

    6. Layout System

        Компилятор должен создавать инфраструктуру layout-системы.

        Она должна обеспечивать:

            контейнеры;
            content width;
            wide width;
            grid/flex layouts;
            sidebar layouts;
            fallback layouts;
            базовую структуру страницы.

        Управление содержимым страниц остаётся за Elementor.


    7. Assets

        Компилятор должен поддерживать декларативное описание ресурсов, необходимых теме, 
            и обеспечивать их корректное использование в итоговой теме.

        Assets являются самостоятельной частью описания темы.

        Компилятор должен обеспечивать необходимую инфраструктуру для ресурсов, 
            включая, в зависимости от архитектуры:
                frontend CSS;
                frontend JavaScript;
                editor assets;
                изображения;
                шрифты;
                другие ресурсы темы;
                необходимые регистрации и подключения.

        Конкретная форма материализации и публикации ресурсов определяется соответствующими слоями компилятора.

    8. WordPress Integration

        Компилятор должен создавать инфраструктуру интеграции с WordPress.

            В частности:

                add_theme_support();
                register_nav_menus();
                register_sidebar();
                image sizes;
                title-tag;
                post thumbnails;
                html5 support;
                custom logo;
                excerpt support;
                другие необходимые регистрации.


    9. Fallback Templates

        Полученная тема должна оставаться полностью работоспособной без Elementor.

        Для этого компилятор должен создавать необходимые fallback-шаблоны.


    10. Infrastructure CSS

        Компилятор должен создавать минимальную инфраструктурную CSS-базу.

            Она должна:
                использовать CSS Variables;
                быть совместимой с theme.json;
                не конфликтовать с Elementor;
                содержать только инфраструктурные стили.


        Что не входит в данный этап

            На данном этапе компилятор не должен:

                создавать контент;
                создавать страницы;
                создавать Elementor Templates;
                генерировать Landing Pages;
                проектировать интерфейсы сайта;
                заменять Elementor или Gutenberg;
                выполнять визуальное проектирование.

            Все подобные задачи остаются за разработчиком темы.


        Критерии успешности архитектурных слоёв

            Этап считается успешно реализованным, если:

                Configuration
                    Конфигурационный пакет способен декларативно описать всю информацию, необходимую для компиляции целевой темы.

                Domain Resolution
                    Все необходимые архитектурные решения могут быть получены автоматически без ручного вмешательства.

                ThemeIR
                    Необходимая информация темы представлена в нормализованной форме и доступна Artifacts
                        через публичные контракты ThemeIR.                    

                Artifact Generation
                    Компилятор способен сформировать полный набор артефактов, необходимых для построения целевой темы.

                Artifact Writing
                    Все артефакты автоматически преобразуются в корректную файловую структуру WordPress Theme.


        Финальный результат

            По одному конфигурационному пакету приложение автоматически создаёт готовую WordPress-тему одной из поддерживаемых архитектур:
                Classic Theme + Elementor-first + Hybrid Features
                или
                Block Theme + Full Site Editing + Hybrid Features.

            При этом исходная Theme Configuration остаётся общей для обеих архитектур. 
                За исключением файлов ресурсов в которых расположен код конкретной реализации 
                для каждой из поддерживаемых архитектур.

            в итоге скомпилированная тема:
                устанавливается без ручных изменений;
                корректно работает в WordPress;
                совместима с Elementor;
                поддерживает Gutenberg;
                использует `theme.json` как единый источник дизайн-системы;
                предоставляет полноценную инфраструктуру для дальнейшей разработки.

            Достижение этого результата считается критерием завершения текущего этапа разработки `theme-core v-2`.
