Техническое задание
Node.js-пакет для обработки SVG и генерации SVG-спрайтов
1. Назначение

Node.js-пакет для автоматизированной обработки SVG-иконок, оптимизации, нормализации и генерации SVG-спрайтов с HTML-превью.

Пакет предназначен для использования в build-процессах через CLI.

2. Общие требования

Node.js ≥ LTS

Кроссплатформенность (Windows / Linux / macOS)

Детерминированный результат сборки

Все зависимости управляются самим пакетом (npm)

Не требует глобальной установки

3. Структура входных данных
3.1 Исходная директория
src/
  mono/        # SVG для монохромных иконок
  colored/     # SVG для многоцветных иконок


Требования:

Обрабатываются только .svg

Имена файлов используются как symbol id

Дубликаты имён запрещены

Вложенность папок — по усмотрению реализации (по умолчанию не требуется)

4. Конфигурация
4.1 Конфигурационный файл

Файл config.js в корне проекта, в котором запускается сборка.

4.2 Корневая директория
const ROOT = process.cwd();


Все пути в конфигурации строятся относительно ROOT.

4.3 Структура конфигурации

import path from 'node:path';

export default {
  src: 'src',
  out: 'dist',

  dimensions: {
    width: 24,
    height: 32,
    normalizeViewBox: true
  },

  spriteMono: path.join('dist', 'sprite-mono.svg'),
  spriteColored: path.join('dist', 'sprite-colored.svg'),

  previewMono: path.join('dist', 'preview-mono.html'),
  previewColored: path.join('dist', 'preview-colored.html'),

  precision: 2,

  mono: {
    removeFill: true,
    removeStroke: true
  },

  colored: {
    preserveColors: true
  },

  svgo: {
    // расширяемая конфигурация SVGO
  }
};

5. Логика обработки SVG
5.1 Общий пайплайн (для всех SVG)

Для каждого SVG:

Загрузка и парсинг

Валидация:

корректный SVG

наличие или возможность генерации viewBox

Нормализация:

удаление width и height

приведение viewBox к dimensions.width / dimensions.height
(если normalizeViewBox: true)

Очистка:

удаление metadata, title, desc

удаление inline-стилей

Оптимизация:

через SVGO

с учётом пользовательской конфигурации

Приведение координат и значений к заданной точности (precision)

5.2 Монохромные SVG (mono/)

Удаляются:

fill

stroke

Допускается fill="currentColor"

Результат должен полностью управляться через CSS

5.3 Многоцветные SVG (colored/)

fill и stroke сохраняются

Цвета не модифицируются

Структура SVG сохраняется максимально близкой к исходной

6. Генерация SVG-спрайтов
6.1 Общие правила

Каждый SVG → <symbol>

id = имя файла без расширения

viewBox обязателен

Спрайты независимы друг от друга

6.2 Выходные файлы

Пути и имена задаются в конфигурации:

spriteMono

spriteColored

7. Генерация HTML-превью
7.1 Требования

Для каждого спрайта генерируется отдельная HTML-страница:

previewMono

previewColored

Каждая страница должна:

отображать все иконки из соответствующего спрайта

показывать имя иконки

использовать адаптивную сетку

не требовать JavaScript (если возможно)

Для mono-превью:

поддержка смены цвета через CSS

8. CLI-интерфейс
8.1 Точка входа

Запуск осуществляется через файл:

src/build/tools/svg-builder/index.js

8.2 package.json
{
  "scripts": {
    "svg": "node src/build/tools/svg-builder/index.js"
  }
}


Пример запуска:

npm run svg

9. Ошибки и валидация

Критические ошибки (с завершением процесса):

битый SVG

невозможность нормализовать viewBox

дубликаты symbol id

отсутствие входных файлов

Требования:

читаемые сообщения в CLI

exit code !== 0 при ошибках

10. Результат работы

В указанной выходной директории формируется:

SVG-спрайт для mono-иконок

SVG-спрайт для colored-иконок

HTML-превью для каждого спрайта
